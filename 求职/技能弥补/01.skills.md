FFmpeg 官方文档里，典型 filtergraph 就是从 decoder 接收帧，经过 filter 处理后送到 encoder；libavformat 文档则覆盖 muxer/demuxer，这正好对应你列的 FFmpeg pipeline。([FFmpeg](https://ffmpeg.org/ffmpeg-all.html?utm_source=chatgpt.com "ffmpeg Documentation"))

GOP 里 I/P/B 帧的比例会影响压缩效率、随机访问和错误恢复；AWS 的 GOP 解释也提到更长 GOP 通常压缩更高效，但会牺牲随机访问点和 error resiliency。([Amazon Web Services, Inc.](https://aws.amazon.com/blogs/media/part-1-back-to-basics-gops-explained/?utm_source=chatgpt.com "Back to basics: GOPs explained | AWS for M&E Blog"))
