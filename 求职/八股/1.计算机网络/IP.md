# IP 面试常见题

## 1. 这份笔记在面试中考什么？

这是网络面试的高频「场景题 + 协议题」组合，重点考察你对 **DNS 解析链路**、**一次完整请求的全流程（输入 URL 到页面显示）**、**PING/ICMP 底层机制**、**Cookie 与 Session 状态管理** 的整体理解。面试官想看的不是背诵，而是你能否把「浏览器 → DNS → TCP → HTTP → 渲染」这条链路串起来讲清楚。

## 3. DNS 查询的基本流程是怎样的？

> [!important]- 必须掌握
> DNS 解析是"输入 URL"大题的第一环，面试高频。必须能说清"本地 → 根 → 顶级 → 授权"这条链路，以及递归查询和迭代查询的区别。

> [!summary]- 核心结论
> 客户机到本地域名服务器之间是**递归查询**（一次问到底、直接给答案）；本地域名服务器到根/顶级/授权服务器之间是**迭代查询**（每一级只返回下一级的地址）。查到结果后本地服务器会缓存并返回给客户机。

> [!question]- 面试怎么答
> 客户机先向本地域名服务器发请求，本地服务器查缓存，没命中就代替客户机去问：先问根域名服务器，根返回对应顶级域（如 .com）服务器的 IP；再问顶级域名服务器，返回授权域名服务器 IP；最后问授权服务器，拿到真正的目标 IP。本地服务器把结果缓存后返回给客户机。客户机到本地是递归，本地往上是迭代。

> [!example]- 具体例子
> 解析 `www.qq.com` 的层级顺序：`. (根)` → `.com (顶级)` → `qq.com (授权)` → `www.qq.com` 对应 IP → 返回客户机。
> 若是转发模式，则方向相反、逐级向上转发：`www.qq.com` → `qq.com` → `.com` → `.`。

> [!warning]- 常见误区
> - 顺序背反：正确是**本地 → 根 → 顶级 → 授权**，不要说成"先访问顶级再访问根"。
> - 混淆递归和迭代：**客户机↔本地是递归，本地↔上级是迭代**，别说反。
> - 忽略缓存：本地域名服务器命中缓存就直接返回，不会每次都走完整链路。

> [!note]- 关键词
> 递归查询、迭代查询、本地/根/顶级/授权域名服务器、DNS 缓存、转发模式

## 4. DNS 用 TCP 还是 UDP？为什么？

> [!note]- 了解即可
> 低频扩展题，知道"区域传输用 TCP，普通查询用 UDP"及各自原因即可，不需要深挖。

> [!summary]- 核心结论
> 普通 DNS 查询用 **UDP**（快、无需三次握手、服务器负载低），区域传输（主从服务器同步）用 **TCP**（数据量大、要求可靠）。一个 DNS UDP 包最大一般是 512 字节。

> [!example]- 具体例子
> - 你 ping 一个网址触发的域名解析 → 数据小、追求快 → **UDP**。
> - 主 DNS 服务器把整个区域数据同步给备用服务器 → 数据大、要可靠 → **TCP**。

> [!note]- 关键词
> 区域传输、512 字节、无连接、可靠性

## 5. DNS 劫持是什么？怎么解决？

> [!note]- 了解即可
> 属于安全类扩展知识，知道"篡改 DNS 解析把用户导向恶意站点"及基本防护即可。

> [!summary]- 核心结论
> DNS 劫持是攻击者通过篡改 DNS 设置或解析记录，把用户对某域名的查询重定向到恶意站点。常见形式有本地劫持（木马改本机 DNS）、路由器劫持、中间人劫持。

> [!example]- 具体例子
> - **本地劫持**：恶意软件改本机 hosts / DNS 设置。
> - **路由器劫持**：攻破路由器改 DNS，影响全网设备。
> - **中间人劫持**：拦截用户与 DNS 服务器通信，返回假 IP。

> [!tip]- 防护思路（记忆）
> 「强密码 + 勤检查 + 锁解析」——账户用强密码并定期更换、定期核对解析记录和 whois、锁定域名解析状态（只能通过服务商改）。

> [!note]- 关键词
> DNS 重定向、本地/路由器/中间人劫持、锁定解析状态

## 6. 浏览器输入一个 URL 到页面显示，经历了什么？

> [!important]- 必须掌握
> 这是网络面试的"压轴综合题"，几乎必考。它把 DNS、TCP、HTTP、渲染全部串起来，能考出你对整条链路的掌握深度。必须能按顺序完整讲出来。

> [!summary]- 核心结论
> 六步：**URL 解析（DNS）→ 建立 TCP 连接 → 发送 HTTP 请求 → 服务器响应 → 浏览器渲染 → 四次挥手断开连接**。

> [!question]- 面试怎么答
> 首先浏览器解析 URL，通过 DNS 拿到目标服务器 IP（先查缓存，没有就走 DNS 递归+迭代解析）；拿到 IP 后调用 Socket 与服务器**三次握手建立 TCP 连接**；然后在 TCP 之上发送 **HTTP 请求**（请求行、请求头、请求体）；服务器处理后返回 **HTTP 响应**（状态码、响应头、响应体）；浏览器拿到响应后开始**渲染**：解析 HTML 构建 DOM 树，解析 CSS 构建渲染树，布局后绘制到屏幕；最后通过**四次挥手断开 TCP 连接**。

> [!example]- 渲染阶段拆解
> 1. 解析 HTML → 构建 DOM 树
> 2. 解析 CSS → 构建 CSSOM / 渲染树
> 3. 布局（Layout）→ 计算每个节点位置大小
> 4. 绘制（Paint）→ 绘制到屏幕

> [!warning]- 常见误区
> - 漏掉"先查缓存"：浏览器缓存/系统缓存/本地 DNS 缓存都可能命中，不一定每次走完整解析。
> - 把 DNS 层级顺序讲反（正确：本地 → 根 → 顶级 → 授权）。
> - 忘记末尾的四次挥手，或把三次握手/四次挥手次数搞混。
> - HTTP 是应用层协议，**建立在 TCP 之上**，不要说成 HTTP 直接连服务器。

> [!note]- 关键词
> DNS 解析、三次握手、HTTP 请求/响应、状态码、DOM 树、渲染树、四次挥手

## 7. PING 是怎么工作的？

> [!important]- 必须掌握
> 高频原理题，考的是你对 **ICMP** 和"一次网络请求底层如何走完 ARP/IP/数据链路层"的理解。能讲清 ICMP 回送请求/应答即可拿分。

> [!summary]- 核心结论
> PING 基于 **ICMP** 协议。源主机发出 **ICMP 回送请求（类型 8）**，目标主机收到后回一个 **ICMP 回送应答（类型 0）**。收到应答说明目标可达，超时未收到则不可达。

> [!question]- 面试怎么答
> ping 时源主机构造一个 ICMP 回送请求包，交给 IP 层封装成 IP 数据包（协议字段设为 1 表示 ICMP），再到数据链路层封装成帧。封装前需要目标 MAC 地址：先查本地 ARP 表，没有就发 ARP 请求获取。目标主机收到帧后逐层解封，把 ICMP 包交给 ICMP 协议，构造一个回送应答包（序号与请求一致）发回源主机。源主机在规定时间内收到应答即判定目标可达。

> [!example]- 关键字段
> - IP 首部协议字段 = 1 → 表示上层是 **ICMP**
> - ICMP 类型 8 → 回送请求（Echo Request）
> - ICMP 类型 0 → 回送应答（Echo Reply）

> [!warning]- 常见误区
> - PING 不用 TCP/UDP，走的是 **ICMP**（属于网络层）。
> - 忽略 ARP 环节：没有目标 MAC 时必须先 ARP 解析。
> - ICMP 不是用来传数据的，主要用于**差错报告和网络探测**。

> [!note]- 关键词
> ICMP、回送请求(8)/应答(0)、协议字段=1、ARP、目标可达

## 8. Cookie 和 Session 的关系和区别是什么？

> [!important]- 必须掌握
> Web/网络面试必考。要能说清两者为什么存在（HTTP 无状态），以及从存储位置、大小、安全性等多维度对比。

> [!summary]- 核心结论
> HTTP 是无状态协议，Cookie 和 Session 都是为了"记住用户状态"。**Cookie 存在客户端**，**Session 存在服务端**。常见做法是：Session 数据放服务端，客户端只用 Cookie 保存一个 SessionID 来关联。

> [!question]- 面试怎么答
> Cookie 是服务器发给浏览器、保存在本地的一小块数据，下次请求同一服务器时自动带上，用于识别用户（如登录态）。Session 是服务端为一次会话保存的状态对象。核心区别：Cookie 存客户端、Session 存服务端；Cookie 只能存 ASCII 且单个不超 4K，Session 能存任意类型、容量大；安全性上 Session 更好，因为数据不暴露在客户端。通常用 Cookie 携带 SessionID 把两者关联起来。

> [!example]- 对比表格
> |维度|Cookie|Session|
> |---|---|---|
> |存储位置|客户端（浏览器）|服务端|
> |存储类型|只能 ASCII|任意数据类型|
> |有效期|可设长期（如"记住登录"）|一般较短，关闭/超时即失效|
> |安全性|较低，易被窃取|较高|
> |容量|单个 ≤ 4K|远大于 Cookie|

> [!warning]- 常见误区
> - 说"Session 存客户端"——错，Session 存**服务端**。
> - 忽略两者关系：Session 通常**依赖 Cookie 传 SessionID**，禁用 Cookie 时需用 URL 重写等方式。
> - 认为 Cookie 一定不安全：可通过 HttpOnly、Secure、SameSite 等属性加固。

> [!note]- 关键词
> HTTP 无状态、客户端/服务端、SessionID、4K 限制、HttpOnly

## 9. IPv4 和 IPv6 的区别？

> [!note]- 了解即可
> 低频概念题，记住"地址从 32 位扩到 128 位、首部更简洁、支持自动配置"即可，不需深入。

> [!summary]- 核心结论
> IPv6 把地址从 **32 位** 扩展到 **128 位**，解决地址枯竭；首部结构更简单（可选项移到扩展头部），路由更快；原生支持地址自动配置（即插即用）和更强的安全性（身份验证、数据一致性、保密性）。

> [!example]- 对比表格
> |维度|IPv4|IPv6|
> |---|---|---|
> |地址长度|32 位|128 位|
> |首部|较复杂|结构更简单，可选项放扩展头|
> |地址配置|手动 / DHCP|支持无状态/有状态自动配置|
> |安全性|依赖上层|内置身份验证/加密支持|

> [!warning]- 常见误区
> IPv6 首部**长度更长（40 字节）但结构更简单**，两者不矛盾——长是因为地址更长，简单是因为可选项被移出主首部。

> [!note]- 关键词
> 128 位地址、扩展头部、无状态自动配置、即插即用

## 10. 什么是跨域？什么情况下会发生？如何解决？

> [!info]- 需要掌握
> 前端/网络交叉高频题。要理解跨域的根源是浏览器的**同源策略**，并能说出判定条件和主流解决方案。

> [!summary]- 核心结论
> 跨域指浏览器基于**同源策略**限制一个页面访问另一个不同源页面的资源。**协议、域名、端口任一不同**即视为跨域。它是浏览器的安全限制，不是服务器行为。

> [!question]- 面试怎么答
> 同源策略要求协议、域名、端口三者完全一致，只要有一个不同，浏览器就限制脚本对目标资源的访问，这就是跨域。常见解决方案有三种：CORS（服务端设置响应头允许跨域，是标准方案）；Nginx 反向代理（让请求都走同一域名和端口）；JSONP（利用 script 标签不受同源限制，但只支持 GET）。

> [!example]- 是否跨域判定
> 以 `http://a.com:80` 为基准：
> - `https://a.com` → 跨域（协议不同）
> - `http://b.com` → 跨域（域名不同）
> - `http://a.com:8080` → 跨域（端口不同）
> - `http://a.com/page2` → 同源（不跨域）

> [!warning]- 常见误区
> - 跨域是**浏览器**的限制，服务器之间互相请求不存在跨域。
> - JSONP **只支持 GET**，不支持 POST。
> - 跨域被限制的是"读取响应"，请求其实往往已经发出去了。

> [!note]- 关键词
> 同源策略、协议/域名/端口、CORS、JSONP、Nginx 反向代理

## 12. 最终速记版

> [!tip]- 一句话速记
> - **DNS**：本地 → 根 → 顶级 → 授权；客户机递归，上级迭代。
> - **输入 URL**：DNS → TCP 握手 → HTTP 请求 → 响应 → 渲染 → 四次挥手。
> - **PING**：ICMP 回送请求(8) / 应答(0)，协议字段=1，先 ARP 拿 MAC。
> - **Cookie/Session**：Cookie 存客户端(≤4K/ASCII)，Session 存服务端(任意/更安全)，靠 SessionID 关联。
> - **IPv6**：32→128 位，首部更简洁，支持自动配置。
> - **跨域**：同源策略，协议/域名/端口任一不同即跨域；CORS / Nginx / JSONP 解决。
