# I/O 与重定向：控制命令的数据从哪里来、到哪里去

每个进程通常从三个标准 file descriptor 开始。重定向改变描述符指向，管道把一个进程的输出连接到另一个进程的输入。

---

## 1. 三个标准流

| FD | 名称 | 默认位置 |
| --- | --- | --- |
| `0` | stdin | 终端输入 |
| `1` | stdout | 终端正常输出 |
| `2` | stderr | 终端诊断输出 |

程序区分 stdout 与 stderr，才能让数据进入管道，同时把诊断留给用户。

## 2. 常用重定向

| 写法 | 含义 |
| --- | --- |
| `COMMAND > FILE` | stdout 覆盖写入文件 |
| `COMMAND >> FILE` | stdout 追加到文件 |
| `COMMAND 2> FILE` | stderr 覆盖写入文件 |
| `COMMAND < FILE` | 从文件提供 stdin |
| `COMMAND > FILE 2>&1` | stdout 与 stderr 都写入文件 |
| `COMMAND &> FILE` | Bash 中合并两者的简写 |

重定向通常先打开目标文件，再启动命令；即使命令失败，`>` 也可能已经截断原文件。

## 3. 为什么顺序重要

```bash
COMMAND > combined.log 2>&1
```

先让 FD 1 指向文件，再让 FD 2 复制 FD 1 的当前指向，因此两者都进文件。

```bash
COMMAND 2>&1 > stdout.log
```

FD 2 先复制原来的 FD 1（终端），随后只有 FD 1 改到文件，所以 stderr 仍可能显示在终端。

> [!tip]- `2>&1` 的本质
> 它不是“把错误写进名为 1 的文件”，而是让 FD 2 复制 FD 1 在该时刻指向的 open file description。

## 4. Pipe 与 tee

```bash
producer | consumer
COMMAND 2>&1 | tee run.log
COMMAND 2>&1 | tee -a run.log
```

普通管道只连接左侧 stdout 到右侧 stdin；要把 stderr 也送入管道，需要显式合并。`tee` 同时写屏幕和文件，默认覆盖，`-a` 追加。

管道中各命令通常运行在不同进程。Bash 默认返回最后一条命令的状态；需要检测任一阶段失败时可使用：

```bash
set -o pipefail
```

## 5. HPC 日志模式

```bash
srun ./simulation 2>&1 | tee "run-${SLURM_JOB_ID:-local}.log"
```

这能实时观察并保存合并日志，但 stdout 与 stderr 合并后不再能单独分类，缓冲也可能影响显示顺序。

> [!warning]- 常见误区
> - `>` 会覆盖，`>>` 才追加。
> - `|` 不会自动传递 stderr。
> - `< FILE` 与 `cat FILE | COMMAND` 经常等价，但前者少一个进程且意图更直接。
> - `tee` 的退出成功不代表左侧程序成功，需考虑 `pipefail` 或 `PIPESTATUS`。
