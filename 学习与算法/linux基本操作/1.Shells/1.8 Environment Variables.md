# 环境变量：Shell 如何向子进程传递配置

Shell variable 只存在于当前 Shell；exported environment variable 会在创建子进程时复制给子进程。子进程之后的修改不能反向改变父进程。

---

## 1. 定义、读取与导出

```bash
project_dir="$HOME/project"
printf '%s\n' "$project_dir"
export PROJECT_DIR="$project_dir"
export OMP_NUM_THREADS=8
```

赋值号两边不能有空格。设置变量时左侧不写 `$`，读取值时才写 `$name` 或 `${name}`。

```bash
env
printenv HOME
env MODE=test COMMAND
unset PROJECT_DIR
```

`env MODE=test COMMAND` 只为该命令及其子进程临时设置环境。

## 2. PATH

`PATH` 是按冒号分隔的目录列表，Shell 从左到右查找外部命令。

```bash
export PATH="$HOME/bin:$PATH"
command -v mytool
```

把自定义目录放前面会覆盖同名系统命令的查找优先级；放后面则保留系统命令优先。不要把命令文件本身加入 PATH，应加入它所在目录。

> [!warning]- PATH 安全
> 空的 PATH 元素可能表示当前目录。避免无意产生开头、结尾或连续冒号，也不要随意加入任何人可写目录。完全覆盖 PATH 可能导致基础命令找不到。

## 3. 作用域与持久化

```text
parent shell --复制环境--> child process
child 的修改 --不能反向--> parent shell
```

当前终端的赋值通常只在会话中有效。需要持久化时，根据 Shell 与登录方式修改相应启动文件，例如 Bash 的 `~/.bashrc` 或 `~/.profile`；修改后可开启新 Shell 验证。

`source FILE` 会在当前 Shell 执行文件，所以能修改当前环境，也意味着不可信文件可以执行任意命令。

## 4. HPC 常见变量

```bash
export OMP_NUM_THREADS=8
export OMP_PROC_BIND=close
export OMP_PLACES=cores
```

变量是否生效由具体程序和调度环境决定；应结合资源申请、程序文档和作业日志验证。

> [!warning]- 易错点
> - `SHELL` 通常是登录 Shell 路径，不保证等于当前 Shell。
> - 未加引号的变量可能被分词和 glob 展开。
> - `export` 传递的是进程创建时的值，不是父子间实时共享变量。
