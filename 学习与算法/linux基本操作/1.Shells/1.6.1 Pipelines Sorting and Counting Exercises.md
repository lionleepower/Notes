# 管道、排序与计数练习：把小工具组合成数据流

管道让每个命令只做一件事。练习重点不是背组合，而是判断每一步的输入、输出与数据类型。

---

## 练习 1：搜索历史命令

> [!success]- 答案
> ```bash
> history | grep -F 'ssh'
> ```
>
> `history` 的行为依赖 Shell；在非交互 Shell 中可能没有预期历史记录。

## 练习 2：文本排序

> [!success]- 答案
> ```bash
> sort names.txt
> sort -r names.txt
> sort -u names.txt
> ```

## 练习 3：数值排序

> [!success]- 答案
> ```bash
> sort -n numbers.txt
> sort -nr numbers.txt
> ```
>
> 默认排序按 locale 和文本规则；例如文本顺序可能把 `10` 放在 `2` 前面。

## 练习 4：统计

> [!success]- 答案
> ```bash
> wc -l FILE
> wc -w FILE
> wc -c FILE
> ```
>
> `-c` 统计字节，字符数可用 `-m`；文件最后没有换行时，`wc -l` 统计的是换行符数量。

## 练习 5：统计唯一值频次

> [!success]- 答案
> ```bash
> sort values.txt | uniq -c | sort -nr
> ```
>
> `uniq` 只合并相邻重复行，所以通常先排序。

## 练习 6：可靠统计文件

`ls | wc -l` 会漏掉隐藏项，并受名称换行等问题影响。需要递归统计普通文件时使用：

> [!success]- 答案
> ```bash
> find . -type f -print0 | awk 'BEGIN { RS = "\0" } { n++ } END { print n + 0 }'
> ```

> [!warning]- 易错点
> - 管道传输字节流，不理解“列”或“文件”。
> - `ps -ef | grep NAME` 会匹配 grep 自己；精确查进程可用 `pgrep -af NAME`。
> - 只查看最终输出会掩盖中间失败；脚本中考虑 `set -o pipefail`。
