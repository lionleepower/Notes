# Shell 入门：一条命令如何被解析和执行

Shell 是命令解释器，也是脚本语言运行环境。掌握命令结构、引号、展开和命令查找顺序，才能解释“为什么同一条命令会得到不同结果”。

---

## 核心模型

```text
读取输入 → 词法解析与各种展开 → 处理重定向 → 找到命令 → 执行 → 返回状态码
```

> [!tip]- 关键判断
> Shell 不只是把字符串交给 kernel。通配符、变量、引号、管道和重定向通常先由 Shell 处理，命令程序收到的是处理后的参数。

## 1. 命令结构

```bash
COMMAND OPTION ARGUMENT
```

```bash
ls -lah /tmp
cp -- source.txt backup.txt
```

- option 改变命令行为；短选项常能组合，长选项通常以 `--` 开头。
- argument 是操作对象。
- `--` 常表示选项结束，适合处理以 `-` 开头的文件名。

## 2. Builtin 与外部命令

| 类型 | 示例 | 为什么重要 |
| --- | --- | --- |
| Shell builtin | `cd`、`export`、`jobs` | 必须修改当前 Shell 状态 |
| External command | `ls`、`grep`、`python3` | 通常是文件系统中的可执行程序 |

```bash
type cd
type -a python3
command -v python3
```

`cd` 不能靠普通子进程改变父 Shell 的工作目录，因此由 Shell 自己实现。

## 3. Shell 如何找命令

对于不含 `/` 的命令名，Shell 会检查 alias、function、builtin，并按 `PATH` 顺序查找外部程序。含 `/` 时按给定路径执行：

```bash
./program
/usr/bin/python3
```

当前目录通常不在 `PATH` 中，所以运行自己的程序常需要 `./`。

## 4. 引号与展开

| 写法 | 行为 |
| --- | --- |
| `'text $HOME'` | 完全按字面值处理 |
| `"text $HOME"` | 允许变量和命令替换，抑制分词与通配符展开 |
| `text\ value` | 反斜杠保护下一个字符 |

```bash
name='Linux notes'
printf '%s\n' "$name"
```

变量展开通常应加双引号，避免空格和通配符造成意外分词。

## 5. 退出状态

命令用整数 exit status 报告结果，`0` 通常表示成功，非零表示不同失败。

```bash
grep 'ERROR' run.log
printf '%s\n' "$?"
```

`$?` 只保存最近一条命令的状态，应在目标命令后立即读取。

> [!warning]- 常见误区
> - prompt 中的 `$` 通常不是命令内容。
> - Tab completion 只负责补全，不证明目标一定可执行。
> - `echo` 的选项和转义行为存在实现差异，格式化输出优先用 `printf`。
> - 文件存在不代表可以直接输入文件名执行，还取决于路径、权限和格式。

## 一句话总结

理解 Shell 的关键是分清“Shell 先做的解析与展开”和“命令程序最终收到的参数”。
