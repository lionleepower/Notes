# Linux 目录导航：用路径准确定位文件

路径描述文件系统中的位置。绝对路径不依赖当前目录，relative path 则以当前工作目录为起点；多数“文件找不到”问题都来自基准目录判断错误。

---

## 1. 路径模型

| 写法 | 含义 |
| --- | --- |
| `/` | 根目录 |
| `~` | 当前用户 home directory |
| `.` | 当前目录 |
| `..` | 父目录 |
| `-` | `cd` 中表示上一次工作目录 |

```bash
pwd
cd /absolute/path
cd relative/path
cd ..
cd ~
cd -
```

> [!tip]- 判断方法
> 以 `/` 开头的是 absolute path；其他通常是 relative path。`~` 由 Shell 展开成 home path。

## 2. 查看目录

```bash
ls
ls -lah
ls -lah /tmp
```

- `-l`：长格式；
- `-a`：包括以 `.` 开头的隐藏项；
- `-h`：把大小显示为易读单位，通常配合 `-l`。

隐藏文件只是命名以 `.` 开头，并不具有额外安全性。

## 3. 通配符

| Pattern | 含义 |
| --- | --- |
| `*` | 任意长度字符串 |
| `?` | 任意一个字符 |
| `[abc]` | 集合中的一个字符 |

```bash
printf '%s\n' ./*.c
ls -- report?.txt
```

通配符由 Shell 在命令运行前展开。匹配不到时的行为取决于 Shell 与配置，因此脚本中不要盲目假设一定得到空列表。

## 4. 含空格的路径

```bash
cd 'Project Files'
cp "report final.txt" backup/
```

引号保护的是参数边界，不会成为文件名的一部分。

## HPC 工作流

```bash
cd "$HOME/project"
pwd
ls -lah
cd "${SCRATCH:?}/experiment"
```

`${SCRATCH:?}` 在变量为空或未设置时让 Shell 报错，避免误把路径落到根目录或当前目录；具体集群是否提供 `SCRATCH` 要看站点文档。

> [!warning]- 常见误区
> - `cd /` 与 `cd ~` 完全不同。
> - relative path 的含义随 `pwd` 改变。
> - `ls *` 默认不会匹配隐藏项。
> - 不要解析 `ls` 输出作为脚本数据；遍历文件应使用 glob、`find` 或适当工具。
