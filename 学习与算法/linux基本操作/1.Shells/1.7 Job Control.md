# Job Control：管理前台、后台任务与进程信号

Job control 是交互式 Shell 管理 pipeline 的机制；process management 则由内核按 PID 和 signal 工作。job number 与 PID 不能混用。

---

## 核心概念

| 概念 | 标识 | 范围 |
| --- | --- | --- |
| Job | `%1`、`%2` | 当前交互 Shell 管理的 pipeline |
| Process | PID | 系统范围的执行实例 |
| Process group | PGID | pipeline 中的一组进程 |

## 1. 前后台操作

```bash
COMMAND &
jobs -l
fg %1
bg %1
```

- `Ctrl-C` 通常向前台 process group 发送 `SIGINT`。
- `Ctrl-Z` 通常发送 `SIGTSTP`，只是暂停。
- `bg` 让 stopped job 在后台继续；`fg` 把 job 重新接回终端。

后台运行不等于能安全脱离终端。程序仍可能收到 `SIGHUP`、尝试读取终端或随会话结束。

## 2. 查看进程

```bash
ps -o pid,ppid,pgid,stat,cmd
pgrep -af python
top
```

`jobs` 只知道当前 Shell 的任务；`ps`、`pgrep` 和 `top` 面向进程。

## 3. 发送信号

```bash
kill -TERM PID
kill -KILL PID
kill -l
```

`SIGTERM` 可被进程处理并执行清理；`SIGKILL` 不能捕获、阻塞或忽略，应作为最后手段。`kill` 成功只表示信号已发送，不保证进程已退出。

> [!warning]- HPC 边界
> Slurm 作业应优先用 `squeue`、`scancel JOB_ID` 管理。登录节点上的 job control 不能替代调度器，也不应把大型计算靠 `nohup` 放在登录节点运行。

## 4. 典型流程

```bash
COMMAND
# Ctrl-Z
bg %1
jobs -l
fg %1
```

结束卡住的进程时：先确认 PID → 尝试正常中断或 `SIGTERM` → 等待清理 → 最后才考虑 `SIGKILL`。
