# Linux 账户：用户、组与认证如何建立身份边界

Linux 用 UID/GID 作为内核身份，用用户名和组名提供人类可读映射，再用权限与认证机制控制资源访问。

---

## 核心概念

| 概念 | 含义 |
| --- | --- |
| Username | UID 的可读名称 |
| UID | 内核识别用户的数字 ID |
| Primary group | 新建文件通常继承的主要组 |
| Supplementary groups | 用户额外所属的组 |
| GID | 组的数字 ID |

```bash
whoami
id
groups
getent passwd "$USER"
```

文件保存的是 UID/GID。若账户数据库映射变化，`ls -l` 可能显示数字而不是原用户名。

## 1. 账户信息

`/etc/passwd` 保存用户名、UID、GID、home 和登录 Shell 等公开账户信息，不应保存明文密码。

```text
name:x:UID:GID:comment:home:shell
```

密码 hash 通常保存在权限严格的 `/etc/shadow` 或集中身份系统中。系统验证时对输入密码使用相应算法并比较结果，而不是解密明文。

## 2. 组为什么重要

组用于共享项目文件、设备或服务权限。HPC 项目常把成员放入同一组，并通过目录 group ownership、setgid 和 umask 维持协作权限。

## 3. 登录与 SSH

密码认证证明用户知道秘密；SSH public key authentication 证明客户端持有私钥。认证成功后，系统仍根据目标账户的 UID、组和权限决定能访问什么。

> [!warning]- 安全边界
> - Username 不是安全边界，UID 才是内核权限判断基础。
> - 不要共享个人账户或私钥；共享资源应使用组与授权机制。
> - Root 通常是 UID 0；不要把 `/root` 目录与 `/` 根目录混淆。
