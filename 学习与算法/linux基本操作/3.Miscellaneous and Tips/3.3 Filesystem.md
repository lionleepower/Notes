# Linux Filesystem：从根目录理解系统数据布局

Linux 把不同磁盘、虚拟文件系统和网络存储挂到一棵以 `/` 为根的目录树。FHS 提供通用布局，但发行版和 HPC 站点可以扩展或采用 merged `/usr`。

---

## 1. 目录速查

| 路径 | 主要用途 |
| --- | --- |
| `/` | 整棵目录树的根 |
| `/etc` | 系统级配置 |
| `/home` | 普通用户 home |
| `/root` | root 用户 home，不是根目录 |
| `/tmp` | 临时文件，生命周期策略依系统而定 |
| `/var` | 经常变化的数据，如日志、缓存、队列 |
| `/usr` | 共享的用户空间程序、库和只读数据 |
| `/usr/local` | 本机管理员安装的软件 |
| `/opt` | 附加应用软件 |
| `/run` | 本次启动的运行时状态 |
| `/boot` | 启动相关文件 |
| `/mnt`、`/media` | 临时或可移动介质挂载点 |
| `/srv` | 服务提供的数据 |

## 2. 虚拟文件系统

| 路径 | 内容 |
| --- | --- |
| `/dev` | 设备节点和特殊设备 |
| `/proc` | 进程与内核信息 |
| `/sys` | 设备、驱动与内核对象视图 |

这些内容由内核运行时生成，不应理解成普通磁盘文件集合。

```bash
findmnt
df -h
du -sh DIRECTORY
```

`df` 查看 filesystem 空间，`du` 汇总目录可见文件占用，两者统计对象不同，结果不必完全一致。

## 3. merged usr

现代发行版常让 `/bin`、`/sbin`、`/lib` 成为指向 `/usr` 对应目录的符号链接。脚本不应依靠“`/bin` 一定是独立分区”之类历史假设。

## 4. HPC 路径

集群可能提供 `$HOME`、project、scratch 和 archive 等站点目录：

- home：容量较小、常备份，适合代码和配置；
- scratch：高性能、可能定期清理，适合运行数据；
- project：面向团队共享，配额和权限由项目管理。

具体策略必须查看站点文档，不能仅凭目录名推断。

> [!warning]- 常见误区
> - `/` 与 `/root` 完全不同。
> - 文件扩展名不决定 Linux 内核如何存储文件，只是应用约定。
> - “一切皆文件”是统一接口思想，不表示所有对象都是普通持久文件。
> - `/tmp` 不保证永久保存，也不保证所有系统都在重启时清空。

> [!question]- 自测
> 1. `/proc` 为什么不需要真实占用对应磁盘空间？
> 2. `df` 与 `du` 为什么可能不同？
> 3. merged `/usr` 会怎样影响 `/bin`？
