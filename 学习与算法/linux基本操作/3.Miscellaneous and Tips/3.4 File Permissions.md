# Linux 文件权限：用所有权和 rwx 控制访问

传统 Unix 权限把访问者分为 owner、group 和 others，再为每类设置 read、write、execute。最终访问还可能受 ACL、挂载选项、capability 和安全模块影响。

---

## 1. 读取权限字符串

```bash
ls -l FILE
stat FILE
```

```text
- rwx r-x ---
  user group others
```

首字符表示类型，如 `-` 普通文件、`d` 目录、`l` 符号链接。

## 2. 文件与目录的 rwx

| 权限 | 普通文件 | 目录 |
| --- | --- | --- |
| `r` | 读取内容 | 列出名称 |
| `w` | 修改内容 | 创建、删除、重命名目录项 |
| `x` | 作为程序执行 | 穿越目录并访问已知路径 |

删除文件主要由父目录的 `w` 与 `x` 决定，而不是文件自身的 `w`。

## 3. chmod

```bash
chmod u+x script.sh
chmod g-w data.txt
chmod o= secret.txt
chmod 640 data.txt
chmod 750 script.sh
```

数字模式中 `r=4`、`w=2`、`x=1`，三位依次对应 user、group、others。

| Mode | 常见用途 |
| --- | --- |
| `600` | 私钥或仅 owner 读写的文件 |
| `640` | owner 读写、group 只读 |
| `644` | 普通公开可读文件 |
| `700` | 私有目录或程序 |
| `750` | group 可进入/执行 |
| `755` | 公共可进入目录或可执行程序 |

## 4. 所有权与默认权限

```bash
chown USER FILE
chgrp GROUP FILE
umask
umask 027
```

`umask` 从程序请求的默认权限中屏蔽位，常见起点是文件 `666`、目录 `777`；实际结果还受程序和 filesystem 影响。

## 5. 递归修改风险

```bash
find DIRECTORY -type d -exec chmod 750 {} +
find DIRECTORY -type f -exec chmod 640 {} +
```

这比 `chmod -R 750 DIRECTORY` 更精确，因为文件与目录通常不应拥有相同 execute 位。所有权修改和高权限命令也要先打印目标验证。

> [!warning]- 安全误区
> - `chmod 777` 不是通用修复，会让所有用户可写。
> - `./script.sh` 需要 execute permission；`bash script.sh` 需要 Bash 能读取文件。
> - `source script.sh` 在当前 Shell 执行，风险与权限问题不能混为一谈。
> - ACL 可能让实际权限不同于九个 rwx 位的直观判断。
