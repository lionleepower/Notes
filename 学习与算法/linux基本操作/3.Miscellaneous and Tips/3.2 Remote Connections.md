# SSH 远程连接：认证服务器、保护会话并传输文件

SSH 建立加密远程会话：host key 让客户端识别服务器，用户认证让服务器识别登录者。SCP、SFTP 和 rsync 可复用 SSH 通道传输数据。

---

## 1. 基本连接

```bash
ssh USER@HOST
ssh -p PORT USER@HOST
ssh -i ~/.ssh/id_ed25519 USER@HOST
```

第一次连接出现 host key fingerprint 时，应通过可信渠道核对。盲目接受会失去抵御 man-in-the-middle attack 的关键保护。

## 2. 密钥认证

```bash
ssh-keygen -t ed25519
ssh-copy-id USER@HOST
chmod 700 ~/.ssh
chmod 600 ~/.ssh/id_ed25519
```

私钥留在客户端并建议使用 passphrase；公钥放在远端 `~/.ssh/authorized_keys`。不要通过聊天、邮件或共享仓库传播私钥。

可把常用配置写入 `~/.ssh/config`：

```sshconfig
Host cluster
    HostName login.example.edu
    User alice
    IdentityFile ~/.ssh/id_ed25519
```

之后使用 `ssh cluster`。

## 3. X11 Forwarding

```bash
ssh -X USER@HOST
ssh -Y USER@HOST
```

`-X` 是受限、不受信任转发；`-Y` 是 trusted forwarding，对远端程序授予更高信任。只在理解风险、客户端有 X server 且站点允许时使用；大规模可视化更适合本地处理或专用服务。

## 4. 文件传输方向

```bash
# local → remote
scp FILE USER@HOST:~/DESTINATION/

# remote → local
scp USER@HOST:~/results/output.txt ./results/

# directory
scp -r DIRECTORY USER@HOST:~/DESTINATION/
```

冒号所在一侧是 remote path。现代 OpenSSH 的 `scp` 通常使用 SFTP 传输，但命令界面保持相似；旧服务器兼容性要参考站点文档。

## 5. 何时用 rsync

```bash
rsync -av --progress DIRECTORY/ USER@HOST:~/DIRECTORY/
```

`rsync` 适合重复、增量和可恢复传输。源目录末尾的 `/` 会影响“复制目录本身”还是“复制目录内容”，执行前可先用 `--dry-run`。

> [!warning]- 常见误区
> - Host key 验证与用户密码/密钥认证解决不同方向的身份问题。
> - 登录节点不是计算节点，应按 HPC 站点规则提交任务。
> - `-Y` 不是“更好用的 -X”，而是更高信任。
> - 大文件传输要遵守站点 data transfer node 和配额规则。
