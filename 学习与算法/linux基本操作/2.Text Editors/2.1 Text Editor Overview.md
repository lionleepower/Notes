# Linux 文本编辑器概览：按环境与任务选择工具

服务器和 HPC 常没有图形界面，因此至少要掌握一种终端编辑器。选择编辑器的关键是工作环境、学习成本和任务规模，而不是争论哪一个绝对最好。

---

## 编辑器对比

| 工具 | 交互模型 | 适合场景 |
| --- | --- | --- |
| Vim | modal editing | 远程服务器、长期高效编辑 |
| Emacs | key chords、高度可扩展 | 集成式长期工作流 |
| nano | 屏幕底部提示快捷键 | 临时小修改、初学者 |
| VS Code / gedit | GUI | 本地项目和图形环境 |

`vi` 是历史标准编辑器；系统上的 `vi` 可能是 Vim、nvi 或其他兼容实现。

```bash
command -v vi
readlink -f "$(command -v vi)"
```

alias 只影响 Shell 命令解析，`alias vi=vim` 不会修改 `/usr/bin/vi` 文件本身。

## 怎么选

- 只需修改几行配置：`nano FILE`。
- 经常通过 SSH 工作：学习 Vim 基础和 `vimtutor`。
- 本地大型工程：GUI 编辑器加远程开发功能。
- 已有成熟 Emacs 工作流：无需因服务器环境改用其他工具。

> [!warning]- 远程编辑
> 不要在共享登录节点启动重型 GUI。编辑关键配置前先备份，并注意换行符、编码与权限。
