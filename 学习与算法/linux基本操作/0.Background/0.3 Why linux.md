# 为什么使用 Linux：服务器、开发与 HPC 的共同基础

Linux 的价值不只是“免费”，而是可观察、可自动化、可定制，并拥有成熟的服务器与科学计算生态。这些特性让同一套工作流能从个人电脑迁移到集群。

---

## 核心理解

| 优势 | 为什么重要 | HPC 示例 |
| --- | --- | --- |
| Performance | 可针对硬件、网络和存储优化 | NUMA、GPU、并行文件系统 |
| Functionality | 工具链和库成熟 | GCC、MPI、OpenMP、CUDA、Python |
| Flexibility | 可组合命令与定制环境 | shell script、container、module |
| Portability | 支持多种 CPU 与设备 | 本地开发后迁移到 cluster |

> [!tip]- 本质
> Linux 的核心优势是开放接口与可组合生态：编译、运行、调试、调度和数据处理可以放在同一套自动化流程中。

## 1. 为什么适合服务器

- 可最小化安装，减少不需要的图形组件；
- 权限、服务、日志和网络工具成熟；
- 便于通过 SSH 远程管理；
- 长期支持发行版适合稳定生产环境；
- 开源便于审计和针对特定硬件定制。

## 2. 为什么适合 HPC

典型 HPC 软件栈如下：

```text
Linux
├── compiler 与 scientific libraries
├── MPI / OpenMP / GPU runtime
├── Slurm 等 scheduler
├── parallel filesystem
└── profiler、debugger 与 shell 工具
```

常见工作流：

```bash
ssh USER@CLUSTER
module load gcc openmpi
make
sbatch run.slurm
```

`module` 是许多集群提供的环境管理命令，不是所有 Linux 系统的内置命令。

## 3. 可移植不等于完全相同

Shell 脚本和源代码经常可以复用，但不同发行版、CPU 架构、库版本、调度器和文件系统仍可能造成差异。可靠迁移需要记录依赖、版本、编译选项和运行参数。

> [!warning]- 常见误区
> - 开源不自动等于更快；性能仍取决于软件、配置和硬件。
> - Linux 发行版之间并非完全一致，包管理器和默认配置可能不同。
> - 超级计算机统计会随时间变化，引用市场占比时必须写明来源与日期。

> [!question]- 自测
> 1. Linux 对 HPC 的优势为何不只是性能？
> 2. 从本地迁移到集群仍需记录哪些信息？
> 3. `module load` 解决了什么问题？

## 一句话总结

Linux 通过开放、可组合和可自动化的软件栈，把开发、运行与运维统一到适合服务器和 HPC 的工作流中。
