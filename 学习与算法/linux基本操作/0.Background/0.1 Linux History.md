# Linux 历史：从 Unix、GNU 到 Linux 发行版

Linux 不是凭空出现的：Unix 提供设计传统，GNU 提供自由软件工具链，Linux kernel 补上可用内核，发行版再把它们整合成完整系统。

---

## 核心理解

> [!summary]- 核心结论
> `Linux` 严格来说指内核；日常所说的 Linux 系统通常是 Linux kernel、GNU 工具、系统库、包管理器和应用软件的组合。

## 1. 关键时间线

| 时间 | 事件 | 意义 |
| --- | --- | --- |
| 1969 | Unix 在 Bell Labs 诞生 | 奠定多用户、进程、文件等系统思想 |
| 1973 | Unix 主要用 C 重写 | 降低硬件绑定，提高可移植性 |
| 1983 | Richard Stallman 发起 GNU Project | 目标是构建自由的 Unix-compatible 系统 |
| 1987 | Andrew Tanenbaum 发布 MINIX | 用于操作系统教学，对早期 Linux 开发环境有影响 |
| 1991 | Linus Torvalds 发布 Linux 0.01 | 独立编写的类 Unix 内核出现 |
| 1992 | Linux 0.12 改用 GNU GPL | 促进内核与自由软件社区协作 |

> [!warning]- MINIX 与 Linux 的关系
> Linux 早期在 MINIX 上开发并受到类 Unix 思想影响，但不是复制 MINIX 源代码，也不是 MINIX 的直接分支。

## 2. GNU 与 Linux 如何组合

GNU 已经实现编译器、shell、coreutils、C library 等大量用户空间工具，但 GNU 自己的内核长期未形成主流完整系统。Linux kernel 与这些工具组合后，形成可实际使用的自由类 Unix 系统。

```text
应用程序
GNU/其他用户空间工具与系统库
Linux kernel
硬件
```

`GNU/Linux` 强调 GNU 组件的贡献；`Linux` 在日常语境中也常泛指整套系统。理解语境比争论名称更重要。

## 3. 发行版是什么

Distribution（发行版）负责把内核、安装程序、包管理器、默认配置和软件仓库整合起来。

| 发行版家族 | 常见代表 | 特点 |
| --- | --- | --- |
| Debian | Debian、Ubuntu | `deb`、APT 生态 |
| Red Hat | RHEL、Fedora、Rocky Linux | RPM、DNF 生态，服务器常见 |
| Arch | Arch Linux | 滚动更新、高度可定制 |

Android 也使用 Linux kernel，但用户空间和应用生态与传统 GNU/Linux 发行版不同。

## 4. 为什么可移植性重要

用 C 表达大部分系统逻辑后，移植到新架构时主要重写硬件相关部分，而非整个系统。这种分层让同类工具和编程模型可以跨工作站、服务器和超级计算机复用。

## 一句话总结

Unix 提供系统传统，GNU 提供自由用户空间，Linux 提供内核，发行版负责把它们交付给用户。
