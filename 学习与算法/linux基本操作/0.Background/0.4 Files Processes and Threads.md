# 文件、进程与线程：Linux 如何保存数据并执行程序

程序是磁盘上的文件，进程是程序的一次运行实例，线程是进程中的执行流。Linux 内核用标识符、虚拟内存和调度机制管理它们。

---

## 核心概念

| 概念 | 本质 | 典型标识 |
| --- | --- | --- |
| File | 持久化字节序列或内核对象接口 | path、inode |
| Program | 可被执行的代码与数据 | 可执行文件或脚本路径 |
| Process | 运行中的资源容器 | PID |
| Thread | 进程内可被调度的执行流 | TID |

> [!tip]- 核心理解
> 同一程序可以启动多个进程；一个进程可以包含多个线程。进程隔离地址空间，线程共享所属进程的大部分资源。

## 1. 进程包含什么

一个进程通常拥有：

- 独立虚拟地址空间；
- 打开的文件描述符；
- 当前工作目录和环境变量；
- 用户与组身份；
- 一个或多个线程；
- 信号处理状态和其他内核元数据。

```bash
ps -ef
ps -o pid,ppid,stat,cmd -p PID
```

`PID` 标识进程，`PPID` 指父进程。PID 只在进程存活期间有效，结束后可能被复用。

## 2. 线程为何存在

线程共享代码、堆和打开的文件，但各自拥有栈、寄存器和调度状态。共享资源使通信更直接，也带来 data race、deadlock 等并发风险。

```text
Process
├── shared: code, heap, file descriptors
├── Thread 1: registers + stack
└── Thread 2: registers + stack
```

在 Linux 内核中，进程和线程都以 task 的形式调度；用户视角仍应区分资源隔离与共享关系。

## 3. 从命令到进程

```bash
python3 analyse.py
```

大致过程：Shell 找到 `python3` → 创建子进程 → 加载解释器 → 解释器读取脚本 → 内核调度线程 → 进程退出并返回 exit status。

用户程序通过 system call 请求内核打开文件、申请内存、创建进程或通信。标准库函数可能进一步调用一个或多个 system call。

## 4. 文件与“一切皆文件”

Linux 用文件描述符和统一 I/O 接口处理普通文件、管道、终端、socket 和许多设备，但“一切皆文件”是设计概括，不是说所有内核对象都等同于磁盘文件。

| 路径 | 类型 | 用途 |
| --- | --- | --- |
| `/dev` | 设备节点 | 终端、磁盘、`null` 等接口 |
| `/proc` | 虚拟文件系统 | 进程与内核运行信息 |
| `/sys` | 虚拟文件系统 | 设备与内核对象视图 |

```bash
cat /proc/PID/status
ls -l /proc/PID/fd
```

## 5. 生命周期与状态

进程可能处于 running、sleeping、stopped、zombie 等状态。Zombie 已经退出，但父进程尚未读取其退出状态；它不再执行代码，却暂时保留进程表记录。

> [!warning]- 常见误区
> - 程序文件不会因为进程退出而消失。
> - 一个 PID 不永久对应同一个程序。
> - 多线程共享内存不代表访问天然安全。
> - `kill` 的本质是发送信号，不一定立即“强杀”。

> [!question]- 自测
> 1. 进程与线程分别隔离或共享什么？
> 2. Zombie 为什么仍出现在进程表？
> 3. `/proc/PID/fd` 展示什么？

## 一句话总结

文件保存数据，程序描述行为，进程承载一次运行，线程则是进程中真正接受调度的执行流。
