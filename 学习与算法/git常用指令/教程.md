
# Git 常用指令

## 1. 核心总结

Git 是一个版本控制工具，主要用来记录代码或笔记文件的修改历史，并和 GitHub 等远程仓库同步。

日常最常用的流程是：

```bash id="s1js0u"
git status
git add .
git commit -m "message"
git push
````

一句话记忆：

> `add` 是把修改放进暂存区，`commit` 是保存到本地历史，`push` 是上传到远程仓库。

---

## 2. Git 基本工作区概念

Git 中常见的几个区域：

|区域|英文|含义|
|---|---|---|
|工作区|Working Directory|你正在编辑的文件|
|暂存区|Staging Area|准备提交的修改|
|本地仓库|Local Repository|已经 commit 的历史|
|远程仓库|Remote Repository|GitHub / GitLab 上的仓库|

基本流程：

```text
Working Directory
    ↓ git add
Staging Area
    ↓ git commit
Local Repository
    ↓ git push
Remote Repository
```

# 一、初始化与仓库配置

## 3. 初始化 Git 仓库

```bash
git init
```

作用：

> 在当前文件夹中创建一个 Git 仓库。

一般用于你有一个本地文件夹，想从零开始用 Git 管理。

---

## 4. 克隆远程仓库

```bash
git clone <repository-url>
```

例子：

```bash
git clone https://github.com/username/repo.git
```

作用：

> 从 GitHub 等远程平台下载一个已有仓库到本地。

---

## 5. 查看远程仓库地址

```bash
git remote -v
```

作用：

> 查看当前本地仓库连接的是哪个远程仓库。

输出可能类似：

```text
origin  https://github.com/username/repo.git (fetch)
origin  https://github.com/username/repo.git (push)
```

---

## 6. 添加远程仓库

```bash
git remote add origin <repository-url>
```

例子：

```bash
git remote add origin https://github.com/username/repo.git
```

作用：

> 把本地仓库和 GitHub 上的远程仓库连接起来。

---

# 二、日常提交流程

## 7. 查看当前状态

```bash
git status
```

作用：

> 查看哪些文件被修改、哪些文件已经暂存、当前在哪个分支。

这是最常用的 Git 指令之一。

建议每次操作前都先运行：

```bash
git status
```

---

## 8. 添加文件到暂存区

添加所有修改：

```bash
git add .
```

添加指定文件：

```bash
git add filename.md
```

添加指定文件夹：

```bash
git add Notes/
```

作用：

> 把工作区中的修改加入 staging area，准备 commit。

---

## 9. 提交修改

```bash
git commit -m "commit message"
```

例子：

```bash
git commit -m "Update OpenMP notes"
```

作用：

> 把暂存区中的修改保存到本地 Git 历史中。

注意：

> commit 只是保存到本地，还没有上传到 GitHub。

---

## 10. 推送到远程仓库

```bash
git push
```

第一次推送新分支时，可能需要：

```bash
git push -u origin main
```

作用：

> 把本地 commit 上传到 GitHub。

---

## 11. 拉取远程更新

```bash
git pull
```

作用：

> 从远程仓库获取最新修改，并合并到当前本地分支。

日常建议：

```bash
git pull
git status
git add .
git commit -m "message"
git push
```

尤其是你在多台电脑上同步 Obsidian 笔记时，最好先 `pull` 再写或提交。

---

# 三、查看历史与差异

## 12. 查看提交历史

```bash
git log
```

简洁版：

```bash
git log --oneline
```

更清楚的图形版：

```bash
git log --oneline --graph --all
```

作用：

> 查看仓库的 commit 历史。

---

## 13. 查看文件修改内容

查看未暂存的修改：

```bash
git diff
```

查看已经 add 的修改：

```bash
git diff --staged
```

作用：

> 查看这次到底改了什么。

建议在 commit 前使用：

```bash
git diff --staged
```

---

## 14. 查看某个文件的修改记录

```bash
git log -- filename.md
```

作用：

> 查看某个文件相关的提交历史。

---

# 四、分支 Branch

## 15. 查看分支

```bash
git branch
```

查看本地和远程分支：

```bash
git branch -a
```

---

## 16. 创建新分支

```bash
git branch <branch-name>
```

例子：

```bash
git branch test
```

作用：

> 创建一个新分支，但不会自动切换过去。

---

## 17. 切换分支

```bash
git switch <branch-name>
```

旧写法：

```bash
git checkout <branch-name>
```

例子：

```bash
git switch main
```

---

## 18. 创建并切换到新分支

```bash
git switch -c <branch-name>
```

旧写法：

```bash
git checkout -b <branch-name>
```

例子：

```bash
git switch -c openmp-notes
```

作用：

> 创建一个新分支，并立即切换过去。

---

## 19. 合并分支

```bash
git merge <branch-name>
```

例子：

```bash
git switch main
git merge openmp-notes
```

作用：

> 把 `openmp-notes` 分支的修改合并到当前分支。

---

## 20. 删除本地分支

```bash
git branch -d <branch-name>
```

如果 Git 不允许删除，可以强制删除：

```bash
git branch -D <branch-name>
```

---

# 五、撤销与恢复

## 21. 撤销工作区修改

```bash
git restore filename.md
```

作用：

> 放弃某个文件尚未 add 的修改，恢复到最近一次 commit 的状态。

危险程度：较高。  
因为你当前修改会被丢弃。

---

## 22. 撤销已经 add 的文件

```bash
git restore --staged filename.md
```

作用：

> 把文件从暂存区移出来，但保留工作区中的修改。

例如：

```bash
git add .
git restore --staged secret.txt
```

表示不把 `secret.txt` 放进这次 commit。

---

## 23. 修改最近一次 commit message

```bash
git commit --amend -m "new commit message"
```

作用：

> 修改最近一次提交的说明文字。

如果这个 commit 已经 push 到远程，慎用，因为可能需要 force push。

---

## 24. 回退到某个提交

```bash
git reset --hard <commit-id>
```

作用：

> 强制回到某个历史版本，并丢弃之后的修改。

危险程度：很高。

更安全的方式是使用：

```bash
git revert <commit-id>
```

`revert` 会新建一个 commit 来抵消之前的修改，不会直接改写历史。

|指令|是否改写历史|安全程度|
|---|---|---|
|`git reset --hard`|是|危险|
|`git revert`|否|较安全|

---

# 六、远程同步相关

## 25. 拉取远程分支信息

```bash
git fetch
```

作用：

> 只下载远程更新信息，不自动合并。

对比：

|指令|是否自动合并|
|---|---|
|`git fetch`|否|
|`git pull`|是|

可以理解为：

```text
git pull = git fetch + git merge
```

---

## 26. 推送当前分支并设置 upstream

```bash
git push -u origin <branch-name>
```

例子：

```bash
git push -u origin main
```

作用：

> 第一次把本地分支推送到远程，并建立默认追踪关系。

之后就可以直接：

```bash
git push
```

---

## 27. 强制推送

```bash
git push --force
```

更安全一点的强制推送：

```bash
git push --force-with-lease
```

作用：

> 用本地历史覆盖远程历史。

危险程度：很高。

适用场景：

|场景|是否可能需要 force push|
|---|---|
|修改已经 push 的 commit 历史|可能|
|使用 `git filter-repo` 清理敏感信息|可能|
|普通提交代码|不需要|
|多人协作项目|尽量避免|

建议：

> 如果只是日常 Obsidian 笔记同步，基本不需要 force push。

# 七、冲突 Conflict

## 28. 什么是 merge conflict？

当本地和远程都修改了同一个文件的同一部分，Git 不知道该保留哪一个，就会产生 conflict。

文件中可能出现：

```text
<<<<<<< HEAD
你的本地内容
=======
远程或另一个分支的内容
>>>>>>> branch-name
```

你需要手动编辑成最终想保留的内容。

---

## 29. 解决冲突的基本流程

```bash
git status
```

打开冲突文件，手动删除：

```text
<<<<<<<
=======
>>>>>>>
```

保留正确内容后：

```bash
git add .
git commit
```

如果是在 rebase 中：

```bash
git add .
git rebase --continue
```

---

## 30. 放弃 merge

```bash
git merge --abort
```

作用：

> 取消当前 merge，回到 merge 之前的状态。

---

## 31. 放弃 rebase

```bash
git rebase --abort
```

作用：

> 取消当前 rebase，回到 rebase 之前的状态。

---

# 八、Rebase 常用指令

## 32. rebase 是什么？

`rebase` 可以把当前分支的提交移动到另一个分支的最新提交之后。

简单理解：

```text
merge  -> 保留分叉历史
rebase -> 整理成更直线的历史
```

---

## 33. 常用 rebase 指令

```bash
git rebase main
```

作用：

> 把当前分支基于最新的 `main` 重新整理。

如果解决完冲突：

```bash
git add .
git rebase --continue
```

如果想跳过当前 commit：

```bash
git rebase --skip
```

如果想取消：

```bash
git rebase --abort
```

---

# 九、Stash 临时保存

## 34. stash 是什么？

`stash` 用来临时保存当前修改，但不 commit。

适合这种情况：

> 我现在改了一半，但需要先 pull 或切换分支。

---

## 35. 保存当前修改

```bash
git stash
```

带说明文字：

```bash
git stash push -m "temporary notes update"
```

---

## 36. 查看 stash 列表

```bash
git stash list
```

---

## 37. 恢复最近一次 stash

```bash
git stash pop
```

作用：

> 恢复 stash，并从 stash 列表中删除它。

只恢复但不删除：

```bash
git stash apply
```

# 十、.gitignore

## 38. .gitignore 是什么？

`.gitignore` 用来告诉 Git：

> 哪些文件不要被 Git 跟踪。

常见例子：

```gitignore
node_modules/
.env
.DS_Store
*.log
.obsidian/workspace.json
```

---

## 39. 已经被 Git 跟踪的文件，加入 .gitignore 还不够

如果一个文件已经被 Git 跟踪，即使写进 `.gitignore`，Git 仍然会继续跟踪它。

需要先取消跟踪：

```bash
git rm --cached filename
```

取消跟踪文件夹：

```bash
git rm -r --cached foldername/
```

然后：

```bash
git add .
git commit -m "Update gitignore"
```

# 十一、Obsidian 笔记同步常用流程

## 40. 最推荐的 Obsidian Git 流程

每次开始写笔记前：

```bash
git pull
```

写完之后：

```bash
git status
git add .
git commit -m "Update notes"
git push
```

如果你只在一台电脑上用，可以简单一点：

```bash
git add .
git commit -m "Update notes"
git push
```

如果你在多台设备上同步，建议一定先：

```bash
git pull
```

---

## 41. Obsidian 推荐忽略的文件

可以考虑在 `.gitignore` 中加入：

```gitignore
.obsidian/workspace.json
.obsidian/workspace-mobile.json
.obsidian/cache/
.trash/
```

如果你不想同步插件，也可以加入：

```gitignore
.obsidian/plugins/
```

但如果你想同步插件配置，就不要忽略整个 plugins 文件夹。

更稳妥的做法是只忽略容易产生本地差异的文件。

## 49. 本节一句话总结

Git 的日常核心就是 `status → add → commit → push`；如果涉及远程同步，最好先 `pull`，再修改和提交；如果遇到冲突，就用 `status` 找到冲突文件，手动解决后 `add` 并继续 `commit` 或 `rebase --continue`。
