# OpenMP Clauses

## 1. 本节核心总结

OpenMP 的 **clause** 是写在 directive 后面的附加修饰，用来控制 parallel construct 的行为。  
例如，`num_threads(4)` 可以指定线程数，`private(x)` 可以让每个线程拥有自己的 `x`，`reduction(+:sum)` 可以安全地合并多个线程的局部结果。  
理解 clauses 的关键是理解 **变量在 parallel region 中到底是 shared 还是 private**。  
在实际 OpenMP 编程中，`private`、`firstprivate`、`shared`、`default(none)`、`reduction` 和 `num_threads` 最常用。

---

## 2. Clauses 快速总览表

| Clause | 作用 | 常见程度 | 重点理解 |
|---|---|---|---|
| `if(expression)` | 根据条件决定是否启用 parallel construct | 中 | 条件为 false 时不并行 |
| `private(list)` | 每个线程拥有变量的独立副本 | 高 | 初始值未定义 |
| `firstprivate(list)` | 每个线程拥有独立副本，并复制进入 parallel region 前的值 | 中 | private + 初始化 |
| `default(shared/none)` | 设置变量默认共享规则 | 高 | 推荐 `default(none)` |
| `shared(list)` | 指定变量由所有线程共享 | 高 | 多线程访问同一个变量 |
| `copyin(list)` | 把 primary thread 的 threadprivate 变量复制给其他线程 | 低 | 只用于 `threadprivate` 变量 |
| `reduction(operator:list)` | 每个线程先私有计算，最后合并结果 | 高 | 求和、最大值、最小值常用 |
| `num_threads(n)` | 指定该 parallel region 使用的线程数 | 高 | 覆盖其他线程数设置 |

---

## 3. Clause 的基本位置

OpenMP clause 写在 OpenMP directive 后面。

基本形式：

```c
#pragma omp parallel [clause[, clause] ...]
{
    // parallel region
}
````

例如：

```c
#pragma omp parallel num_threads(4) private(x) shared(a)
{
    // code
}
```

这里：

- `parallel` 是 directive name
    
- `num_threads(4)` 是 clause
    
- `private(x)` 是 clause
    
- `shared(a)` 是 clause
    

可以理解为：

```text
directive 决定“要做什么”
clause 决定“怎么做”
```

# 4. `if` clause

## 4.1 作用

`if` clause 用来根据条件决定是否真正启用 parallel construct。

语法：

```c
#pragma omp parallel if(expression)
{
    // code
}
```

如果 `expression` 为 true，则创建多个线程。  
如果 `expression` 为 false，则 parallel construct 不会真正并行执行，通常只由一个线程执行。

---

## 4.2 示例

```c
int n = 100;

#pragma omp parallel if(n > 1000)
{
    printf("Parallel region\n");
}
```

如果 `n = 100`，那么 `n > 1000` 为 false，所以这段代码不会真正并行。

如果 `n = 1000000`，那么条件为 true，OpenMP 才会创建多个线程。

---

## 4.3 为什么需要 if clause？

有些任务太小，并行化反而不划算。

因为创建线程、同步线程都有 overhead。

例如：

```text
问题规模很小：
并行开销 > 并行收益

问题规模很大：
并行收益 > 并行开销
```

所以可以写成：

```c
#pragma omp parallel for if(n > 10000)
for (int i = 0; i < n; i++) {
    a[i] = b[i] + c[i];
}
```

含义是：

> 只有当循环规模足够大时，才使用 OpenMP 并行。

---

## 4.4 另一个不会并行的情况

课本还提到一个情况：

如果当前已经处在一个 active parallel construct 里面，并且 OpenMP 的 nesting flag 是关闭的，那么新的 parallel construct 也不会真正创建新的嵌套线程团队。

默认情况下：

```text
nesting = off
```

也就是说，OpenMP 默认不启用 nested parallelism。

# 5. `private` clause

## 5.1 作用

`private(list)` 表示列表中的变量在 parallel region 中对每个线程都是私有的。

语法：

```c
#pragma omp parallel private(x)
{
    // each thread has its own x
}
```

含义是：

> 每个线程都有一个独立的 `x`，互不影响。

---

## 5.2 重要特点

`private` 变量有两个非常重要的特点：

|位置|状态|
|---|---|
|parallel region 开始时|private 变量的初始值是 undefined|
|parallel region 结束后|外部原变量的值也是 undefined / 不应依赖|

更简单地说：

> `private(x)` 只保证每个线程有自己的 `x`，但不保证它一开始有正确初始值。

---

## 5.3 示例

```c
int x = 10;

#pragma omp parallel private(x)
{
    x = omp_get_thread_num();
    printf("x = %d\n", x);
}

printf("outside x = %d\n", x);
```

在 parallel region 内，每个线程都有自己的 `x`。

可能输出：

```text
x = 0
x = 1
x = 2
x = 3
outside x = 10
```

但是按照 OpenMP 语义，不能依赖 private 变量在区域结束后的外部值来表达计算结果。

---

## 5.4 容易犯的错误

错误写法：

```c
int x = 10;

#pragma omp parallel private(x)
{
    printf("%d\n", x);
}
```

很多人以为每个线程会打印 `10`，但这是错误的。

因为 `private(x)` 中的 `x` 在 parallel region 开始时是未定义的。

正确理解：

```text
外面的 x = 10
每个线程自己的 private x = undefined
```

如果想让每个线程的私有副本一开始等于外面的 `x`，应该使用 `firstprivate`。

---

# 6. `firstprivate` clause

## 6.1 作用

`firstprivate(list)` 和 `private(list)` 类似，也会让每个线程拥有变量的独立副本。

不同点是：

> `firstprivate` 会把进入 parallel region 之前的变量值复制给每个线程的私有副本。

语法：

```c
#pragma omp parallel firstprivate(x)
{
    // each thread has private x initialized from original x
}
```

可以理解为：

```text
firstprivate = private + initial value copied from outside
```

---

## 6.2 示例

```c
int x = 10;

#pragma omp parallel firstprivate(x)
{
    printf("initial x = %d\n", x);
    x += omp_get_thread_num();
    printf("modified x = %d\n", x);
}

printf("outside x = %d\n", x);
```

每个线程开始时自己的 `x` 都是 `10`。

可能输出：

```text
initial x = 10
initial x = 10
initial x = 10
initial x = 10
modified x = 10
modified x = 11
modified x = 12
modified x = 13
outside x = 10
```

外部 `x` 不会被每个线程的私有修改影响。

---

## 6.3 private vs firstprivate

|Clause|每个线程是否有独立副本|初始值|
|---|---|---|
|`private(x)`|是|undefined|
|`firstprivate(x)`|是|复制进入 parallel region 前的值|

简单记忆：

```text
private: 私有，但没初始值
firstprivate: 私有，并且先复制初始值
```

---

# 7. `default` clause

## 7.1 作用

`default` clause 用来设置 parallel region 中变量的默认 sharing attribute。

语法：

```c
#pragma omp parallel default(shared)
{
    // variables are shared by default
}
```

或者：

```c
#pragma omp parallel default(none)
{
    // every variable must be explicitly specified
}
```

在 C/C++ 中，常见选项是：

|选项|含义|
|---|---|
|`default(shared)`|未显式说明的变量默认 shared|
|`default(none)`|所有变量都必须明确写出 shared/private 等属性|

注意：课本中提到 `default(private)` 只适用于 Fortran，不适用于 C/C++。

---

## 7.2 推荐使用 `default(none)`

在学习和写严谨代码时，推荐使用：

```c
#pragma omp parallel default(none) shared(a, n) private(i)
{
    // code
}
```

原因是：

> `default(none)` 会强迫你明确说明每个变量是 shared 还是 private，可以减少 race condition 和变量作用域错误。

---

## 7.3 示例

```c
int n = 100;
double a[100];

#pragma omp parallel for default(none) shared(a, n)
for (int i = 0; i < n; i++) {
    a[i] = i * 2.0;
}
```

这里：

- `a` 是 shared，因为所有线程共同写入同一个数组的不同位置
    
- `n` 是 shared，因为所有线程只读取它
    
- `i` 是循环变量，在 OpenMP `parallel for` 中通常自动 private
    

---

# 8. `shared` clause

## 8.1 作用

`shared(list)` 表示列表中的变量由所有线程共享。

语法：

```c
#pragma omp parallel shared(a, n)
{
    // all threads access the same a and n
}
```

也就是说：

> 所有线程看到的是同一个变量，而不是各自的副本。

---

## 8.2 示例

```c
int x = 0;

#pragma omp parallel shared(x)
{
    x = x + 1;
}

printf("x = %d\n", x);
```

这段代码有问题，因为多个线程同时修改同一个 shared 变量 `x`，可能发生 **race condition**。

如果有 4 个线程，直觉上你可能期待输出：

```text
x = 4
```

但实际结果可能不是 4。

原因是：

```text
x = x + 1
```

不是一个原子操作，它包含读取、加一、写回多个步骤。

---

## 8.3 shared 变量的常见用途

shared 变量适合：

|场景|是否适合 shared|
|---|---|
|多线程只读同一个变量|适合|
|多线程写数组不同位置|通常适合|
|多线程同时更新同一个标量变量|危险，可能 race condition|
|所有线程需要访问同一个大数组|适合|

例如：

```c
#pragma omp parallel for shared(a, b, c, n)
for (int i = 0; i < n; i++) {
    a[i] = b[i] + c[i];
}
```

这里 `a`、`b`、`c` 都是 shared，但是每个线程处理不同的 `i`，所以通常是安全的。

---

# 9. `copyin` clause

## 9.1 作用

`copyin(list)` 用于把 **primary thread** 中的 `threadprivate` 变量复制到其他线程中。

课本中的核心意思是：

> 在创建线程之后、线程开始执行工作之前，把 primary thread 的变量值复制给其他线程。

语法大致为：

```c
#pragma omp parallel copyin(x)
{
    // each thread's threadprivate x gets initial value from primary thread
}
```

---

## 9.2 为什么 copyin 要求变量是 threadprivate？

课本中特别说明：

> The variables in the list must also be threadprivate because if they were shared, copying would be meaningless.

意思是：

如果变量本来就是 shared，那么所有线程看到的已经是同一个变量，没有“复制”的意义。

只有当变量是 `threadprivate` 时，每个线程都有自己的副本，`copyin` 才有意义。

---

## 9.3 初学阶段如何处理 copyin？

对你目前学习 OpenMP 来说，`copyin` 不是最优先的重点。

你可以先记住：

```text
copyin 主要用于 threadprivate 变量。
普通 parallel for、reduction、private/shared 场景中较少使用。
```

优先掌握：

```text
private
firstprivate
shared
default(none)
reduction
num_threads
```

# 10. `reduction` clause

## 10.1 作用

`reduction(operator:list)` 用于把多个线程的局部结果安全地合并成一个最终结果。

最常见例子是求和：

```c
double sum = 0.0;

#pragma omp parallel for reduction(+:sum)
for (int i = 0; i < n; i++) {
    sum += a[i];
}
```

如果不用 `reduction`，多个线程同时执行：

```c
sum += a[i];
```

会产生 race condition。

---

## 10.2 reduction 的执行过程

`reduction(+:sum)` 可以理解为三步：

```text
1. 每个线程创建自己的 private sum
2. 每个线程在自己的 private sum 上累加
3. parallel region 结束时，把所有 private sum 合并到原来的 sum
```

图示：

```text
Thread 0: local sum = 10
Thread 1: local sum = 20
Thread 2: local sum = 15
Thread 3: local sum = 25

Final sum = 10 + 20 + 15 + 25 = 70
```

---

## 10.3 reduction 为什么比 critical 更适合求和？

也可以用 `critical` 防止 race condition：

```c
double sum = 0.0;

#pragma omp parallel for
for (int i = 0; i < n; i++) {
    #pragma omp critical
    {
        sum += a[i];
    }
}
```

但这通常很慢，因为每次更新 `sum` 都要排队。

更推荐：

```c
double sum = 0.0;

#pragma omp parallel for reduction(+:sum)
for (int i = 0; i < n; i++) {
    sum += a[i];
}
```

原因：

|方法|正确性|性能|
|---|---|---|
|直接 shared sum|错误，race condition|不可靠|
|`critical`|正确|通常较慢|
|`reduction`|正确|通常更快|

---

## 10.4 C/C++ 常见 reduction 操作

|Reduction 类型|C/C++ operator|每个线程私有副本初始值|
|---|---|---|
|Add|`+`|`0`|
|Multiply|`*`|`1`|
|Subtract|`-`|`0`|
|Max|`max`|该类型可表示的最小值|
|Min|`min`|该类型可表示的最大值|
|Logical AND|`&&`|`1`|
|Logical OR|`||
|Bitwise AND|`&`|`~0`|
|Bitwise OR|`|`|
|Bitwise XOR|`^`|`0`|

注意：你给的课本表格里 Min 的 Fortran 操作符部分可能写成了 `MAX`，从语义上看这里应对应 `MIN`。但你做笔记时可以重点记 C/C++ 部分即可。

---

## 10.5 reduction 示例：求最大值

```c
int max_value = a[0];

#pragma omp parallel for reduction(max:max_value)
for (int i = 0; i < n; i++) {
    if (a[i] > max_value) {
        max_value = a[i];
    }
}
```

含义是：

- 每个线程维护自己的局部最大值
    
- 最后 OpenMP 把所有局部最大值合并成全局最大值
    

---

## 10.6 reduction 中外部变量的状态

课本提到：

> Any variable defined outside the parallel region that is involved in a reduction operation is undefined while the reduction calculation is in progress.

意思是：

当 reduction 正在进行时，不应该在 parallel region 内依赖外部那个原始 reduction 变量的值。

因为每个线程实际操作的是自己的 private copy。

简单理解：

```text
parallel region 内：线程主要使用 private copy
parallel region 结束后：结果合并回原变量
```

# 11. `num_threads` clause

## 11.1 作用

`num_threads(integer expression)` 用于指定当前 parallel region 使用的线程数量。

语法：

```c
#pragma omp parallel num_threads(4)
{
    // use 4 threads if possible
}
```

课本强调：

> `num_threads` 会覆盖其他指定线程数量的方式。

例如，即使环境变量中设置：

```bash
export OMP_NUM_THREADS=8
```

如果代码中写：

```c
#pragma omp parallel num_threads(4)
{
    // code
}
```

那么这个 parallel region 会优先尝试使用 4 个线程。

---

## 11.2 示例

```c
#include <stdio.h>
#include <omp.h>

int main() {
    #pragma omp parallel num_threads(4)
    {
        printf("Thread %d of %d\n",
               omp_get_thread_num(),
               omp_get_num_threads());
    }

    return 0;
}
```

可能输出：

```text
Thread 0 of 4
Thread 2 of 4
Thread 1 of 4
Thread 3 of 4
```

输出顺序不固定，这是正常的。

# 12. 常用 Clause 对比总结

## 12.1 变量作用域相关 clauses

|Clause|是否每个线程有独立副本|初始值|是否影响外部变量|
|---|---|---|---|
|`private(x)`|是|undefined|不应该依赖区域后的外部值|
|`firstprivate(x)`|是|外部进入前的值|不影响外部变量|
|`shared(x)`|否，所有线程共享同一个 x|原变量值|会影响同一个变量|
|`reduction(+:x)`|是，先私有再合并|取决于 operator|结束后合并到外部变量|

---

## 12.2 如何选择？

|需求|推荐 clause|
|---|---|
|每个线程需要自己的临时变量|`private`|
|每个线程需要自己的变量，并且初始值来自外部|`firstprivate`|
|所有线程只读同一个变量|`shared`|
|所有线程写数组不同位置|`shared` 数组 + private 循环索引|
|多线程累加一个结果|`reduction(+:sum)`|
|多线程找最大值|`reduction(max:max_value)`|
|想明确检查变量作用域|`default(none)`|
|想指定线程数|`num_threads(n)`|
|小问题不想并行|`if(n > threshold)`|

# 13. 常见错误总结

## 13.1 错误 1：把需要初始值的变量写成 private

错误：

```c
int x = 10;

#pragma omp parallel private(x)
{
    printf("%d\n", x);
}
```

问题：

```text
private x 在 parallel region 开始时是 undefined，不一定是 10。
```

正确：

```c
int x = 10;

#pragma omp parallel firstprivate(x)
{
    printf("%d\n", x);
}
```

---

## 13.2 错误 2：多个线程直接更新 shared 标量变量

错误：

```c
double sum = 0.0;

#pragma omp parallel for shared(sum)
for (int i = 0; i < n; i++) {
    sum += a[i];
}
```

问题：

```text
多个线程同时更新 sum，会产生 race condition。
```

正确：

```c
double sum = 0.0;

#pragma omp parallel for reduction(+:sum)
for (int i = 0; i < n; i++) {
    sum += a[i];
}
```

---

## 13.3 错误 3：以为 num_threads 一定绝对生效

```c
#pragma omp parallel num_threads(8)
{
    printf("%d\n", omp_get_num_threads());
}
```

通常会使用 8 个线程，但实际运行环境、runtime 设置、系统限制、dynamic 调整等因素也可能影响最终线程数。

更稳妥的做法是在 parallel region 中检查：

```c
omp_get_num_threads()
```

---

## 13.4 错误 4：不写 default(none)，导致变量作用域不清楚

不推荐：

```c
#pragma omp parallel for
for (int i = 0; i < n; i++) {
    a[i] = b[i] + c[i];
}
```

更清晰：

```c
#pragma omp parallel for default(none) shared(a, b, c, n)
for (int i = 0; i < n; i++) {
    a[i] = b[i] + c[i];
}
```

这样可以强制自己检查每个变量的作用域。

---

# 14. 本节重点

- Clause 是 OpenMP directive 后面的修饰项，用来控制 construct 的行为。
    
- `private` 会给每个线程创建独立副本，但初始值 undefined。
    
- `firstprivate` 会给每个线程创建独立副本，并复制外部初始值。
    
- `shared` 表示所有线程访问同一个变量。
    
- `default(none)` 推荐用于明确变量作用域。
    
- `reduction` 用于安全高效地合并多线程结果。
    
- `num_threads` 用于指定当前 parallel region 的线程数。
    
- `if` 可以根据问题规模决定是否启用并行。
    
- 初学时最重要的 clauses 是：`private`、`firstprivate`、`shared`、`default(none)`、`reduction`、`num_threads`。
    

---

# 15. 一句话记忆

```text
private 是每个线程各有一份但没初始值；firstprivate 是各有一份并复制初始值；shared 是所有线程共用一份；reduction 是各算各的，最后合并。
```
