# OpenMP Loop Construct

## 1. 本节核心总结

OpenMP 的 **loop construct** 用来把循环的不同 iterations 分配给多个 threads 执行。  
在 C/C++ 中使用 `#pragma omp for`，在 Fortran 中使用 `do directive`，本笔记主要关注 C/C++ 写法。  
`#pragma omp for` 本身必须出现在一个已经存在的 `parallel region` 内；如果 parallel region 刚好就是这个 loop，则可以合并写成 `#pragma omp parallel for`。  
OpenMP loop 并不是任何循环都能并行，它要求循环边界在执行前可确定，循环变量不能在 loop body 中被随意修改，也不能随意 `break` 跳出 OpenMP 控制的循环。

---

## 2. 快速对照表

| 概念 | 英文关键词 | 简单理解 |
|---|---|---|
| Loop construct | `for` construct | 用 OpenMP 并行化循环 |
| C/C++ directive | `#pragma omp for` | 把 for-loop 的 iterations 分给多个线程 |
| Combined construct | `#pragma omp parallel for` | 创建线程并立即分配循环任务 |
| Loop region | loop region | 被 OpenMP for directive 控制的循环范围 |
| Iteration variable | loop index | 循环变量，例如 `i` |
| Implicitly private | automatically private | OpenMP 会自动把循环变量设为 private |
| Nested loop | nested loop | 循环里面还有循环 |
| Nested parallelism | nested parallel regions | parallel region 里面再创建 parallel region |
| Branching restriction | no illegal branch | 不能随意跳入或跳出 OpenMP loop |

---

## 3. Loop Construct 是什么？

OpenMP loop construct 的作用是：

> 把一个循环中的不同 iterations 分配给多个线程执行。

在 C/C++ 中，基本形式是：

```c
#pragma omp for
for (int i = 0; i < n; i++) {
    // loop body
}
````

但要注意：

```c
#pragma omp for
```

必须出现在一个已经存在的 `parallel region` 里面。

所以完整写法通常是：

```c
#pragma omp parallel
{
    #pragma omp for
    for (int i = 0; i < n; i++) {
        a[i] = b[i] + c[i];
    }
}
```

这里的执行逻辑是：

```text
1. #pragma omp parallel 创建多个 threads
2. #pragma omp for 把 for-loop 的 iterations 分配给这些 threads
3. 每个 thread 执行一部分循环
4. 所有 iterations 合起来完成整个 loop
```

---

## 4. `parallel` 和 `for` 的关系

### 4.1 `parallel` 只负责创建线程

```c
#pragma omp parallel
{
    printf("Hello\n");
}
```

这会让每个线程都执行一次 `printf`。

如果有 4 个线程，可能输出 4 次：

```text
Hello
Hello
Hello
Hello
```

---

### 4.2 `for` 负责分配循环 iterations

```c
#pragma omp parallel
{
    #pragma omp for
    for (int i = 0; i < 8; i++) {
        printf("i = %d\n", i);
    }
}
```

这里不是每个线程都完整执行 `i = 0` 到 `7`，而是 OpenMP 把这些 iterations 分给不同线程。

例如 4 个线程时，可能类似：

```text
Thread 0: i = 0, 1
Thread 1: i = 2, 3
Thread 2: i = 4, 5
Thread 3: i = 6, 7
```

具体分配方式取决于 `schedule` 设置。

---

## 5. 最常用写法：`parallel for`

如果一个 parallel region 只包含一个 loop，那么可以把：

```c
#pragma omp parallel
{
    #pragma omp for
    for (int i = 0; i < n; i++) {
        // work
    }
}
```

简写成：

```c
#pragma omp parallel for
for (int i = 0; i < n; i++) {
    // work
}
```

这叫 **combined construct**。

它等价于：

```text
创建线程 + 分配 loop iterations
```

因此，实际编程中最常见的写法是：

```c
#pragma omp parallel for
for (int i = 0; i < n; i++) {
    a[i] = b[i] + c[i];
}
```

---

## 6. Loop Construct 的范围

在 C/C++ 中，`#pragma omp for` 控制的是它后面紧跟着的那个 `for` loop。

例如：

```c
#pragma omp parallel
{
    #pragma omp for
    for (int i = 0; i < n; i++) {
        a[i] = i;
    }

    printf("Done\n");
}
```

这里：

```c
for (int i = 0; i < n; i++) {
    a[i] = i;
}
```

是 OpenMP loop construct 的范围。

但：

```c
printf("Done\n");
```

不属于 `#pragma omp for` 的 loop region。

不过它仍然在 `parallel region` 里面，所以每个线程都会执行一次 `printf("Done\n")`。

---

## 7. `#pragma omp for` 不能单独出现在 parallel region 外面

错误写法：

```c
#pragma omp for
for (int i = 0; i < n; i++) {
    a[i] = i;
}
```

问题是：

```text
#pragma omp for 必须由已有的 thread team 来执行。
如果没有 parallel region，就没有多个 threads 可以分配 loop iterations。
```

正确写法 1：

```c
#pragma omp parallel
{
    #pragma omp for
    for (int i = 0; i < n; i++) {
        a[i] = i;
    }
}
```

正确写法 2：

```c
#pragma omp parallel for
for (int i = 0; i < n; i++) {
    a[i] = i;
}
```

# 8. OpenMP Loop 的限制

并不是所有 `for` loop 都能直接加 OpenMP。

OpenMP 对 loop construct 有几个重要限制。

---

## 8.1 限制 1：循环变量不能在 loop body 中被随意修改

合法写法：

```c
#pragma omp parallel for
for (int i = 0; i < n; i++) {
    a[i] = i;
}
```

错误写法：

```c
#pragma omp parallel for
for (int i = 0; i < n; i++) {
    i = i + 2;   // 不应该在 loop body 中修改 iteration variable
    a[i] = i;
}
```

原因是：

```text
OpenMP 需要根据循环变量 i 的初始值、结束条件和步长来分配 iterations。
如果在 loop body 中随意修改 i，OpenMP 就无法正确调度循环。
```

循环变量只能通过 `for` 语句本身的 increment expression 改变，例如：

```c
for (int i = 0; i < n; i++)
```

或者：

```c
for (int i = 0; i < n; i += 2)
```

---

## 8.2 限制 2：循环初始值和边界必须在 loop 开始前可确定

OpenMP 需要在循环开始前知道：

```text
循环从哪里开始
循环到哪里结束
每次增加多少
总共有多少 iterations
```

例如：

```c
#pragma omp parallel for
for (int i = 0; i < n; i++) {
    a[i] = i;
}
```

这里 `0`、`n`、`i++` 都可以在 loop 开始前确定，所以可以被 OpenMP 调度。

不适合并行的例子：

```c
#pragma omp parallel for
for (int i = 0; i < get_limit_during_loop(); i++) {
    a[i] = i;
}
```

如果循环边界依赖循环执行过程中的变化，OpenMP 就很难提前分配 iterations。

---

## 8.3 限制 3：OpenMP loop 中不能随意 `break`

串行代码中常见写法：

```c
for (int i = 0; i < n; i++) {
    if (a[i] == target) {
        break;
    }
}
```

但在 OpenMP 控制的 loop 中，不能随意 `break` 跳出：

```c
#pragma omp parallel for
for (int i = 0; i < n; i++) {
    if (a[i] == target) {
        break;  // 不允许
    }
}
```

原因是：

```text
OpenMP 已经把不同 iterations 分配给不同 threads。
如果某个 thread 突然 break，其他 threads 可能还在执行自己的 iterations。
这会破坏 OpenMP 对 loop 的调度和同步。
```

---

## 8.4 可以跳出嵌套在 OpenMP loop 内部的普通 loop

课本中提到：

> It is OK to break out of a loop nested inside an OpenMP loop.

例如：

```c
#pragma omp parallel for
for (int i = 0; i < n; i++) {

    for (int j = 0; j < m; j++) {
        if (condition(i, j)) {
            break;  // 允许，因为 break 的是内部普通 loop
        }
    }

}
```

这里 `break` 只跳出内部的 `j` loop，不是跳出 OpenMP 控制的外层 `i` loop，所以可以。

---

## 8.5 跳到 error handler 的特殊情况

课本中提到，如果从 OpenMP loop 跳出到 error handler 是允许的。

但如果这种情况发生，OpenMP 会自动终止正在处理 loop 其他部分的线程。

这属于异常处理场景，不是常规控制流程。

初学阶段可以记为：

```text
普通情况下，不要从 OpenMP loop 中 break / goto / return 跳出。
```

# 9. Iteration Variable 的 private 规则

OpenMP 会自动把被它控制的循环变量设为 private。

例如：

```c
#pragma omp parallel for
for (int i = 0; i < n; i++) {
    a[i] = i;
}
```

这里的 `i` 会被 OpenMP 自动处理成每个线程自己的私有变量。

所以你通常不需要写：

```c
#pragma omp parallel for private(i)
```

尤其当 `i` 在 `for` 语句中声明时：

```c
for (int i = 0; i < n; i++)
```

这是最清晰、最安全的写法。

---

## 9.1 如果循环变量在外面声明

例如：

```c
int i;

#pragma omp parallel for
for (i = 0; i < n; i++) {
    a[i] = i;
}
```

OpenMP 仍然会把这个 loop 的 iteration variable `i` 隐式设为 private。

但是要注意：

> loop construct 结束后，外部的 `i` 的最终值不能可靠使用，除非使用 `lastprivate`。

---

## 9.2 `lastprivate` 的作用

课本提到：

> The final value of the iteration variable will not be available outside the loop construct unless it is listed in a lastprivate clause.

意思是，如果你想在 OpenMP loop 结束后使用最后一次 iteration 的变量值，需要 `lastprivate`。

例如：

```c
int i;

#pragma omp parallel for lastprivate(i)
for (i = 0; i < n; i++) {
    a[i] = i;
}

printf("Final i = %d\n", i);
```

`lastprivate(i)` 会把逻辑上最后一次 iteration 后的 `i` 值复制回外部变量。

但在实际代码中，更推荐避免依赖 loop 后的 `i` 值。

---

## 9.3 Nested Loop 的变量要小心

课本中特别提醒：

> The iteration variables for nested loops, if they are declared outside the parallel region, will not be made private by default.

例如：

```c
int i, j;

#pragma omp parallel for
for (i = 0; i < n; i++) {
    for (j = 0; j < m; j++) {
        a[i][j] = i + j;
    }
}
```

这里：

- 外层 `i` 是 OpenMP 控制的 iteration variable，会自动 private
    
- 内层 `j` 如果在外面声明，可能不是自动 private，可能导致 race condition
    

更好的写法是：

```c
#pragma omp parallel for
for (int i = 0; i < n; i++) {
    for (int j = 0; j < m; j++) {
        a[i][j] = i + j;
    }
}
```

或者显式写：

```c
int i, j;

#pragma omp parallel for private(j)
for (i = 0; i < n; i++) {
    for (j = 0; j < m; j++) {
        a[i][j] = i + j;
    }
}
```

# 10. Nested Parallel Loops

## 10.1 什么是 Nested Parallelism？

从 OpenMP 3.0 开始，可以使用 nested parallel regions。

也就是说，一个 parallel region 里面可以再创建新的 parallel region。
![[Pasted image 20260525165618.png]]

例如：

```c
#pragma omp parallel
{
    #pragma omp parallel
    {
        // nested parallel region
    }
}
```

在 nested parallel region 中：

```text
外层 parallel region 中的某个 thread
可以创建自己的 short-lived thread team
```

---

## 10.2 Nested Parallel Loop 示例

例如：

```c
#pragma omp parallel for
for (int i = 0; i < n; i++) {

    #pragma omp parallel for
    for (int j = 0; j < m; j++) {
        a[i][j] = i + j;
    }

}
```

这表示外层 loop 并行，内层 loop 也尝试并行。

但是这通常不是一个好主意。

---

## 10.3 为什么 nested parallelism 不一定好？

课本强调：

> just because you can have them, doesn't mean you necessarily should

也就是说：

> OpenMP 支持 nested parallelism，不代表你应该随便使用它。

原因包括：

|问题|解释|
|---|---|
|线程数量膨胀|外层每个线程可能再创建一组内层线程|
|调度开销增加|创建和销毁线程 team 有 overhead|
|资源争抢|线程数超过 cores 数量可能导致 oversubscription|
|性能不稳定|线程调度、cache、NUMA 影响更复杂|
|难以调试|嵌套并行更容易产生 race condition 和同步问题|

例如，如果外层有 8 个线程，内层每个线程又创建 8 个线程，理论上可能变成：

```text
8 × 8 = 64 threads
```

如果机器只有 16 个 cores，就可能导致线程过多，性能反而下降。

---

## 10.4 什么时候 nested parallelism 可能有用？

课本提到，nested parallelism 可能适合某些算法：

```text
某些阶段可并行的 work 很少
需要在局部阶段额外启动线程来提高 core utilization
```

也就是说，当程序某些部分天然并行度不足时，nested parallelism 可能有帮助。

但一般情况下，我们更希望：

```text
在大多数 parallel regions 中保持相同数量的 threads
让 cores 持续饱和
避免频繁创建额外线程
```

# 11. Loop Construct 常见例子

## 11.1 向量加法

```c
#pragma omp parallel for
for (int i = 0; i < n; i++) {
    a[i] = b[i] + c[i];
}
```

为什么适合并行？

```text
每个 iteration 写入不同的 a[i]
不同 iterations 之间没有依赖
```

---

## 11.2 数组求和

错误写法：

```c
double sum = 0.0;

#pragma omp parallel for
for (int i = 0; i < n; i++) {
    sum += a[i];
}
```

问题：

```text
多个 threads 同时更新 shared sum，产生 race condition。
```

正确写法：

```c
double sum = 0.0;

#pragma omp parallel for reduction(+:sum)
for (int i = 0; i < n; i++) {
    sum += a[i];
}
```

---

## 11.3 二维数组更新

推荐写法：

```c
#pragma omp parallel for
for (int i = 0; i < n; i++) {
    for (int j = 0; j < m; j++) {
        a[i][j] = b[i][j] + c[i][j];
    }
}
```

如果 `i` 和 `j` 都在 loop 内声明，变量作用域更清晰。

---

## 11.4 有 loop-carried dependency 的循环不能直接并行

例如：

```c
for (int i = 1; i < n; i++) {
    a[i] = a[i - 1] + b[i];
}
```

这里 `a[i]` 依赖前一次 iteration 的 `a[i - 1]`。

所以不能简单写成：

```c
#pragma omp parallel for
for (int i = 1; i < n; i++) {
    a[i] = a[i - 1] + b[i];
}
```

原因是：

```text
iteration i 依赖 iteration i-1 的结果。
如果多个 iterations 同时执行，结果可能错误。
```

这种依赖叫：

```text
loop-carried dependency
```

---

# 12. 如何判断一个 loop 能不能并行？

可以用这个检查表：

|问题|如果答案是 Yes|
|---|---|
|每个 iteration 是否独立？|更可能适合并行|
|是否写入不同数组位置？|通常安全|
|是否多个线程更新同一个变量？|需要 reduction / atomic / critical|
|是否存在 `a[i]` 依赖 `a[i-1]`？|不能直接并行|
|是否会在 loop 中 `break`？|不适合 OpenMP loop|
|loop 边界是否在开始前可确定？|OpenMP 可以调度|
|loop body 是否修改 iteration variable？|不允许|

# 13. `parallel for` 常用模板

## 13.1 基础模板

```c
#pragma omp parallel for
for (int i = 0; i < n; i++) {
    // independent work
}
```

---

## 13.2 推荐学习模板：加上 `default(none)`

```c
#pragma omp parallel for default(none) shared(a, b, c, n)
for (int i = 0; i < n; i++) {
    a[i] = b[i] + c[i];
}
```

这样可以明确变量作用域。

---

## 13.3 带 reduction 的模板

```c
double sum = 0.0;

#pragma omp parallel for default(none) shared(a, n) reduction(+:sum)
for (int i = 0; i < n; i++) {
    sum += a[i];
}
```

---

## 13.4 Nested loop 模板

```c
#pragma omp parallel for default(none) shared(a, b, c, n, m)
for (int i = 0; i < n; i++) {
    for (int j = 0; j < m; j++) {
        a[i][j] = b[i][j] + c[i][j];
    }
}
```

更推荐让 `i` 和 `j` 都在 loop header 中声明。

# 14. 常见错误总结

## 14.1 错误 1：在 parallel region 外使用 `omp for`

错误：

```c
#pragma omp for
for (int i = 0; i < n; i++) {
    a[i] = i;
}
```

正确：

```c
#pragma omp parallel for
for (int i = 0; i < n; i++) {
    a[i] = i;
}
```

或者：

```c
#pragma omp parallel
{
    #pragma omp for
    for (int i = 0; i < n; i++) {
        a[i] = i;
    }
}
```

---

## 14.2 错误 2：以为 `parallel` 和 `parallel for` 一样

```c
#pragma omp parallel
for (int i = 0; i < n; i++) {
    a[i] = i;
}
```

这通常不是你想要的。

因为每个线程都会完整执行整个 loop，可能导致重复计算。

正确：

```c
#pragma omp parallel for
for (int i = 0; i < n; i++) {
    a[i] = i;
}
```

---

## 14.3 错误 3：在 OpenMP loop 中使用 `break`

错误：

```c
#pragma omp parallel for
for (int i = 0; i < n; i++) {
    if (a[i] == target) {
        break;
    }
}
```

OpenMP loop 不允许这样跳出。

可以改成使用 shared flag，但需要小心同步。例如概念上：

```c
int found = 0;

#pragma omp parallel for shared(found)
for (int i = 0; i < n; i++) {
    if (!found && a[i] == target) {
        found = 1;
    }
}
```

不过这个简单写法本身也可能涉及 race condition。更严谨的写法后面学到 `atomic` 或 `critical` 时再处理。

---

## 14.4 错误 4：忽略 nested loop 的内层变量

不推荐：

```c
int i, j;

#pragma omp parallel for
for (i = 0; i < n; i++) {
    for (j = 0; j < m; j++) {
        a[i][j] = i + j;
    }
}
```

更推荐：

```c
#pragma omp parallel for
for (int i = 0; i < n; i++) {
    for (int j = 0; j < m; j++) {
        a[i][j] = i + j;
    }
}
```

---

## 14.5 错误 5：并行化有依赖的循环

错误：

```c
#pragma omp parallel for
for (int i = 1; i < n; i++) {
    a[i] = a[i - 1] + b[i];
}
```

问题：

```text
a[i] 依赖 a[i-1]，iterations 之间不是独立的。
```

---

# 15. 本节重点

- OpenMP loop construct 在 C/C++ 中使用 `#pragma omp for`。
    
- `#pragma omp for` 必须出现在 `parallel region` 内。
    
- 最常用写法是 `#pragma omp parallel for`。
    
- `parallel` 创建线程，`for` 分配 loop iterations。
    
- loop construct 控制的是 directive 后面紧跟着的那个 loop。
    
- OpenMP loop 的 iteration variable 会被隐式设为 private。
    
- nested loop 的内层变量要特别小心，最好在 loop header 中声明。
    
- OpenMP loop 中不能随意 `break` 跳出。
    
- 不是所有 loop 都能并行，有 loop-carried dependency 的循环不能直接并行。
    
- nested parallelism 虽然 OpenMP 3.0 后支持，但不代表应该随便使用。

# 16. 一句话记忆

```text
parallel 负责创建线程，for 负责分配循环；parallel for 则是最常见的“创建线程并并行执行循环”的写法。
```

```text
OpenMP loop 适合 iterations 独立、边界清晰、没有 break、没有 loop-carried dependency 的循环。
```
