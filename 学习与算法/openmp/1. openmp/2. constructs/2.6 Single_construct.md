# OpenMP Single Construct

## 1. 本节核心总结

`single construct` 用于在一个 `parallel region` 中指定：**某一段代码只由一个线程执行一次**。  
它常用于只需要一个线程完成的工作，例如初始化、读入数据、打印信息、分配资源等。

简单理解：

| Construct | 核心作用 | 谁来执行 |
|---|---|---|
| `for / do` | 循环迭代并行 | 多个线程分工执行 |
| `sections` | 多个代码块并行 | 不同线程执行不同 section |
| `single` | 某段代码只执行一次 | parallel team 中任意一个线程 |

一句话记忆：

> `single` 表示“这段代码只让一个线程做，但不指定是哪一个线程”。

---

## 2. Single Construct 是什么？

`single construct` 是 OpenMP 中用于**单线程执行代码块**的结构。

它必须出现在 `parallel region` 中，用来告诉 OpenMP：

```text
虽然现在有多个线程，但下面这段代码只需要一个线程执行一次。
````

典型场景：

|场景|为什么适合 single|
|---|---|
|打印一条提示信息|不希望每个线程都重复打印|
|读取输入文件|通常只需要读一次|
|初始化共享数据结构|避免多个线程重复初始化|
|创建任务 `task`|常见于 task-based parallelism|
|分配共享资源|避免重复分配或冲突|

---

## 3. 基本语法结构

### 3.1 C / C++ 写法

```c
#pragma omp parallel
{
    // 多个线程都会执行这里

    #pragma omp single
    {
        // 只有一个线程会执行这里
        initialise_data();
    }

    // 默认情况下，所有线程会在 single 结束处同步
}
```

执行逻辑：

1. `parallel` 创建多个线程。
    
2. 每个线程都会进入 parallel region。
    
3. 遇到 `single` 时，只有一个线程执行 single block。
    
4. 其他线程跳过这个 block。
    
5. 默认情况下，所有线程在 single 结束处等待。
    

---

## 4. 哪个线程执行 single？

课本强调：

> There is no guarantee about which thread will be used.

也就是说，OpenMP 不保证具体由哪个线程执行 `single`。

例如：

```c
#pragma omp parallel
{
    #pragma omp single
    {
        printf("This is executed by one thread only.\n");
    }
}
```

可能是 thread 0 执行，也可能是 thread 2、thread 5 等其他线程执行。

因此：

|情况|是否适合 single|
|---|---|
|只关心代码执行一次|适合|
|必须由 master thread / thread 0 执行|不适合，应该考虑 `master` 或其他机制|
|不在乎哪个线程执行初始化|适合|
|需要某个固定线程执行 I/O|不适合直接依赖 `single`|

一句话：

> `single` 保证“只执行一次”，但不保证“谁来执行”。

---

## 5. Implicit Barrier：默认同步

`single construct` 结束时默认有一个 `implicit barrier`。

也就是说：

```c
#pragma omp parallel
{
    #pragma omp single
    {
        initialise_data();
    }

    use_data();
}
```

这里默认保证：

1. 某一个线程执行完 `initialise_data()`。
    
2. 其他线程在 `single` 结束处等待。
    
3. 所有线程确认初始化完成后，才继续执行 `use_data()`。
    

所以这种情况是安全的：

```c
#pragma omp parallel
{
    #pragma omp single
    {
        shared_array = malloc(sizeof(double) * N);
        initialise_array(shared_array);
    }

    // 默认 barrier 后，所有线程都可以安全使用 shared_array
    do_work(shared_array);
}
```

---

## 6. `nowait` Clause

如果不希望线程在 `single` 结束处等待，可以使用 `nowait`。

```c
#pragma omp parallel
{
    #pragma omp single nowait
    {
        print_message();
    }

    independent_work();
}
```

含义：

1. 某一个线程执行 `print_message()`。
    
2. 其他线程不等待它完成。
    
3. 线程可以直接继续执行 `independent_work()`。
    

适合使用 `nowait` 的情况：

|情况|是否适合 `nowait`|
|---|---|
|后续代码依赖 single 中产生的数据|不适合|
|后续代码与 single block 无关|适合|
|想减少不必要的等待|适合|
|需要保证初始化完成后再继续|不适合|

错误示例：

```c
#pragma omp parallel
{
    #pragma omp single nowait
    {
        initialise_data();
    }

    // 危险：可能有线程在 initialise_data() 完成前就使用数据
    use_data();
}
```

如果 `use_data()` 依赖 `initialise_data()`，就不能使用 `nowait`。

## 7. Single Construct 可用 Clauses

课本列出的 clauses：

|Clause|作用|
|---|---|
|`private(list)`|single block 内变量对执行线程是私有的|
|`firstprivate(list)`|私有变量会用进入 single 前的值初始化|
|`copyprivate(list)`|把 single 中的私有变量值广播给其他线程|
|`nowait`|取消 single 结束处的隐式同步|

其中最重要的是：

- `nowait`
    
- `copyprivate`
    

---

## 8. `copyprivate` Clause

`copyprivate` 用于把执行 `single` 的线程中的某些私有变量值，复制给 parallel team 中其他线程对应的私有变量。

课本解释：

> The copyprivate clause lists variables that are to be broadcast to all of the threads as private variables when execution of the single region completes.

简单理解：

> `copyprivate` 就是 single 线程算出一个结果，然后把这个结果广播给所有线程。

---

## 9. 为什么需要 `copyprivate`？

假设只有一个线程读取输入值，然后其他线程都要使用这个值。

概念上类似这样：

```c
int x;

#pragma omp parallel private(x)
{
    #pragma omp single copyprivate(x)
    {
        x = read_input();
    }

    // 所有线程现在都有自己的 private x，并且值相同
    use_value(x);
}
```

这里的关键是：

1. `x` 是每个线程的 private variable。
    
2. 只有执行 single 的线程给自己的 `x` 赋值。
    
3. `copyprivate(x)` 会把这个值复制给其他线程的 private `x`。
    
4. single 结束处的 implicit barrier 保证复制完成后，所有线程再继续。
    

---

## 10. `copyprivate` 和 `nowait` 不能同时使用

课本强调：

> If the copyprivate clause is used, the nowait clause cannot be.

原因是：

`copyprivate` 需要在 `single` 结束时把变量值广播给其他线程。  
这个广播动作依赖 `implicit barrier`。

如果使用 `nowait`，线程不会在这里同步，那么就无法保证所有线程都正确接收到 `copyprivate` 的值。

所以：

```c
#pragma omp single copyprivate(x) nowait
```

这是不允许的。

记忆方式：

|Clause|是否需要 barrier|
|---|---|
|`copyprivate`|需要|
|`nowait`|取消 barrier|

所以它们互相冲突。

## 11. Fortran 中的写法

课本给出的 Fortran 结构：

```fortran
!$OMP PARALLEL [clause[,clause]]
    ...
!$OMP SINGLE [clause[,clause]]
    ...
!$OMP END SINGLE [NOWAIT]
    ...
!$OMP END PARALLEL
```

Fortran 中有一个特殊点：

> `nowait` 写在 `END SINGLE` 上，而不是写在 `SINGLE` 上。

例如：

```fortran
!$OMP SINGLE
    ! only one thread executes this block
!$OMP END SINGLE NOWAIT
```

另外，课本还说明：

> In Fortran, the copyprivate clause, like the nowait clause, appears on the END SINGLE construct.

也就是说，Fortran 中 `copyprivate` 也写在 `END SINGLE` 上：

```fortran
!$OMP SINGLE
    x = input_value
!$OMP END SINGLE COPYPRIVATE(x)
```

## 12. Single vs Master

虽然这节课本主要讲 `single`，但可以顺便区分一下 `single` 和 `master`。

|Construct|谁执行|是否默认 barrier|
|---|---|---|
|`single`|任意一个线程|有 implicit barrier|
|`master`|只有 master thread / thread 0|没有 implicit barrier|

简单区别：

```text
single: 只执行一次，但不指定哪个线程
master: 只由主线程执行
```

如果你只关心“执行一次”，用 `single`。  
如果你必须让 thread 0 执行，用 `master`。

---

## 13. Single vs Critical

`single` 和 `critical` 也容易混淆。

|Construct|作用|执行次数|
|---|---|---|
|`single`|只允许一个线程执行整个代码块|只执行一次|
|`critical`|多个线程都可能进入，但一次只能一个线程进入|可能执行多次|

例子：

```c
#pragma omp parallel
{
    #pragma omp single
    {
        printf("Only once\n");
    }
}
```

输出一次。

```c
#pragma omp parallel
{
    #pragma omp critical
    {
        printf("One at a time\n");
    }
}
```

每个线程都会执行一次，只是不会同时打印。

一句话：

> `single` 控制“执行次数”，`critical` 控制“互斥访问”。

---

## 14. 实际例子：只读一次文件

假设多个线程都需要使用同一份配置文件，但文件只需要读取一次：

```c
#pragma omp parallel
{
    #pragma omp single
    {
        read_config_file();
        initialise_shared_data();
    }

    // 默认 barrier 后，所有线程都可以安全使用配置
    compute_using_config();
}
```

这里使用 `single` 很合适，因为：

1. 读取配置只需要执行一次。
    
2. 初始化共享数据也只需要执行一次。
    
3. 默认 barrier 保证所有线程在计算前都能看到初始化后的数据。
    

---

## 15. 实际例子：打印信息避免重复输出

如果不用 `single`：

```c
#pragma omp parallel
{
    printf("Starting computation...\n");
}
```

假设有 8 个线程，可能会打印 8 次。

使用 `single`：

```c
#pragma omp parallel
{
    #pragma omp single
    {
        printf("Starting computation...\n");
    }

    compute();
}
```

这样只会打印一次。

## 16. 常见易错点

### 16.1 误以为 single 一定由 thread 0 执行

错误理解：

```text
single block 一定由主线程执行。
```

正确理解：

```text
single block 由 parallel team 中任意一个线程执行。
```

如果必须 thread 0 执行，不要依赖 `single`。

---

### 16.2 忘记 single 末尾默认有 barrier

默认情况下：

```c
#pragma omp single
{
    work();
}
```

结束时会有同步等待。

如果不需要等待，可以加：

```c
#pragma omp single nowait
{
    work();
}
```

---

### 16.3 在依赖初始化结果时错误使用 nowait

危险写法：

```c
#pragma omp parallel
{
    #pragma omp single nowait
    {
        initialise_data();
    }

    use_data();
}
```

如果 `use_data()` 依赖 `initialise_data()`，可能出现 race condition。

---

### 16.4 同时使用 copyprivate 和 nowait

错误：

```c
#pragma omp single copyprivate(x) nowait
```

原因：

`copyprivate` 需要 barrier 来完成广播，`nowait` 会取消 barrier。

---

## 17. 和前面 Constructs 的对比总结

|Construct|主要用途|是否要求 parallel region|默认是否有 barrier|
|---|---|---|---|
|`for / do`|分配 loop iterations|是|是|
|`sections`|分配多个独立代码块|是|是|
|`single`|只让一个线程执行某段代码|是|是|
|`master`|只让主线程执行某段代码|是|否|
|`critical`|保护互斥访问|是|否，不是 barrier|

---

## 18. 本节一句话总结

`single construct` 用于在一个 `parallel region` 中让某段代码只执行一次，但不保证由哪个线程执行；它默认在结束处有 `implicit barrier`，可以用 `nowait` 取消同步，而 `copyprivate` 可以把 single 线程中的私有变量值广播给其他线程，但不能和 `nowait` 同时使用。
