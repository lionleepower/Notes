# OpenMP Workshare Construct

## 1. 本节核心总结

`workshare construct` 是 OpenMP 中专门用于 **Fortran 程序** 的并行结构。  
它主要配合 **Fortran 90 array syntax** 使用，让编译器把数组运算背后隐藏的循环自动分配给多个线程执行。

简单理解：

| Construct | 适用语言 | 核心用途 |
|---|---|---|
| `for / do` | C/C++ / Fortran | 显式循环并行 |
| `sections` | C/C++ / Fortran | 多个代码块并行 |
| `single` | C/C++ / Fortran | 某段代码只执行一次 |
| `workshare` | Fortran only | 并行化 Fortran 数组语法背后的隐式循环 |

一句话记忆：

> `workshare` 是 Fortran 专用的“数组语法并行化”结构，用来把 whole-array operations 自动分配给多个线程。

---

## 2. Workshare Construct 是什么？

`workshare construct` 可以出现在 Fortran 的 `parallel region` 中。

它的目标是处理 Fortran 90 中这种数组整体操作：

```fortran
A = B + C
````

这行代码表面上不是一个显式循环，但实际含义类似：

```fortran
do i = 1, N
    A(i) = B(i) + C(i)
end do
```

因此，`workshare` 允许编译器把这种隐含的数组操作并行化。

核心思想：

|概念|含义|
|---|---|
|`workshare`|把 Fortran 数组语句中的工作分给多个线程|
|`array syntax`|Fortran 90 中对整个数组进行操作的语法|
|`whole-array operation`|对整个数组一次性赋值或计算|
|`unit of work`|编译器划分出的工作单元|
|`serial equivalence`|并行执行结果必须和串行执行结果一致|

---

## 3. 重要限制：C/C++ 没有等价功能

课本明确说：

> There is no equivalent functionality for C/C++.

也就是说，`workshare` 是 Fortran 专用的 OpenMP construct。

在 C/C++ 中，如果想并行数组操作，一般需要显式写循环：

```c
#pragma omp parallel for
for (int i = 0; i < N; i++) {
    A[i] = B[i] + C[i];
}
```

而在 Fortran 中，可以通过 `workshare` 处理类似：

```fortran
!$OMP WORKSHARE
A = B + C
!$OMP END WORKSHARE
```

---

## 4. 基本语法结构

课本给出的 Fortran 结构：

```fortran
!$OMP PARALLEL [clause[,clause]]
    ...
!$OMP WORKSHARE
    ...
!$OMP END WORKSHARE
    ...
!$OMP END PARALLEL
```

注意：

|部分|说明|
|---|---|
|`WORKSHARE`|开始 workshare region|
|`END WORKSHARE`|结束 workshare region|
|clauses|`WORKSHARE` directive 本身不带 clauses|
|`parallel region`|`workshare` 必须出现在并行区域中|

---

## 5. Workshare Directive 不带 Clauses

课本强调：

> The workshare directive begins with the OpenMP sentinel and takes no clauses.

也就是说：

```fortran
!$OMP WORKSHARE
```

后面不能像 `for`、`sections`、`single` 那样加很多 clauses。

例如下面这种写法不符合该描述：

```fortran
!$OMP WORKSHARE private(x)
```

`workshare` 本身不带 clauses。

不过，`END WORKSHARE` 可以带 `nowait`：

```fortran
!$OMP END WORKSHARE NOWAIT
```

---

## 6. Workshare Region 中可以出现什么？

课本列出，`workshare region` 中只能出现以下内容：

|允许出现的内容|中文解释|
|---|---|
|`array assignments`|数组赋值|
|`scalar assignments`|标量赋值|
|`FORALL statements and constructs`|Fortran 的 `FORALL` 语句或结构|
|`WHERE statements and constructs`|Fortran 的条件数组赋值结构|
|`atomic constructs`|OpenMP 原子操作|
|`critical constructs`|OpenMP 临界区|
|`parallel constructs`|OpenMP 并行结构|

简单记忆：

> `workshare` 主要允许“数组/标量赋值 + Fortran 数组控制结构 + 少量 OpenMP 同步结构”。

---

## 7. Array Assignment：数组赋值

这是 `workshare` 最典型的使用场景。

例如：

```fortran
!$OMP PARALLEL
!$OMP WORKSHARE
    A = B + C
!$OMP END WORKSHARE
!$OMP END PARALLEL
```

其中：

```fortran
A = B + C
```

代表对整个数组执行逐元素操作：

```fortran
A(i) = B(i) + C(i)
```

编译器可以把不同元素的计算分给不同线程。

---

## 8. Scalar Assignment：标量赋值

`workshare region` 中也允许标量赋值。

例如：

```fortran
!$OMP WORKSHARE
    x = 10
!$OMP END WORKSHARE
```

但是要注意，标量赋值本身通常没有什么并行价值。  
它存在的意义更多是允许在 workshare block 中保留必要的普通赋值语句。

---

## 9. WHERE Construct

Fortran 的 `WHERE` 可以对数组中满足条件的元素赋值。

例如：

```fortran
WHERE (A > 0)
    B = SQRT(A)
ELSEWHERE
    B = 0
END WHERE
```

这表示：

|条件|操作|
|---|---|
|`A(i) > 0`|`B(i) = SQRT(A(i))`|
|`A(i) <= 0`|`B(i) = 0`|

放入 `workshare` 中：

```fortran
!$OMP PARALLEL
!$OMP WORKSHARE
    WHERE (A > 0)
        B = SQRT(A)
    ELSEWHERE
        B = 0
    END WHERE
!$OMP END WORKSHARE
!$OMP END PARALLEL
```

这类操作很适合并行，因为每个数组元素通常可以独立处理。

---

## 10. FORALL Statement / Construct

`FORALL` 是 Fortran 中表达数组并行赋值的一种结构。

例如：

```fortran
FORALL (i = 1:N)
    A(i) = B(i) + C(i)
END FORALL
```

它也可以出现在 `workshare region` 中。

```fortran
!$OMP PARALLEL
!$OMP WORKSHARE
    FORALL (i = 1:N)
        A(i) = B(i) + C(i)
    END FORALL
!$OMP END WORKSHARE
!$OMP END PARALLEL
```

不过在现代 Fortran 中，很多场景可以直接使用数组语法表达。

---

## 11. Serial Equivalence：结果必须和串行一致

课本强调：

> The result of executing a workshare region in OpenMP must be the same as they would be in a serial context.

也就是说，`workshare` 虽然会并行执行，但结果必须看起来像串行代码执行出来的一样。

这非常重要，因为数组语法可能存在语句之间的依赖关系。

例如：

```fortran
!$OMP WORKSHARE
    A = B + C
    D = A + 1
!$OMP END WORKSHARE
```

这里 `D = A + 1` 依赖上一句 `A = B + C` 的结果。

所以 OpenMP / 编译器必须保证：

1. 第一条语句的效果完成后；
    
2. 第二条语句才能基于正确的 `A` 计算；
    
3. 最终结果和串行执行一致。
    

---

## 12. Workshare 如何分配工作？

课本说，`workshare region` 中的语句会被分成多个 `units of work`，然后分配给绑定的 parallel region 中的线程。

可以理解为：

```text
Fortran array syntax
        ↓
compiler identifies hidden work
        ↓
split into units of work
        ↓
assign units to threads
        ↓
synchronize when dependencies require
```

例如：

```fortran
A = B + C
```

可能会被看成：

```text
A(1:250)     -> thread 0
A(251:500)   -> thread 1
A(501:750)   -> thread 2
A(751:1000)  -> thread 3
```

不过具体如何划分由编译器和 OpenMP runtime 决定。

---

## 13. RHS 必须先完成再进行 LHS 赋值

课本中有一句比较重要：

> The evaluation of the right-hand side of an assignment must appear to be complete before assignments are made on the left-hand side.

意思是：

赋值语句右边 `right-hand side, RHS` 的计算，必须表现得像是在左边 `left-hand side, LHS` 被赋值之前已经完成。

例如：

```fortran
A = A + 1
```

逻辑上应该是：

1. 先读取旧的 `A`
    
2. 计算 `A + 1`
    
3. 再写回新的 `A`
    

对于更复杂的数组赋值：

```fortran
A(2:N) = A(1:N-1)
```

并行执行时必须非常小心，因为 RHS 和 LHS 都涉及 `A`，存在重叠。

OpenMP 必须保证执行效果等价于串行语义，而不是让线程随意读写导致错误结果。

---

## 14. User-defined Function 的限制：必须是 ELEMENTAL

课本指出：

> If any user-defined functions are found in the workshare region, they must be ELEMENTAL.

也就是说，如果在 `workshare region` 中调用用户自定义函数，这个函数必须是 `ELEMENTAL`。

### 14.1 什么是 ELEMENTAL function？

Fortran 中的 `ELEMENTAL` 函数表示：

> 这个函数可以逐元素地应用到数组的每个元素上。

例如概念上：

```fortran
ELEMENTAL FUNCTION square(x)
    square = x * x
END FUNCTION
```

这样就可以写：

```fortran
A = square(B)
```

含义是：

```fortran
A(i) = square(B(i))
```

每个元素可以相对独立计算，因此适合 `workshare` 分配为不同工作单元。

### 14.2 为什么必须是 ELEMENTAL？

因为 `workshare` 可能把函数调用分给不同线程执行。

如果函数不是 `ELEMENTAL`，它可能：

- 修改共享状态
    
- 有副作用
    
- 依赖调用顺序
    
- 不适合逐元素并行执行
    

这会破坏 serial equivalence。

---

## 15. Implicit Barrier 和 nowait

`workshare construct` 结束时默认有一个 `implicit barrier`。

也就是说：

```fortran
!$OMP PARALLEL
!$OMP WORKSHARE
    A = B + C
!$OMP END WORKSHARE

    ! 默认情况下，所有线程确认 workshare 完成后才继续
    call use_array(A)

!$OMP END PARALLEL
```

如果后面的代码不依赖 `workshare` 的完成，可以在 `END WORKSHARE` 上使用 `NOWAIT`：

```fortran
!$OMP END WORKSHARE NOWAIT
```

注意：

> Fortran 中 `nowait` 写在 `END WORKSHARE` 上。

适合使用 `NOWAIT` 的情况：

|情况|是否适合 NOWAIT|
|---|---|
|后续代码依赖数组计算结果|不适合|
|后续代码完全独立|适合|
|需要保证所有 workshare 工作完成|不适合|
|想减少不必要同步开销|适合|

## 16. Workshare 的一个完整例子

```fortran
program workshare_example
    use omp_lib
    implicit none

    integer, parameter :: N = 1000
    real :: A(N), B(N), C(N), D(N)

    B = 1.0
    C = 2.0

!$OMP PARALLEL
!$OMP WORKSHARE
    A = B + C
    D = A * 2.0
!$OMP END WORKSHARE
!$OMP END PARALLEL

end program workshare_example
```

含义：

1. `A = B + C` 对整个数组做逐元素加法。
    
2. `D = A * 2.0` 对整个数组做逐元素乘法。
    
3. `workshare` 允许这些数组操作背后的工作被多个线程分担。
    
4. 同时必须保证 `D = A * 2.0` 使用的是已经更新后的 `A`。

## 17. Workshare vs DO Construct

Fortran 中也可以使用 `do` construct 显式并行循环。

### 使用 `workshare`

```fortran
!$OMP PARALLEL
!$OMP WORKSHARE
    A = B + C
!$OMP END WORKSHARE
!$OMP END PARALLEL
```

### 使用 `do`

```fortran
!$OMP PARALLEL DO
do i = 1, N
    A(i) = B(i) + C(i)
end do
!$OMP END PARALLEL DO
```

对比：

|方面|`workshare`|`do`|
|---|---|---|
|代码风格|更接近 Fortran 数组语法|显式循环|
|适用场景|whole-array operations|loop iterations|
|可控性|较低，依赖编译器|较高，可以控制 schedule 等|
|C/C++ 是否支持|不支持|C/C++ 有对应 `for`|
|可读性|对数组操作很简洁|对循环逻辑更明确|

简单理解：

> `workshare` 更像“让编译器帮我并行化数组语法”；`do` 更像“我明确告诉 OpenMP 这个循环怎么并行”。

---

## 18. Workshare 的优点与局限

### 18.1 优点

|优点|说明|
|---|---|
|代码简洁|直接使用 Fortran array syntax|
|表达清晰|很适合数组整体运算|
|潜在并行性明显|数组元素操作通常可以分配给多个线程|
|保持串行语义|OpenMP 要保证结果等价于串行执行|

### 18.2 局限

|局限|说明|
|---|---|
|Fortran only|C/C++ 没有对应 construct|
|依赖编译器优化|性能很大程度取决于编译器实现|
|可控性较弱|不像 `do` 那样能显式控制循环调度|
|允许语句有限|region 中只能出现特定类型语句|
|用户函数有限制|user-defined functions 必须是 `ELEMENTAL`|

---

## 19. 常见易错点

### 19.1 误以为 C/C++ 也能使用 workshare

错误理解：

```text
OpenMP workshare 在 C/C++ 和 Fortran 中都可以使用。
```

正确理解：

```text
workshare 是 Fortran-only construct。
```

C/C++ 中要用显式循环配合 `parallel for`。

---

### 19.2 忘记 workshare 本身不带 clauses

错误：

```fortran
!$OMP WORKSHARE NOWAIT
```

更符合课本描述的写法：

```fortran
!$OMP WORKSHARE
    ...
!$OMP END WORKSHARE NOWAIT
```

---

### 19.3 忽略 serial equivalence

不能认为 `workshare` 中的语句可以随便乱序执行。

例如：

```fortran
!$OMP WORKSHARE
    A = B + C
    D = A + 1
!$OMP END WORKSHARE
```

第二条语句依赖第一条语句，执行结果必须和串行一致。

---

### 19.4 在 workshare 中调用非 ELEMENTAL 用户函数

如果用户自定义函数出现在 `workshare region` 中，它必须是 `ELEMENTAL`。

否则可能不适合被分配为独立工作单元。

---

## 20. 与前面 Constructs 的对比总结

|Construct|适用语言|核心用途|默认 barrier|
|---|---|---|---|
|`for / do`|C/C++ / Fortran|显式循环并行|有|
|`sections`|C/C++ / Fortran|多个独立代码块并行|有|
|`single`|C/C++ / Fortran|某段代码只执行一次|有|
|`workshare`|Fortran only|Fortran 数组语法并行化|有|
|`master`|C/C++ / Fortran|只由主线程执行|无|

---

## 21. 本节一句话总结

`workshare construct` 是 Fortran 专用的 OpenMP 并行结构，主要用于把 Fortran 90 数组语法、`WHERE`、`FORALL` 等结构背后的工作自动分配给多个线程；它必须保持与串行执行相同的结果，用户自定义函数必须是 `ELEMENTAL`，并且默认在 `END WORKSHARE` 处有 `implicit barrier`，可以用 `NOWAIT` 取消。
