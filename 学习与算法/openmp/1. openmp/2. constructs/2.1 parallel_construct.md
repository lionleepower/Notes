# OpenMP Parallel Construct

## 1. 本节核心总结

`parallel construct` 是 OpenMP 多线程程序中最基础、最常见的 construct。  
当程序执行到 `#pragma omp parallel` 时，OpenMP 会创建一组 threads，这些 threads 共同组成一个 **team of threads**。  
在 `parallel region` 中，被包裹的代码会被每一个 thread 都执行一遍。  
单独使用 `parallel` 可能会导致重复执行，因此实际中常常和 `for`、`sections`、`single` 等 **worksharing constructs** 结合使用，让不同线程完成不同工作。

---

## 2. 快速对照表

| 概念 | 英文关键词 | 简单理解 |
|---|---|---|
| Construct | OpenMP construct | OpenMP 指令加上它影响的代码区域 |
| Directive | OpenMP directive | 以 `#pragma omp` 开头的编译器指令 |
| Region | Parallel region | 被 OpenMP directive 影响的一段代码 |
| Parallel construct | `#pragma omp parallel` | 创建多个线程并行执行代码 |
| Team of threads | thread team | 当前 parallel region 中参与执行的一组线程 |
| Worksharing construct | `for`, `sections`, `single` | 把工作分给不同线程，避免所有线程重复做同一件事 |
| Clause | OpenMP clause | 修饰 directive 行为的附加条件 |
| Runtime control variable | runtime control variable | OpenMP 运行时维护的控制变量 |

---

## 3. 什么是 OpenMP Construct？

OpenMP construct 由两部分组成：

```text
OpenMP construct = OpenMP directive + affected executable code region
````

在 C/C++ 中，一个 OpenMP directive 通常长这样：

```c
#pragma omp parallel
{
    // affected code region
}
```

其中：

- `#pragma omp parallel` 是 **OpenMP directive**
    
- `{ ... }` 中的代码是被它影响的 **parallel region**
    

也就是说，construct 不只是那一行 `#pragma`，还包括它控制的代码区域。

---

## 4. 什么是 Parallel Construct？

`parallel construct` 是 OpenMP 中用来创建多线程的基本结构。

基本形式：

```c
#pragma omp parallel
{
    // code executed by every thread
}
```

当程序执行到 `#pragma omp parallel` 时：

1. 原本的主线程，即 **initial thread**，遇到 parallel directive
    
2. OpenMP runtime 创建额外线程
    
3. 所有线程组成一个 **team of threads**
    
4. 每个线程都执行 parallel region 中的代码
    
5. 当 parallel region 结束后，线程团队结束
    
6. 程序回到单线程执行状态
    

可以理解为：

```text
Before parallel region:

Initial Thread

Inside parallel region:

Thread 0
Thread 1
Thread 2
Thread 3

After parallel region:

Initial Thread
```

---

## 5. Parallel Region 的边界

在 C/C++ 中，parallel region 通常由花括号 `{ ... }` 包围：

```c
#pragma omp parallel
{
    printf("Hello from a thread\n");
}
```

在 Fortran 中，则使用类似：

```fortran
!$OMP PARALLEL
    ...
!$OMP END PARALLEL
```

本课程内容主要看 C/C++ 时，需要重点记住：

> `{ ... }` 决定了 parallel region 的范围。

---

## 6. Parallel Region 中的代码会被每个线程执行

这是 `parallel construct` 最容易混淆的点。

例如：

```c
#pragma omp parallel
{
    printf("Hello\n");
}
```

如果 OpenMP 创建了 4 个线程，那么输出可能是：

```text
Hello
Hello
Hello
Hello
```

原因是：

> parallel region 中的代码会被当前 team 中的每一个 thread 都执行一遍。

这说明单独使用 `parallel` 并不会自动“分工”。  
它只是创建多个线程，并让每个线程执行同一段代码。

---

## 7. 为什么单独使用 parallel 可能会浪费？

如果每个线程都执行完全相同的计算，就可能造成重复工作。

例如：

```c
#pragma omp parallel
{
    expensive_computation();
}
```

如果有 8 个线程，这段函数可能会被执行 8 次。

这通常不是我们想要的效果。

因此，OpenMP 需要配合 **worksharing constructs** 使用，让不同线程分配到不同任务。

常见 worksharing constructs 包括：

|Worksharing construct|作用|
|---|---|
|`for` / `do`|把循环迭代分配给多个线程|
|`sections`|把不同代码块分给不同线程|
|`single`|只让一个线程执行某段代码|
|`workshare`|Fortran 中用于数组操作等工作共享|

最常见的组合是：

```c
#pragma omp parallel for
for (int i = 0; i < n; i++) {
    // loop iterations distributed among threads
}
```

这里的意思是：

> 创建线程，并把 for-loop 的不同迭代分配给不同线程执行。

---

## 8. Parallel Construct 的基本语法

### 单独使用 parallel

```c
#pragma omp parallel
{
    // every thread executes this block
}
```

### parallel 和 for 结合

```c
#pragma omp parallel for
for (int i = 0; i < 1000000; i++) {
    // loop iterations are divided among threads
}
```

这也是 OpenMP 中最常见的写法之一。

---

## 9. Parallel Construct 的控制变量

OpenMP runtime 维护一些控制变量，用于影响 `parallel construct` 的行为。

本节提到三个重要变量：

|Control variable|Environment variable|Runtime function|Query function|Default|
|---|---|---|---|---|
|`nthreads`|`OMP_NUM_THREADS`|`omp_set_num_threads()`|`omp_get_max_threads()`|vendor-defined|
|`dynamic`|`OMP_DYNAMIC`|`omp_set_dynamic()`|`omp_get_dynamic()`|vendor-defined|
|`nesting`|`OMP_NESTED`|`omp_set_nested()`|`omp_get_nested()`|`false`|

---

## 10. nthreads

`nthreads` 控制 OpenMP 默认想要使用的线程数量。

可以通过环境变量设置：

```bash
export OMP_NUM_THREADS=4
```

也可以在程序中设置：

```c
omp_set_num_threads(4);
```

查询方式：

```c
omp_get_max_threads();
```

注意：

```c
omp_get_max_threads()
```

查询的是当前 OpenMP runtime 预计会使用的最大线程数。

而：

```c
omp_get_num_threads()
```

返回的是当前 parallel region 中实际正在执行的线程数。

这两个函数不要混淆。

---

## 11. `omp_get_max_threads()` 和 `omp_get_num_threads()` 的区别

|函数|含义|使用位置|
|---|---|---|
|`omp_get_max_threads()`|返回下一次 parallel region 可能使用的最大线程数|parallel region 内外都可用|
|`omp_get_num_threads()`|返回当前 parallel region 中实际线程数|主要在 parallel region 内使用|

例子：

```c
#include <stdio.h>
#include <omp.h>

int main() {
    printf("Max threads = %d\n", omp_get_max_threads());

    #pragma omp parallel
    {
        printf("Number of threads = %d\n", omp_get_num_threads());
    }

    return 0;
}
```

如果设置：

```bash
export OMP_NUM_THREADS=4
```

可能输出：

```text
Max threads = 4
Number of threads = 4
Number of threads = 4
Number of threads = 4
Number of threads = 4
```

注意：`omp_get_num_threads()` 在 parallel region 中会被每个线程调用，所以可能打印多次。

---

## 12. dynamic

`dynamic` 控制 OpenMP runtime 是否可以动态调整线程数量。

可以通过环境变量设置：

```bash
export OMP_DYNAMIC=true
```

也可以在程序中设置：

```c
omp_set_dynamic(1);
```

查询方式：

```c
omp_get_dynamic();
```

==如果 dynamic 开启，OpenMP runtime 可能不会严格使用你指定的线程数，而是根据系统情况自动调整==。

例如你设置：

```bash
export OMP_NUM_THREADS=8
```

但如果 dynamic 开启，实际运行时可能只使用 4 个线程。

---

## 13. nesting

`nesting` 控制是否允许 nested parallelism，也就是嵌套并行。

所谓嵌套并行，是指在一个 parallel region 里面再开启另一个 parallel region。

例如：

```c
#pragma omp parallel
{
    #pragma omp parallel
    {
        // nested parallel region
    }
}
```

可以通过环境变量设置：

```bash
export OMP_NESTED=true
```

也可以在程序中设置：

```c
omp_set_nested(1);
```

查询方式：

```c
omp_get_nested();
```

默认情况下，`nesting` 通常是关闭的：

```text
nesting default = false
```

对于初学阶段，通常不建议一开始就使用 nested parallelism，因为它容易导致线程数量膨胀和性能问题。

---

## 14. Branching 规则：不能跳入或跳出 Parallel Region

OpenMP 要求 parallel region 中的线程需要正确协调。

因此：

> It is illegal to branch into or out of a parallel region.

也就是说，不能用某些跳转语句强行跳入或跳出 parallel region。

例如，不能从 parallel region 外部 `goto` 到 parallel region 内部，也不能从 parallel region 内部随意跳到外部。

原因是：

- parallel region 需要 OpenMP runtime 创建和管理线程
    
- 每个线程必须正确进入和退出 region
    
- 随意跳转会破坏线程同步和运行时状态
    

简单理解：

> parallel region 必须正常开始，也必须正常结束。

---

## 15. 如果线程在 Parallel Region 中异常终止

课本中提到：

> If a thread should happen to terminate in a parallel region, all the rest of the threads will be killed.

意思是：

如果某个线程在 parallel region 中终止，其他线程也会被终止。

这是因为 parallel region 中的线程属于同一个 team，OpenMP 需要保持它们的执行状态一致。

所以在 parallel region 中应避免：

- 非正常退出
    
- 随意终止线程
    
- 不受控制的程序中断
    
- 破坏同步结构

## 16. Clause 是什么？

OpenMP directive 后面可以跟一些修饰项，称为 **clauses**。

例如：

```c
#pragma omp parallel num_threads(4)
{
    // code
}
```

这里的：

```c
num_threads(4)
```

就是一个 clause。

它的作用是修改 parallel construct 的行为。

常见 parallel construct clauses 包括：

|Clause|作用|
|---|---|
|`num_threads(n)`|指定线程数量|
|`private(var)`|每个线程拥有变量的私有副本|
|`shared(var)`|多个线程共享同一个变量|
|`default(shared/none)`|设置变量默认共享规则|
|`reduction(op:var)`|对变量进行归约合并|

后续学习 OpenMP 时，clauses 会非常重要。

## 17. 示例 1：最简单的 parallel construct

```c
#include <stdio.h>
#include <omp.h>

int main() {
    #pragma omp parallel
    {
        printf("Hello from thread %d\n", omp_get_thread_num());
    }

    return 0;
}
```

可能输出：

```text
Hello from thread 0
Hello from thread 2
Hello from thread 1
Hello from thread 3
```

注意输出顺序不一定固定，因为多个线程是并行执行的。

---

## 18. 示例 2：指定线程数量

```c
#include <stdio.h>
#include <omp.h>

int main() {
    #pragma omp parallel num_threads(4)
    {
        int id = omp_get_thread_num();
        int nthreads = omp_get_num_threads();

        printf("Thread %d out of %d\n", id, nthreads);
    }

    return 0;
}
```

可能输出：

```text
Thread 0 out of 4
Thread 3 out of 4
Thread 1 out of 4
Thread 2 out of 4
```

其中：

- `omp_get_thread_num()` 返回当前线程编号
    
- `omp_get_num_threads()` 返回当前 parallel region 中线程总数
    

---

## 19. 示例 3：parallel for

```c
#pragma omp parallel for
for (int i = 0; i < 1000000; i++) {
    a[i] = b[i] + c[i];
}
```

这段代码中：

- OpenMP 创建一个 thread team
    
- for-loop 的不同迭代被分给不同线程
    
- 每个线程只处理一部分循环
    
- 避免了所有线程重复执行完整循环
    

可以理解为：

```text
Thread 0: i = 0 ... 249999
Thread 1: i = 250000 ... 499999
Thread 2: i = 500000 ... 749999
Thread 3: i = 750000 ... 999999
```

实际分配方式还取决于 `schedule` 设置。

## 20. 常见误区

### 误区 1：以为 parallel 会自动分工

错误理解：

```text
#pragma omp parallel 会自动把任务分成几份
```

正确理解：

```text
#pragma omp parallel 只是创建多个线程，让每个线程执行同一段代码。
真正的分工通常需要 for、sections、single 等 worksharing constructs。
```

---

### 误区 2：以为 `omp_get_num_threads()` 在任何地方都返回多线程数量

例如：

```c
printf("%d\n", omp_get_num_threads());
```

如果这行代码在 parallel region 外面，通常会输出：

```text
1
```

因为当前只有一个线程在执行。

要查询可能使用的最大线程数，应使用：

```c
omp_get_max_threads();
```

---

### 误区 3：线程输出顺序应该固定

多线程程序中，线程执行顺序通常不可预测。

例如：

```c
#pragma omp parallel
{
    printf("Hello from thread %d\n", omp_get_thread_num());
}
```

输出可能是：

```text
Hello from thread 2
Hello from thread 0
Hello from thread 3
Hello from thread 1
```

也可能是其他顺序。

这是正常现象。

---

### 误区 4：线程数一定等于 `OMP_NUM_THREADS`

不一定。

原因包括：

- `OMP_DYNAMIC` 可能开启
    
- 系统资源不足
    
- OpenMP runtime 实现差异
    
- nested parallelism 限制
    
- 运行环境或调度器限制
    

因此，真实线程数最好在 parallel region 内用：

```c
omp_get_num_threads()
```

检查。

## 21. 本节重点

- `parallel construct` 是 OpenMP 多线程的基础。
    
- OpenMP construct = directive + affected code region。
    
- `#pragma omp parallel` 会创建一个 thread team。
    
- parallel region 中的代码会被每个 thread 执行。
    
- 单独使用 `parallel` 可能造成重复工作。
    
- 实际中常与 `for`、`sections`、`single` 等 worksharing constructs 结合。
    
- `OMP_NUM_THREADS`、`OMP_DYNAMIC`、`OMP_NESTED` 可以影响 parallel construct 的行为。
    
- `omp_get_max_threads()` 和 `omp_get_num_threads()` 含义不同。
    
- 不能非法跳入或跳出 parallel region。
