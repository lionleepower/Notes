# OpenMP Sections Construct

## 1. 本节核心总结

`sections construct` 用来处理**非循环型并行任务**。  
如果任务不是 `for loop` 那种重复迭代，而是几个彼此独立的代码块，就可以用 `sections` 把不同代码块分配给不同线程执行。

简单理解：

| Construct | 适合的并行类型 | 典型场景 |
|---|---|---|
| `for / do` | 循环迭代并行 | 把一个 loop 的不同 iterations 分给线程 |
| `sections` | 任务块并行 | 把几个不同 code blocks 分给线程 |
| `parallel sections` | 创建并行区并立即执行 sections | parallel region 和 sections region 范围相同时使用 |

一句话记忆：

> `for` 是“同一类工作分很多份”，`sections` 是“几件不同的工作分给不同线程”。

---

## 2. Sections Construct 是什么？

`sections construct` 是 OpenMP 中用于**任务分块并行**的一种结构。

它适合这种情况：

```c
task_A();
task_B();
task_C();
````

这三个任务不是循环的一部分，但它们互相独立，可以同时执行。  
这时就可以把它们写成多个 `section`，让 OpenMP 尝试把它们分配给不同线程。

核心思想：

|关键词|含义|
|---|---|
|`sections`|表示接下来有一组可并行执行的代码块|
|`section`|表示其中一个具体的代码块|
|`parallel region`|`sections` 必须出现在并行区域中|
|`implicit barrier`|`sections` 结束时默认有同步屏障|
|`nowait`|取消结尾默认同步|

---

## 3. 基本语法结构

### 3.1 C / C++ 写法

```c
#pragma omp parallel
{
    #pragma omp sections
    {
        #pragma omp section
        {
            // task 1
        }

        #pragma omp section
        {
            // task 2
        }

        #pragma omp section
        {
            // task 3
        }
    }
}
```

含义：

1. `parallel` 创建多个线程。
    
2. `sections` 表示下面有多个可以并行执行的任务块。
    
3. 每个 `section` 是一个独立任务。
    
4. OpenMP 会把这些 `section` 分配给线程执行。
    
5. 默认情况下，所有线程会在 `sections` 结束处等待。
    

---

## 4. `sections` 和 `section` 的区别

这两个词很容易混淆。

|Directive|中文理解|是否可以带 clauses|
|---|---|---|
|`sections`|一组任务块的开始|可以|
|`section`|单个任务块的开始|不可以|

也就是说：

```c
#pragma omp sections
```

表示“这里开始是一组任务”。

```c
#pragma omp section
```

表示“这是其中一个具体任务”。

注意：

> `section` 是 singular，表示单个任务块；`sections` 是 plural，表示整组任务块。

---

## 5. `sections` 必须在 parallel region 中

课本强调：

> A complete sections construct must occur in a parallel region.

也就是说，下面这种结构是标准用法：

```c
#pragma omp parallel
{
    #pragma omp sections
    {
        #pragma omp section
        {
            // task A
        }

        #pragma omp section
        {
            // task B
        }
    }
}
```

如果 `sections` 外面没有 `parallel`，就没有多个线程来执行这些任务，无法真正并行。

---

## 6. `parallel sections` 简写形式

如果 `parallel region` 和 `sections region` 范围完全一样，可以合并为：

```c
#pragma omp parallel sections
{
    #pragma omp section
    {
        // task A
    }

    #pragma omp section
    {
        // task B
    }
}
```

这等价于：

```c
#pragma omp parallel
{
    #pragma omp sections
    {
        #pragma omp section
        {
            // task A
        }

        #pragma omp section
        {
            // task B
        }
    }
}
```

区别只是写法更简洁。

---

## 7. 隐式屏障：Implicit Barrier

`sections` 结束时默认有一个 `implicit barrier`。

也就是说，所有线程必须等到全部 `section` 都执行完，才能继续往下走。

示例：

```c
#pragma omp parallel
{
    #pragma omp sections
    {
        #pragma omp section
        {
            task_A();
        }

        #pragma omp section
        {
            task_B();
        }
    }

    // 所有 sections 都完成后，线程才会执行这里
    after_sections();
}
```

如果 `task_A()` 很快完成，但 `task_B()` 很慢，那么执行 `task_A()` 的线程也要在 `sections` 末尾等待。

---

## 8. `nowait` Clause

如果不希望线程在 `sections` 结束处等待，可以使用 `nowait`。

```c
#pragma omp parallel
{
    #pragma omp sections nowait
    {
        #pragma omp section
        {
            task_A();
        }

        #pragma omp section
        {
            task_B();
        }
    }

    // 完成自己 section 的线程可以直接继续执行这里
    independent_work();
}
```

适合使用 `nowait` 的情况：

|情况|是否适合 `nowait`|
|---|---|
|后续代码依赖所有 section 的结果|不适合|
|后续代码与其他 section 无关|适合|
|需要保证所有任务完成后再继续|不适合|
|想减少不必要的等待|适合|

一句话：

> 如果后面的代码不依赖全部 sections 的完成，可以考虑 `nowait`。

---

## 9. `sections` 可用 clauses

课本列出的 clauses：

|Clause|作用|
|---|---|
|`private(list)`|每个线程拥有变量的私有副本|
|`firstprivate(list)`|私有副本会用进入并行区前的值初始化|
|`lastprivate(list)`|保存最后一个执行的 section 对变量的结果|
|`reduction(operator:list)`|对多个线程的结果做归约操作|
|`nowait`|去掉结尾的隐式同步屏障|

注意：

`section` 本身不能带 clauses。  
只有 `sections` 可以带 clauses。

错误理解：

```c
#pragma omp section private(x)   // 错误
```

正确写法：

```c
#pragma omp sections private(x)
```

## 10. Fortran 中的特殊点

Fortran 写法大致如下：

```fortran
!$OMP PARALLEL
!$OMP SECTIONS

!$OMP SECTION
    ! task 1

!$OMP SECTION
    ! task 2

!$OMP END SECTIONS

!$OMP END PARALLEL
```

Fortran 中有一个特殊点：

> 如果要使用 `nowait`，它不是写在 `SECTIONS` 上，而是写在 `END SECTIONS` 上。

例如：

```fortran
!$OMP END SECTIONS nowait
```

而不是：

```fortran
!$OMP SECTIONS nowait
```

## 11. Nested Parallel Regions 中的绑定规则

课本最后一句：

> If the sections construct appears in nested parallel regions, it will bind to the threads of the innermost enclosing region.

意思是：

如果 `sections` 出现在嵌套并行区域中，它会绑定到**最内层的 parallel region**。

简单例子：

```c
#pragma omp parallel
{
    // outer parallel region

    #pragma omp parallel
    {
        // inner parallel region

        #pragma omp sections
        {
            #pragma omp section
            {
                task_A();
            }

            #pragma omp section
            {
                task_B();
            }
        }
    }
}
```

这里的 `sections` 会由最里面那个 `parallel` 区域的线程执行，而不是外层的线程。

记忆方式：

> OpenMP construct 通常绑定到离它最近的 enclosing parallel region。

## 12. 一个实际例子

假设一个程序需要做三件互不依赖的事情：

1. 读取文件
    
2. 初始化数据结构
    
3. 预处理参数
    

可以写成：

```c
#pragma omp parallel sections
{
    #pragma omp section
    {
        read_file();
    }

    #pragma omp section
    {
        initialise_data();
    }

    #pragma omp section
    {
        preprocess_parameters();
    }
}
```

如果有 3 个或更多线程，这三个任务可能同时执行。

但是要注意：

> `sections` 的并行度受 section 数量限制。

如果只有 3 个 `section`，即使有 16 个线程，最多也只有 3 个线程能做有效工作，其他线程可能处于等待状态。

---

## 13. Sections Construct 的适用场景

适合：

|场景|原因|
|---|---|
|多个独立函数可以并行执行|每个函数可以放进一个 `section`|
|初始化阶段有多个独立任务|减少总初始化时间|
|不规则任务并行|不适合用 loop 时可以用 sections|
|小规模 task parallelism|写法简单直接|

不太适合：

|场景|原因|
|---|---|
|大量相似重复任务|应该用 `for` / `do`|
|section 数量远小于线程数|很多线程会闲置|
|任务之间依赖复杂|容易出现同步和数据竞争问题|
|动态任务数量很多|更适合 OpenMP `task` construct|

---

## 14. Sections vs For vs Task

|Construct|主要用途|工作数量|调度特点|
|---|---|---|---|
|`for`|循环并行|通常很多 iterations|OpenMP 分配 loop iterations|
|`sections`|固定数量代码块并行|通常较少 sections|每个 section 执行一次|
|`task`|动态任务并行|可多可少，运行时生成|更灵活，适合递归或不规则任务|

简单理解：

```text
for       -> parallel loop
sections  -> parallel code blocks
task      -> dynamic task parallelism
```

## 15. 常见易错点

### 15.1 误以为 `sections` 会自动创建线程

错误理解：

```c
#pragma omp sections
{
    ...
}
```

`sections` 本身不创建线程。  
它必须在 `parallel` 区域中，或者使用 `parallel sections`。

---

### 15.2 混淆 `sections` 和 `section`

`sections` 是整体结构。  
`section` 是其中一个任务块。

---

### 15.3 忘记默认 barrier

默认情况下，`sections` 结束时有同步屏障。

如果后续代码不需要等待全部任务完成，可以使用：

```c
#pragma omp sections nowait
```

---

### 15.4 线程数多不一定更快

如果只有两个 section：

```c
#pragma omp parallel sections num_threads(8)
{
    #pragma omp section
    task_A();

    #pragma omp section
    task_B();
}
```

最多只有两个线程真正工作，其余线程可能没有任务可做。

所以 `sections` 的并行度通常受限于 section 数量。

---

## 16. 本节一句话总结

`sections construct` 用于把几个独立的代码块分配给不同线程执行，适合非循环型并行任务；它必须位于 `parallel region` 中，默认在结束时有 `implicit barrier`，可以用 `nowait` 取消同步，但要确保后续代码不依赖所有 section 的结果。
