
# Linaro Forge MAP 实战笔记

## 一句话理解

`map` 是 Linaro Forge MAP 的命令行 profiling 工具。它负责启动程序、采样性能数据，并生成 `.map` 文件。

对于 MPI/OpenMP 程序，最重要的是分清三层参数：

```text
map 自己的参数
Slurm/srun 启动参数
程序自己的参数
```

> [!summary]- 核心结论
> 
> ```text
> 可执行程序路径前面：MAP 怎么启动程序
> --mpiargs 里面：Slurm/srun 怎么分配资源
> 可执行程序路径后面：PETSc/ex2 程序自己怎么运行
> ```

---

## 1. MAP 命令整体结构

典型命令：

```bash
map -n "${MAP_RANKS}" \
     --mpi=slurm \
     --mpiargs="--nodes=${NODES} --ntasks-per-node=${R} --cpus-per-task=${T} --exact --hint=nomultithread --distribution=block:block" \
     --profile \
     "${PETSC_DIR}/src/ksp/ksp/tutorials/ex2" \
     -m "${M}" -n "${N}" -ksp_converged_reason -log_view \
     -ksp_type cg \
     -pc_type gamg \
     -ksp_rtol 1e-5 -ksp_atol 1e-10 \
    < /dev/null \
  | tee "${LOG}"
```

可以先压缩成这个结构：

```bash
map [MAP参数] [可执行程序] [程序参数] < /dev/null | tee "${LOG}"
```

> [!tip]- 核心理解  
> MAP 不是单纯运行程序，而是“包住”你的程序运行。
> 
> 所以命令结构不是：
> 
> ```bash
> ./ex2 map ...
> ```
> 
> 而是：
> 
> ```bash
> map ... ./ex2 ...
> ```
> 
> MAP 先接管启动过程，然后再把真正的程序跑起来。

---

## 2. MAP 参数和 PETSc 参数怎么区分？

判断标准：看可执行程序路径在哪里。

```bash
map -n 16 --mpi=slurm --profile ./my_program -m 1000 -n 1000 -log_view
```

分成三段：

```text
map -n 16 --mpi=slurm --profile
```

这是 MAP 参数。

```text
./my_program
```

这是被 profiling 的程序。

```text
-m 1000 -n 1000 -log_view
```

这是程序参数。

在 PETSc 里，`-m`、`-n`、`-log_view` 会被 PETSc options database 读取。

> [!warning]- 常见误区  
> 不要把 PETSc 参数写到可执行程序前面。
> 
> 错误写法：
> 
> ```bash
> map -n 16 -m 1000 -n 1000 -log_view --mpi=slurm --profile ./ex2
> ```
> 
> 这样 MAP 可能会把 `-m`、`-log_view` 当成自己的参数解析，导致报错或行为异常。

---

## 3. `--mpi=slurm` 是什么意思？

```bash
--mpi=slurm
```

意思是告诉 MAP：

```text
这个 MPI 程序通过 Slurm 启动。
```

在普通 MPI 环境里，可能会用 `mpirun` 或 `mpiexec` 启动程序。

但在集群上，尤其是 Slurm 管理的 HPC 系统里，程序通常通过 `srun` 启动。

所以 MAP 需要知道：

```text
我应该用哪种 MPI 启动方式？
```

这里答案就是：

```text
用 Slurm。
```

> [!tip]- 核心理解  
> `--mpi=slurm` 不是在设置 PETSc，也不是在设置 OpenMP。
> 
> 它只是在告诉 MAP：
> 
> ```text
> 你 profiling 的这个程序，是一个由 Slurm 启动的 MPI 程序。
> ```

---

## 4. `--mpiargs="..."` 为什么要放 Slurm 参数？

例如：

```bash
--mpiargs="--nodes=${NODES} --ntasks-per-node=${R} --cpus-per-task=${T} --exact --hint=nomultithread --distribution=block:block"
```

这些参数本质上是 Slurm/srun 的参数，不是 MAP 自己的参数。

所以不能直接写成：

```bash
map --nodes=1 --ntasks-per-node=16 --cpus-per-task=8 ...
```

更合理的写法是：

```bash
map -n 16 \
    --mpi=slurm \
    --mpiargs="--nodes=1 --ntasks-per-node=16 --cpus-per-task=8" \
    --profile \
    ./ex2
```

> [!summary]- 核心结论
> 
> ```text
> MAP profiling 参数：直接写在 map 后面
> Slurm/srun 参数：放进 --mpiargs
> PETSc/ex2 参数：放在可执行程序后面
> ```

---

## 5. `-n "${MAP_RANKS}"` 和 `--ntasks-per-node` 的关系

`-n "${MAP_RANKS}"` 表示总 MPI rank 数。

```bash
map -n "${MAP_RANKS}"
```

`--ntasks-per-node=${R}` 表示每个节点上的 MPI rank 数。

```bash
--ntasks-per-node=${R}
```

二者关系是：

$$  
\mathrm{MAP_RANKS} = \mathrm{NODES} \times R  
$$

例如单节点：

```bash
NODES=1
R=16
MAP_RANKS=$(( NODES * R ))
```

所以：

```text
MAP_RANKS = 16
--nodes = 1
--ntasks-per-node = 16
```

两节点：

```bash
NODES=2
R=16
MAP_RANKS=$(( NODES * R ))
```

所以：

```text
MAP_RANKS = 32
--nodes = 2
--ntasks-per-node = 16
```

> [!warning]- 常见误区  
> `map -n` 和 `--ntasks-per-node` 不是随便写的。
> 
> 它们必须表达同一个运行布局。
> 
> 例如：
> 
> ```bash
> map -n 32 \
>     --mpi=slurm \
>     --mpiargs="--nodes=2 --ntasks-per-node=16"
> ```
> 
> 这是合理的，因为：
> 
> $$  
> 32 = 2 \times 16  
> $$
> 
> 但下面这种就不一致：
> 
> ```bash
> map -n 32 \
>     --mpi=slurm \
>     --mpiargs="--nodes=1 --ntasks-per-node=16"
> ```
> 
> 因为 Slurm 只要求了 16 个 task，但 MAP 认为要跑 32 个 rank。

## 6. `--cpus-per-task` 和 `OMP_NUM_THREADS` 为什么要一致？

在 hybrid MPI + OpenMP 程序里：

```text
MPI rank 数 = 有多少个 task
OpenMP thread 数 = 每个 task 内部开多少线程
```

通常脚本里会有：

```bash
export OMP_NUM_THREADS="${T}"
export SRUN_CPUS_PER_TASK="${T}"
```

命令里也会有：

```bash
--cpus-per-task=${T}
```

它们都使用同一个 `T`，是为了保证：

```text
Slurm 给每个 MPI rank 分配 T 个 CPU core
OpenMP 在每个 MPI rank 内部开启 T 个线程
```

> [!example]- 示例  
> 假设：
> 
> ```bash
> NODES=1
> R=16
> T=8
> ```
> 
> 表示：
> 
> ```text
> 1 个节点
> 每个节点 16 个 MPI rank
> 每个 MPI rank 开 8 个 OpenMP threads
> ```
> 
> 总线程资源需求：
> 
> $$  
> 16 \times 8 = 128  
> $$
> 
> 如果节点上正好有 128 个 CPU cores，这就是一个合理布局。

> [!warning]- 常见误区  
> 如果 Slurm 只给每个 task 1 个 CPU：
> 
> ```bash
> --cpus-per-task=1
> ```
> 
> 但 OpenMP 开了 8 个线程：
> 
> ```bash
> export OMP_NUM_THREADS=8
> ```
> 
> 结果就是每个 MPI rank 只有 1 个 core，却要塞 8 个线程。
> 
> 这会造成 CPU oversubscription，性能可能明显变差，线程绑定也可能混乱。

## 7. 常见 Slurm 参数解释

```bash
--nodes=${NODES}
```

使用多少个计算节点。

```bash
--ntasks-per-node=${R}
```

每个节点启动多少个 MPI ranks。

```bash
--cpus-per-task=${T}
```

每个 MPI rank 分配多少个 CPU cores，通常对应 OpenMP threads 数。

```bash
--exact
```

要求 Slurm 尽量精确按照指定资源启动 task，避免资源分配和预期不一致。

```bash
--hint=nomultithread
```

通常表示避免使用超线程，优先使用物理核心。

```bash
--distribution=block:block
```

控制 task 在节点和 socket 上的分布方式。`block:block` 通常表示尽量连续块状分配。

> [!tip]- 核心理解  
> 对 hybrid MPI/OpenMP 来说，资源布局的核心是：
> 
> ```text
> 每节点 MPI ranks × 每个 rank 的 OpenMP threads ≤ 每节点可用 CPU cores
> ```
> 
> 在 ARCHER2 这类系统上，如果每节点最多 128 cores，则通常要满足：
> 
> $$  
> R \times T \le 128  
> $$

## 8. `< /dev/null` 是什么意思？

```bash
< /dev/null
```

这是输入重定向。

意思是：

```text
程序的标准输入来自 /dev/null
```

`/dev/null` 可以理解成一个永远没有内容的空文件。

这样做的好处是：如果程序不小心等待用户输入，它会直接读到 EOF，不会一直卡在那里。

> [!example]- 示例
> 
> ```bash
> ./my_program < /dev/null
> ```
> 
> 表示运行 `my_program`，但不提供任何交互式输入。

---

## 9. `| tee "${LOG}"` 是什么意思？

```bash
| tee "${LOG}"
```

`tee` 的作用是：

```text
一边把输出显示在屏幕上
一边把输出保存到文件里
```

例如：

```bash
echo "hello" | tee out.log
```

终端会显示：

```text
hello
```

同时 `out.log` 里也会保存：

```text
hello
```

在 profiling 脚本里：

```bash
| tee "${LOG}"
```

表示把 PETSc 程序输出保存到日志文件。

> [!summary]- 核心结论
> 
> ```text
> < /dev/null：不让程序等待交互输入
> | tee "${LOG}"：屏幕显示一份，日志保存一份
> ```

## 11. 写 MAP 脚本的推荐流程

不要一开始就写复杂的 MAP 命令。

推荐顺序：

```text
先写能跑的 srun 命令
确认 MPI/OpenMP 布局正确
再用 map --profile 包住程序
最后加入 tee 保存日志
```

> [!tip]- 推荐思路  
> 第一步，确认普通运行没问题：
> 
> ```bash
> srun --nodes=${NODES} \
>      --ntasks-per-node=${R} \
>      --cpus-per-task=${T} \
>      ./ex2 -m "${M}" -n "${N}" -log_view
> ```
> 
> 第二步，再改成 MAP：
> 
> ```bash
> map -n "${MAP_RANKS}" \
>     --mpi=slurm \
>     --mpiargs="--nodes=${NODES} --ntasks-per-node=${R} --cpus-per-task=${T}" \
>     --profile \
>     ./ex2 -m "${M}" -n "${N}" -log_view
> ```
> 
> 这样更容易定位错误：  
> 如果第一步都跑不通，问题通常不是 MAP，而是 Slurm/PETSc/程序本身。

## 12. MAP 脚本最常见错误

> [!warning]- 常见错误清单
> 
> 1. 把 Slurm 参数直接写成 MAP 参数
>     
> 
> ```bash
> map --nodes=1 --ntasks-per-node=16 ...
> ```
> 
> 应该放进：
> 
> ```bash
> --mpiargs="--nodes=1 --ntasks-per-node=16"
> ```
> 
> 2. 忘记加载 Forge 模块
>     
> 
> ```bash
> module load forge/25.0.1
> ```
> 
> 3. `map -n` 和 Slurm task 数不一致
>     
> 
> ```text
> MAP_RANKS 必须等于 NODES × ntasks-per-node
> ```
> 
> 4. `--cpus-per-task` 和 `OMP_NUM_THREADS` 不一致
>     
> 
> ```bash
> export OMP_NUM_THREADS="${T}"
> --cpus-per-task=${T}
> ```
> 
> 5. 把 PETSc 参数写到可执行程序前面
>     
> 
> 错误：
> 
> ```bash
> map -n 16 -log_view --profile ./ex2
> ```
> 
> 正确：
> 
> ```bash
> map -n 16 --profile ./ex2 -log_view
> ```
> 
> 6. 引用了未定义变量
>     
> 
> 例如实际变量叫：
> 
> ```bash
> LOG="${OUTDIR}/run.log"
> ```
> 
> 但最后写成：
> 
> ```bash
> echo "${LOG_FILE}"
> ```
> 
> 7. 只用 `bash -n` 检查脚本
>     
> 
> `bash -n` 只能检查 Bash 语法，不能检查 MAP 参数、Slurm 参数、PETSc 参数是否正确。

## 13. 一个完整的 mental model

MAP 命令可以理解成三层：

```text
第一层：MAP
负责 profiling
例如：map -n 16 --mpi=slurm --profile

第二层：Slurm/srun
负责资源布局
例如：--nodes=1 --ntasks-per-node=16 --cpus-per-task=8

第三层：PETSc/ex2
负责真正计算
例如：-m 1000 -n 1000 -ksp_type cg -pc_type gamg -log_view
```

最终结构：

```bash
map [MAP 参数] \
    --mpiargs="[Slurm/srun 参数]" \
    --profile \
    [可执行程序] [PETSc/程序参数]
```

> [!summary]- 最终记忆
> 
> ```text
> map 负责观察程序
> Slurm 负责分配资源
> PETSc 负责实际计算
> ```
> 
> 写命令时只要分清这三层，MAP 脚本就不会乱。

## 15. 术语表

> [!note]- 术语表  
> `MAP`  
> Linaro Forge MAP，性能 profiling 工具。
> 
> `profiling`  
> 性能采样与分析，用来观察程序时间花在哪里、MPI/OpenMP 行为如何。
> 
> `MPI rank`  
> MPI 并行程序里的进程单位。
> 
> `OpenMP thread`  
> 每个 MPI rank 内部可以开启的线程。
> 
> `Slurm`  
> HPC 集群常用作业调度系统。
> 
> `srun`  
> Slurm 下启动并行程序的命令。
> 
> `--mpiargs`  
> MAP 传给 MPI 启动器的额外参数。在这里主要是 Slurm/srun 参数。
> 
> `--cpus-per-task`  
> 每个 MPI task 分配多少 CPU cores。
> 
> `OMP_NUM_THREADS`  
> 控制每个 MPI rank 内部开启多少 OpenMP threads。
> 
> `tee`  
> 同时把输出显示到终端并保存到文件。
> 
> `/dev/null`  
> 空输入或丢弃输出的特殊设备文件。
