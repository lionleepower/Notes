# Python 赋值与拷贝

Python 的赋值不会自动复制对象，而是让变量名绑定到对象。判断一段代码会不会影响原数据，关键是分清“变量改绑到新对象”和“通过变量修改原对象”。

---

## 思路

Python 中，变量更像对象的名字，而不是存放对象本体的盒子。执行 `b = a` 后，`a` 与 `b` 通常指向同一个对象；只有显式调用复制操作时，才会创建新的容器。

> [!tip]- 核心思路
> 先判断代码做的是哪一种操作：
>
> ```python
> b = a          # 共享对象：b 绑定到 a 当前指向的对象
> b = new_value  # 重新绑定：只改变 b 的指向
> b.append(x)    # 原地修改：修改 b 指向的对象
> b.attr = x     # 修改对象属性：共享该对象的变量都能看到
> ```
>
> 一句话：`变量 = 值` 改绑定，`变量.操作()` 或 `变量.属性 = 值` 可能改对象。

---

## 1. 赋值是名称绑定

> [!example]- 两个变量指向同一个列表
> ```python
> a = [1, 2, 3]
> b = a
>
> b.append(4)
> print(a)  # [1, 2, 3, 4]
> print(a is b)  # True
> ```
>
> 图示：
>
> ```text
> a ─┐
>    ↓
>   [1, 2, 3, 4]
>    ↑
> b ─┘
> ```

`is` 判断两个变量是否指向同一个对象，`==` 判断两个对象的值是否相等。

```python
a = [1, 2]
b = [1, 2]

print(a == b)  # True，内容相等
print(a is b)  # False，不是同一个列表对象
```

---

## 2. 重新绑定与原地修改

| 写法 | 含义 | 是否影响共享的原对象 |
| --- | --- | --- |
| `b = a` | 让 `b` 与 `a` 绑定同一对象 | 不修改对象 |
| `b = [...]` | 让 `b` 改绑到新列表 | 否 |
| `b.append(x)` | 修改 `b` 指向的列表 | 是 |
| `b += values` | 列表通常原地扩展 | 是 |
| `b = b + values` | 创建新列表并让 `b` 改绑 | 否 |

> [!example]- `+=` 与 `+` 的区别
> ```python
> a = [1, 2]
> b = a
> b += [3]
> print(a)  # [1, 2, 3]
>
> c = a
> c = c + [4]
> print(a)  # [1, 2, 3]
> print(c)  # [1, 2, 3, 4]
> ```

`list +=` 通常修改原列表，而 `list +` 创建新列表。判断影响范围时，不能只看有没有赋值符号，还要看对象类型和运算是否原地执行。

---

## 3. 可变对象与不可变对象

| 类型 | 常见对象 | 能否原地修改内容 |
| --- | --- | --- |
| 不可变 | `int`、`float`、`bool`、`str`、`tuple` | 不能 |
| 可变 | `list`、`dict`、`set`、大多数自定义对象 | 能 |

> [!example]- 为什么整数看起来像被复制
> ```python
> a = 1
> b = a
> b = 2
>
> print(a)  # 1
> print(b)  # 2
> ```
>
> `b = 2` 没有把整数对象 `1` 改成 `2`，而是让 `b` 改绑到另一个整数对象。

不可变不代表变量不能变化，而是对象本身不能被原地改写。变量随时可以重新绑定到另一个对象。

---

## 4. 浅拷贝

浅拷贝会创建一个新的外层容器，但内部元素仍然沿用原对象的引用。

> [!success]- 常见浅拷贝写法
> ```python
> original = [1, 2, 3]
>
> copy1 = original.copy()
> copy2 = original[:]
> copy3 = list(original)
> ```

> [!example]- 嵌套容器共享内部对象
> ```python
> original = [[1, 2], [3, 4]]
> copied = original.copy()
>
> copied.append([5, 6])
> print(original)  # [[1, 2], [3, 4]]，外层不同
>
> copied[0].append(99)
> print(original)  # [[1, 2, 99], [3, 4]]，内层仍共享
> ```

```text
original ─→ [ · , · ]
              ↓   ↓
             [1] [2]
              ↑   ↑
copied   ─→ [ · , · ]
```

---

## 5. 深拷贝

深拷贝会递归复制嵌套对象，适合需要完全独立修改嵌套数据的场景。

> [!success]- `copy.deepcopy`
> ```python
> import copy
>
> original = [[1, 2], [3, 4]]
> copied = copy.deepcopy(original)
>
> copied[0].append(99)
> print(original)  # [[1, 2], [3, 4]]
> print(copied)    # [[1, 2, 99], [3, 4]]
> ```

深拷贝并非默认选择。它需要遍历对象结构，消耗额外时间和空间；只有确实需要嵌套数据完全独立时才使用。

## 6. 函数参数仍然是对象绑定

调用函数时，形参会绑定到传入的对象。函数内重新绑定形参不会影响外部变量，但修改可变对象会影响调用者看到的内容。

> [!example]- 改绑定与改对象
> ```python
> def rebind(items):
>     items = [100]
>
> def mutate(items):
>     items.append(100)
>
> nums = [1, 2]
> rebind(nums)
> print(nums)  # [1, 2]
>
> mutate(nums)
> print(nums)  # [1, 2, 100]
> ```

如果函数不应该修改调用者的数据，可以在函数入口按需求复制：

```python
def sorted_copy(items):
    items = items.copy()
    items.sort()
    return items
```

## 7. 自定义对象与链表节点

自定义类的实例通常是可变对象。两个变量指向同一节点时，通过任一变量修改属性，另一变量都能看到。

> [!example]- 共享节点对象
> ```python
> class ListNode:
>     def __init__(self, val=0, next=None):
>         self.val = val
>         self.next = next
>
> dummy = ListNode(0, ListNode(1))
> p0 = dummy
>
> p0.next = ListNode(2)
> print(dummy.next.val)  # 2
> ```

`p0 = dummy` 不是复制节点。链表中移动变量和修改节点指针的完整区别见：[[Python_链表指针与区间反转]]。

## 8. 回溯收答案：为什么必须拷贝

回溯中 `path` 是被反复复用的可变对象。`ans.append(path)` 存进去的不是快照，而是同一个 list 的引用——最终 `ans` 里全部是 `path` 的最终状态。

> [!example]- 9 个箭头指向同一个 path
> 
> ```python
> ans.append(path)   # 错：存的是箭头（引用），不是内容
> ```
> 
> | 时刻 | `path` 当前内容 | `ans` 实际存的 |
> | --- | --- | --- |
> | 收 "ad" 时 | `['a','d']` | `[→path]` |
> | 收 "ae" 时 | `['a','e']` | `[→path, →path]` |
> | 全部结束 | `['c','f']` | 9 个 `→path`，打印全是 `['c','f']` |
> 
> append 那一刻内容确实是对的，但存下的只有地址；最后打印时顺着地址找到的是 `path` 的**最终**状态。

> [!success]- 两种正确写法
> 
> ```python
> ans.append(''.join(path))   # 拼成新字符串，与 path 脱钩（17. 电话号码的字母组合）
> ans.append(path.copy())     # 浅拷贝出新 list（78. 子集 / 131. 分割回文串）
> ```
> 
> 核心一句：`path` 是可变对象且被反复复用，收答案时必须做一份独立拷贝。应用场景见 [[6.0 回溯型算法]] 与 [[6.1 子集型回溯]]。

## 9. 赋值与复制怎么选

| 目标 | 推荐写法 |
| --- | --- |
| 共享同一对象 | `b = a` |
| 复制一层容器 | `b = a.copy()` |
| 复制列表 | `b = a.copy()` 或 `b = a[:]` |
| 复制嵌套对象并完全独立 | `b = copy.deepcopy(a)` |
| 只需排序后的新列表 | `b = sorted(a)` |
| 只需反转后的新列表 | `b = a[::-1]` |

创建新容器不一定都要调用 `copy`。`sorted()`、切片和列表推导式也会创建新的外层列表，但嵌套元素是否共享仍要单独判断。

## 10. 常见易错点

> [!warning]- 易错点
> - 误以为 `b = a` 会复制列表：它只会共享对象。
> - 回溯收答案写 `ans.append(path)`：存的是引用，`ans` 里最终全是同一份内容；必须 `path.copy()` 或 `''.join(path)`。
> - 混淆 `is` 与 `==`：前者比较身份，后者比较值。
> - 以为浅拷贝能隔离嵌套对象：浅拷贝只复制外层容器。
> - 在函数中原地修改参数，却以为外部数据不会变化。
> - 使用可变对象作为默认参数，导致多次调用共享同一对象。
> - 不加判断地使用 `deepcopy()`，造成不必要的时间和空间开销。

可变默认参数应写成：

```python
def collect(value, result=None):
    if result is None:
        result = []
    result.append(value)
    return result
```

---

## 复杂度

> [!summary]- 常见操作复杂度
> - 普通赋值 `b = a`：时间和额外空间都是 $O(1)$，只增加一个绑定。
> - 长度为 $n$ 的列表浅拷贝：时间和额外空间都是 $O(n)$，复制外层引用。
> - 深拷贝：时间和额外空间通常与被递归复制的对象总规模成正比。

---

## 一句话总结

Python 赋值共享对象，浅拷贝只分离外层容器，深拷贝才递归分离嵌套对象；判断副作用时先分清“变量改绑”还是“对象被修改”。

---

## 模板归纳

看到赋值、函数传参或容器修改时，依次判断：

1. 当前对象是可变还是不可变？
2. 两个变量是否指向同一对象？
3. 当前操作是重新绑定，还是原地修改？
4. 如果发生复制，是浅拷贝还是深拷贝？
5. 嵌套对象是否仍然共享？

```python
# 共享对象
b = a

# 浅拷贝
b = a.copy()

# 深拷贝
import copy
b = copy.deepcopy(a)

# 判断身份和值
same_object = a is b
same_value = a == b
```
