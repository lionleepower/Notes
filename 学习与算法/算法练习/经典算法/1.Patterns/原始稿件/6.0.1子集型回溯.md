```python
MAPPING = ["","", "abc", "def", "ghi", "jkl", "mno", "pqrs", "tuv", "wxyz"]

  

class Solution:

    def letterCombinations(self, digits: str) -> List[str]:

        n = len(digits)

        if n == 0:

            return []



        ans = []

        path = [''] * n

        def dfs(i):

            if i == n:

                ans.append(''.join(path))

                return

            for c in MAPPING[int(digits[i])]:

                path[i] = c

                dfs(i+1)

        dfs(0)

  

        return ans

```

这道题的抽象感，大概率来自一个点：**你不知道 `dfs(i)` 到底"是谁、在干什么"**。先把它翻译成人话。

## 1. 它本质上就是"层数不固定的嵌套 for 循环"

如果 `digits = "23"`，你会怎么写？

```python
for a in "abc":
    for b in "def":
        ans.append(a + b)
```

如果 `digits = "234"`，就要三层 for。`digits` 有多长就要多少层 —— 但代码是写死的，你没法写"n 层 for"。

**递归就是用来生成"n 层 for 循环"的工具。** 每递归一层 = 多一层 for。这就是全部的动机。

## 2. `dfs(i)` 的语义（最关键的一句）

> `dfs(i)` 表示：`path[0..i-1]` 已经填好了，我负责**填第 i 位，以及后面所有位**。

注意它不"看"前面填了什么，也不关心自己被谁调用。它只做两件事：

- 如果 `i == n`，说明没位置可填了 → 这是一条完整答案，收走
- 否则，第 i 位可以是 `MAPPING[digits[i]]` 里的任意一个字母，**每种可能都试一遍**，试完把剩下的交给 `dfs(i+1)`

这跟你熟悉的二叉树递归是同一件事：写给"任意一个抽象节点"，不是写给某个具体层。区别只是二叉树每个节点分叉 2 个（left/right），这里每个节点分叉 3~4 个（字母数）。

## 3. `path` 是一张"答题卡"

```python
path = [''] * n
```

它是一个长度为 n 的固定数组，**第 i 层只负责写第 i 格**，井水不犯河水。

所以这里没有 `pop()` / 撤销操作 —— 因为 `path[i] = c` 是**覆盖**。下一次循环换个字母时，直接把第 i 格擦掉重写就行，不需要显式恢复现场。（如果你写成 `path.append(c)`，那就必须配一个 `path.pop()`。）

## 4. 画出递归树

以 `digits = "23"` 为例，2 → "abc"，3 → "def"：

```
                    dfs(0)  path = ['', '']
        ┌──────────────┼──────────────┐
      a=path[0]      b=path[0]      c=path[0]
      dfs(1)         dfs(1)         dfs(1)
    ┌───┼───┐      ┌───┼───┐      ┌───┼───┐
    d   e   f      d   e   f      d   e   f
  dfs(2)dfs(2)dfs(2) ...            ...
   ↓
 i==n 收答案 "ad"
```

走一遍最左边这条路：

|调用|做的事|path|
|---|---|---|
|`dfs(0)`|循环到 `c='a'`，写 `path[0]='a'`|`['a','']`|
|`dfs(1)`|循环到 `c='d'`，写 `path[1]='d'`|`['a','d']`|
|`dfs(2)`|`i == n=2`，收 `"ad"`|`['a','d']`|
|回到 `dfs(1)`|for 继续，`c='e'`，**覆盖** `path[1]='e'`|`['a','e']`|
|`dfs(2)`|收 `"ae"`||
|...|`dfs(1)` 的 for 跑完，函数结束，回到 `dfs(0)`||
|回到 `dfs(0)`|for 继续，`c='b'`，覆盖 `path[0]='b'`|`['b','d']`...|

**注意最后两行**：`dfs(1)` 的 for 循环跑完就自然 return 了，控制权回到 `dfs(0)` 的 for 循环里 —— 这就是"回溯"。它不是一个你要写的动作，而是**函数返回本身**带来的效果。

## 5. 三个最容易卡住的点

**① "递归怎么知道要回去？"** 不需要"知道"。`dfs(i+1)` 只是一次普通函数调用，它 return 了，代码自然接着执行 `dfs(i)` 里 for 的下一次迭代。跟 `print()` 调用完回来是一模一样的机制。

**② "for 循环和递归到底谁在纵、谁在横？"**

- **for 循环 = 横向**：同一位上换不同字母（兄弟节点）
- **递归 = 纵向**：往下一位走（父 → 子）

抽象感往往就来自这两者混在一起。分开看就清楚了。

**③ 为什么 `if n == 0: return []`？** 不写的话，`dfs(0)` 一进来 `i == n == 0` 直接命中终止条件，会往 `ans` 塞一个空串 `""`，返回 `[""]` 而不是 `[]`。这是本题的经典 WA 点。

## 6. 复杂度

设 n 为数字个数，每个数字最多对应 4 个字母：

- 时间：$O(n \cdot 4^n)$ —— 叶子最多 $4^n$ 个，每个叶子 `''.join(path)` 花 $O(n)$
- 空间：$O(n)$ —— 递归栈深度 n，`path` 长度 n（不算答案）

---

**一句话本质**：`digits` 的每一位是一个"槽位"，每个槽位有若干候选字母，递归负责纵向推进槽位，for 负责横向枚举候选，走到底就收一份答案。


MAPPING[int(digits[i])]这个语法是什么意思？

- `digits[i]` 取出字符，比如 `'2'` —— 注意是**字符**，不是数字
- `int(...)` 把字符 `'2'` 变成整数 `2`
- `MAPPING[2]` 就是 `"abc"`

也就是 `MAPPING` 用数字本身当下标。这也是为什么它前两个位置要塞两个空串 `""`：`MAPPING[0]` 和 `MAPPING[1]` 占位，让 2 恰好对上 `"abc"`。

然后 `for c in "abc"` 就是遍历字符串的每个字符 —— 这一步很多人也会晃一下，因为 Python 里字符串本身就可迭代。

### 递归树是画出来的，执行是一条线

那张树容易骗人——它看起来像三条分支并排展开，好像 `path[0]` 同时是 `a`、`b`、`c`。但代码是单线程的，for 循环一次只能跑一个迭代：

python

```python
for c in "abc":
    path[0] = c
    dfs(1)      # ← 这一行必须完全跑完（整棵子树走完），才会回来进入下一次循环
```

时间轴上其实是：

```
path[0]='a' → 把 a 开头的答案全收完 → path[0]='b' → 把 b 开头的全收完 → path[0]='c' → ...
```

任何一个瞬间，`path` 里只有一份值，就是"当前正在走的这条路径"。

### 关键：`dfs(1)` 是阻塞的

`dfs(1)` 不是"启动一个分支去跑"，它是一次**普通的同步函数调用**。跟 `print()` 一样，调用方停在原地等它返回。它内部再调 `dfs(2)`、`dfs(2)` 再往下……整棵子树全部执行完毕、答案全部 `append` 进 `ans` 之后，`dfs(1)` 才 return，`dfs(0)` 才继续 for 的下一轮。

所以 `path[0]` 被改成 `'b'` 的时候，所有以 `'a'` 开头的答案早就已经被 `''.join(path)` **拷贝成字符串**存进 `ans` 里了。改 `path` 影响不到它们。

### 那个 join 很重要

python

```python
ans.append(''.join(path))
```

如果写成 `ans.append(path)`，那就真出问题了——存进去的是同一个 list 的**引用**，后续每次 `path[i] = c` 都会把已存的答案一起改掉，最后 `ans` 里全是同一个东西。`''.join()` 生成的是一个全新的、独立的字符串，所以是安全的。

## 先看 `''` 的疑问

`path = ['', '']` 只是**初始值**。递归一开始，`path[0] = 'a'` 就把第 0 格覆盖了，空串再也回不来了。因为这份代码**没有任何撤销操作**，所以整个过程跑完之后，`path` 停在最后一次被写入的状态——也就是 `['c', 'f']`（最后一条路径 "cf"）。

所以 `ans` 不会是一堆 `''`，而是 9 个 `['c','f']`。

## 为什么会"一起改掉"

```python
a = ['x', 'y']
b = a          # b 不是复制，b 和 a 是同一个 list
a[0] = 'z'
print(b)       # ['z', 'y']  ← b 也变了
```

`ans.append(path)` 就是这个 `b = a`。做 9 次，`ans` 里就是 9 个 `b`，全都指着同一个 `path`。

## 时间轴对照

|时刻|`path` 当前内容|`ans` 长什么样|
|---|---|---|
|收 "ad" 时 append|`['a','d']`|`[→path]`|
|收 "ae" 时 append|`['a','e']`|`[→path, →path]`|
|...|||
|收 "cf" 时 append|`['c','f']`|9 个 `→path`|
|全部结束，返回|`['c','f']`|打印出来：9 个 `['c','f']`|

注意第一行：append 的**那一刻** `path` 确实是 `['a','d']`，看起来没问题。但 `ans` 里没有存下"那一刻的快照"，只存了地址。等你最后打印时，顺着地址找过去，看到的是 `path` 的**最终**状态。

```python
class Solution:

    def subsets(self, nums: List[int]) -> List[List[int]]:

        ans = []

        path = []

        n =len(nums)

        def dfs(i):

            if i == n:

                ans.append(path.copy())

                return

  

            dfs(i+1)

            path.append(nums[i])

            dfs(i+1)

            path.pop()

        dfs(0)

        return ans
```

你的直觉其实抓到了真东西：**`dfs(0)` 一进门什么都不干，直接就调 `dfs(1)`**，一路下潜到 `dfs(n)` 才第一次产出答案。所以"最先执行完的是最深处"这个感觉是对的——但这不等于"从 n 开始考虑"。

## 先明确 `dfs(i)` 的语义

> `dfs(i)`：`nums[0..i-1]` 的选/不选已经决定好了（结果都记在 `path` 里），我负责**从第 i 个数开始，把剩下的决定做完**。

对第 i 个数只有两种决定，所以函数体就是两块：

```python
dfs(i+1)              # 决定一：不选 nums[i]，直接问下一个
path.append(nums[i])  # 决定二：选 nums[i]
dfs(i+1)              #          然后再问下一个
path.pop()            #          擦掉痕迹，还原给调用者
```

跟上一题对比：那题每一位**必须填**一个字母（for 循环枚举 3~4 种），这题每一位只有**选 / 不选**两种（所以摊平成两行，不用 for）。本质是同一个模子。

## 跑一遍 `nums = [1,2]`

缩进代表递归深度，从上往下就是真实的执行时间顺序：

```
dfs(0)  path=[]
├ dfs(1)  path=[]            ← 不选 1
│ ├ dfs(2)  i==n → 收 []                    ans=[[]]
│ ├ path.append(2) → [2]     ← 选 2
│ ├ dfs(2)  i==n → 收 [2]                   ans=[[],[2]]
│ └ path.pop() → []
├ path.append(1) → [1]       ← 选 1
├ dfs(1)  path=[1]
│ ├ dfs(2)  i==n → 收 [1]                   ans=[[],[2],[1]]
│ ├ path.append(2) → [1,2]   ← 选 2
│ ├ dfs(2)  i==n → 收 [1,2]                 ans=[[],[2],[1],[1,2]]
│ └ path.pop() → [1]
└ path.pop() → []
```

看第一条收到的答案是 `[]`（空集）——因为下潜路上全走"不选"分支，到底时 `path` 还是空的。这正是空集的由来，很多人在这里会觉得"凭空冒出来一个空数组"。

## 回答你的问题

**"是不是先从 dfs(n) 开始考虑？"**

不是。**写代码时**你是站在 `dfs(i)` 这个抽象位置想问题的：我只管第 i 个数选不选，剩下的交给 `dfs(i+1)`。**运行时**才表现为一路下潜到底、再逐层弹回。

这两件事要分开：写的是逻辑，看到的是执行轨迹。你觉得抽象，多半是想同时在脑子里跟踪整条执行轨迹——那必然爆炸。只信任"`dfs(i+1)` 会把后面的事全部办妥"这一句就够了，跟你写二叉树递归时信任 `dfs(root.left)` 是一回事。

## 为什么这题要 `pop()`，上一题不要

||电话号码|子集|
|---|---|---|
|`path`|定长 `[''] * n`|变长，动态增删|
|写入方式|`path[i] = c`（**覆盖**）|`path.append()`（**追加**）|
|需要撤销吗|不需要，下次覆盖即可|需要，否则会污染兄弟分支|

关键是最后一行。如果不 `pop()`，`dfs(1)` 里选了 2 之后 `path=[1,2]`，返回到 `dfs(0)` 时 `path` 还带着 2，`dfs(0)` 再 `pop()` 掉的就是 2 而不是 1，全乱套。

**记一条铁律：`append` 和 `pop` 必须成对出现，夹住中间的递归调用。** 这就叫"恢复现场"——保证 `dfs(i)` 返回时，`path` 跟进来时长得一模一样。

`dfs(i)` 是在问"第 i 个数要不要"，两条分支穷尽两种可能；`pop()` 只是把选过的痕迹擦掉，好让调用者拿到一个干净的 `path`。

## 核心概念：每一层"只拥有"自己那一个元素

`path` 是所有层共用的一块公共区域。但每一层对它的**所有权是有边界的**：

- `dfs(0)` 只拥有 `nums[0]` 这个元素——只有它有资格把 1 放进去、把 1 拿出来
- `dfs(1)` 只拥有 `nums[1]`——只有它能动 2
- `dfs(i)` 只拥有 `nums[i]`

谁放的谁收，绝不越界去动别人的东西。这是设计上的约定，跟"程序跑到哪一步"无关。

## 由此得出一条不变量（invariant）

> **`dfs(i)` 返回时，`path` 必须和它刚进来时一模一样。**

这就是每一层向调用者做出的**承诺**。`dfs(0)` 之所以敢写 `dfs(1)` 这一行然后接着干活，正是因为它相信这个承诺：不管 `dfs(1)` 内部折腾了多少东西，回来时 `path` 一定被还原了。

`append` / `pop` 成对出现，就是这层在**兑现自己的承诺**：

```python
path.append(nums[i])   # 我借用了公共区域，多放了一个我的东西
dfs(i+1)               # 期间子层随便折腾，但它也会守约还原
path.pop()             # 我用完了，把我放的东西收回，恢复原样
```

注意 `pop()` 的含义：**不是"删掉最后一个元素"，而是"归还我借用的那一格"**。之所以恰好等价于删最后一个，正是因为下面每一层都守约了——它们借的都还回去了，所以栈顶露出来的必然是我自己放的那个。

## 不 pop 会破坏什么

不是"跑错了一步"，而是**承诺被撕毁了**。

`dfs(1)` 不还原就返回，`path` 里就残留了不属于 `dfs(0)` 的垃圾。此时 `dfs(0)` 再执行 `pop()`，它以为自己在收回 1，实际收回的是别人的 2。

从这一刻起，"栈顶元素属于当前层"这个前提失效了。而所有层的 `pop()` 都建立在这个前提上，所以错误不会停在一处，会顺着调用链一路蔓延。这就是我说的"乱套"——不是某一步算错，是**整套所有权规则崩了**。

## 一个类比

把 `path` 想成一块公共白板，每层来写一行字：

- 我写一行 → 让下一个人来写 → 他写完擦掉自己那行走了 → 我擦掉我那行走
- 每个人离场时白板恢复成他到场时的样子

如果有人写完不擦就走，下一个人擦的就是别人的字。白板从此没人对得上号。

**你不需要在脑子里模拟白板每一刻的内容**，只需要相信一件事：每个人都会擦掉自己写的。这就是递归可以"不用跟踪执行过程"就写对的原因。

## 回到你的困惑本身

你觉得难，是因为在追踪 `path` 每个瞬间的值。但正确的思考姿势是：

- **写 `dfs(i)` 时**：假设 `path` 已经正确记录了前 i-1 个决定（不用管怎么来的），我做我的决定，做完还原
- **看 `dfs(i+1)` 这一行时**：把它当黑箱，它会办妥后面的事，并把 `path` 完好归还

这跟你在二叉树里信任 `dfs(root.left)` 会返回正确的子树答案，是完全同一种思维方式。区别只是二叉树的返回值是显式的，这里的"返回值"藏在 `ans` 和 `path` 的状态约定里。

path.append(nums[i]) # 我借用了公共区域，多放了一个我的东西 dfs(i+1) # 期间子层随便折腾，但它也会守约还原 path.pop() # 我用完了，把我放的东西收回，恢复原样

这是我放入的情况呀，不是还有我没有放入的情况吗

对，而且这正好说明了那条不变量的适用范围——**只有动过 `path` 的分支才需要还原**。

看两条分支各自的"借用"情况：

```python
dfs(i+1)               # 分支一：不选。我什么都没往 path 里放
                       #        → 没借东西，自然不用还
path.append(nums[i])   # 分支二：选。我借了一格
dfs(i+1)
path.pop()             #        → 用完必须还
```

"不选"的那一行，`path` 从头到尾没被这一层碰过。子层守约还原之后，`path` 自动就跟进来时一模一样了。**承诺已经兑现了，不需要额外动作。**

## 换个角度说

不变量是「进来什么样，出去什么样」，而不是「每个分支都得写 pop」。

- 分支一：0 次 append，0 次 pop → 平衡 ✓
- 分支二：1 次 append，1 次 pop → 平衡 ✓

要求的是**收支平衡**，不是"必须有 pop"。

## 顺带回答一个隐含疑问

你可能还会想：分支一执行完之后，`path` 是不是已经"脏"了，导致分支二的起点不对？

不会。分支一返回时 `path` 已被还原成 `dfs(i)` 刚进门的状态，所以分支二的 `append` 是从同一个干净起点开始的。**两条分支互不干扰**——这也是为什么它们能各自穷尽一半的可能性，加起来正好覆盖全部 $2^n$ 个子集。

这个"兄弟分支互不污染"的性质，正是恢复现场存在的全部意义。

                dfs(j+1)

        return ans
