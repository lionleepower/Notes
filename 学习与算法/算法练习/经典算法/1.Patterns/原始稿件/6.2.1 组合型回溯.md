倒序枚举：
```python
class Solution:

    def combine(self, n: int, k: int) -> List[List[int]]:
        ans = []
        path = []
        def dfs(i):
            if len(path) == k:
                ans.append(path.copy())
                return
            for j in range(i, 0, -1):
                path.append(j)
                dfs(j-1)
                path.pop()
        dfs(n)

        return ans
```


### 为什么"可以"倒着枚举

先说结论：**倒序不是必须的**。正序写 `dfs(i)` 里 `for j in range(i, n+1): dfs(j+1)`，从 `dfs(1)` 开始，同样正确。两者只是在同一棵搜索树上换了个遍历顺序，题目又说"任何顺序"都行。

它们本质上是同一个不变量：

> `dfs(i)` 的含义是"**候选池只剩下某个区间，从中再挑 k−∣path∣k - |path| k−∣path∣ 个**"。

- 正序版：候选池是 `[i, n]`，池子的"上界固定、下界在推进"。
- 倒序版：候选池是 `[1, i]`，池子的"下界固定 1、上界在收缩"。

### 那为什么很多人偏爱倒序

因为**剪枝写起来更顺**。

组合问题最关键的剪枝是：_剩下的数不够凑齐 k 个了，直接放弃这条分支_。

- 倒序：候选池是 `[1, i]`，池子大小**就是 `i` 本身**。所以剪枝条件直接是

python

```python
  if i < k - len(path):
      return
```

一眼就能读懂：能选的还剩 `i` 个，但还需要 `k - len(path)` 个，不够，撤。

- 正序：候选池是 `[i, n]`，大小是 `n - i + 1`，剪枝条件变成 `n - i + 1 < k - len(path)`，多一层算术，写的时候容易把 `+1` 弄错。

另外倒序还天然对应组合数的递推 C(n,k)=C(n−1,k−1)+C(n−1,k)C(n,k) = C(n-1,k-1) + C(n-1,k) C(n,k)=C(n−1,k−1)+C(n−1,k)：站在数字 nn n 面前只问"选它 / 不选它"，两条分支都把问题规模降到 n−1n-1 n−1。正序反而要绕一下才能对上这个式子。

所以：**倒序是为了让"剩余可选个数"这个量直接等于参数本身**，纯粹是可读性和剪枝便利，不是正确性要求。

加上剪枝的完整版：

python

```python
def dfs(i):
    d = k - len(path)          # 还需要选几个
    if d == 0:
        ans.append(path.copy())
        return
    if i < d:                  # 剩下的数不够了
        return
    for j in range(i, d - 1, -1):   # j 至少要留 d-1 个在它下面
        path.append(j)
        dfs(j - 1)
        path.pop()
```

注意 `range` 的下界也从 `0` 收紧成了 `d - 1`：选了 `j` 之后，下面还得凑 `d - 1` 个，所以 `j` 不能小于 `d`。这是同一个剪枝在循环层面的等价写法，两处只留一处也可以。

这一步我没想明白： for j in range(i, d - 1, -1):为什么是d-1?
分两步拆：先想清楚 **j 最小能取到几**，再想 range 的写法。

**第一步：j 的下界是 d，不是 d-1。**

站在 `dfs(i)` 这一层，`d = k - len(path)` 表示"连 j 在内，还得凑齐 d 个数"。  
一旦选了 j，剩下的候选池收缩成 `[1, j-1]`，池子里只有 **j-1 个数**，而还需要 **d-1 个**。

要能凑齐，必须：

j−1≥d−1⟹j≥dj - 1 \ge d - 1 \quad\Longrightarrow\quad j \ge dj−1≥d−1⟹j≥d

直觉上也很好记：选中的 d 个数互不相同、且严格递减往下走，最小的那个至少是 1，所以最大的那个（也就是这一层的 j）至少是 d。比如还要选 3 个，j 取 3 时下面只能是 2 和 1，刚好卡满；j 取 2 就无论如何凑不出 3 个了。

**第二步：range 的 stop 是开区间。**

`range(start, stop, -1)` 生成到 `stop + 1` 为止，**不含 stop**。既然想让 j 一路取到 d，stop 就得写成 `d - 1`。

python

```python
range(i, d - 1, -1)   # j = i, i-1, ..., d+1, d   ← 停在 d
```

那个 `-1` 纯粹是"开区间"带来的偏移，跟剪枝逻辑没关系。你可以把它读成两层：**数学上的约束是 `j >= d`，语法上为了表达这个约束才写 `d - 1`**。

顺带一提，这条循环下界和前面那句 `if i < d: return` 是**同一个剪枝的两个位置**——一个在进入这层时提前拦截，一个在循环里不让 j 走到无效区。留一个就够，两个都写只是更保险。

同样选或是不选：

对比一下两种写法的"停止机制"：

- **循环版**：`for j in range(i, 0, -1)`。当 `i == 0` 时这个 range 是空的，循环体一次都不执行，函数自然返回。**边界藏在 range 里，是免费的。**
- **选 / 不选版**：没有循环。`dfs(i-1, t)` 这条"不选"的分支，`path` 不增长、`t` 不减小，唯一在变的就是 `i`。所以只要 `len(path) < k` 且 `t >= 0`，它就会一直 `i-1, i-2, ...` 地掉下去，直到爆栈。

换个说法：`i` 表示候选池 `[1, i]`。**池子空了必须收手**，而循环版是 range 帮你收的手，选/不选版得你自己写。

### 修法

python

```python
def dfs(i, t):
    if len(path) == k:
        if t == 0:
            ans.append(path.copy())
        return
    if i == 0 or t < 0:      # 池子空了 / 和已经超了
        return
    dfs(i - 1, t)            # 不选 i
    path.append(i)
    dfs(i - 1, t - i)        # 选 i
    path.pop()
```

注意两个 return 的**顺序不能反**：先判成功（选够 k 个），再判失败（池子空）。反过来的话，最后一个数刚好在 `i == 0` 前一层选中的情况会被误杀。

### 顺带一提

`if i == 0` 其实是剪枝 `if i < k - len(path)` 的弱化版——池子里剩 `i` 个数，还需要 `k - len(path)` 个，不够就撤。用后者可以同时把边界和剪枝一次解决：

python

```python
if i < k - len(path):
    return
```

`i == 0` 而 `len(path) < k` 时必然满足这个条件，所以它是被包含进去的。

两种写法（枚举选哪个 / 选或不选）本质是同一棵搜索树的两种切法，**记住它们的区别就在于边界是不是自动的**：循环版的 range 自带兜底，二叉版必须显式写。

## 一、先把问题翻译成熟悉的形状

前面几题的搜索树是"**从数字池里挑几个**"。这题看起来是"生成字符串"，但它其实是：

> 有 $2n$ 个**格子**排成一排，每个格子必须填 `(` 或 `)`，问哪些填法合法。

一旦这样看，它就回到了老骨架：`dfs(i)` 表示"**前 i 个格子已经填好，现在决定第 i 格填什么**"。候选池不再是数字 `[1, i]`，而是固定的两个字符。到 `i == m` 就是格子填满了，收工。

所以这不是新算法，只是**候选池换了内容**。

## 二、真正的难点：怎么把"合法"变成局部判断

括号合法性听起来是个"看完整个串才知道"的全局性质。回溯需要的是**能在每一步立刻检查**的条件。这题的关键定理就是把全局翻译成局部：

> 一个括号串合法 $\iff$ (1) 左右括号各 $n$ 个；(2) **任意前缀**中，右括号数量 $\le$ 左括号数量。

第二条是精髓。它的含义很直白：**每个右括号都必须找得到一个在它左边、且还没被配对的左括号**。如果某个前缀里右括号超了，说明有个右括号"无家可归"，那么无论后面再怎么填都救不回来了——错误一旦发生就不可逆。

这个"不可逆"正是回溯剪枝成立的前提：可以在半路就砍掉整棵子树，不必等填满再验。

## 三、两个 if 就是这两条约束

```python
if open < n:          # 约束 (1)：左括号别超额
if i - open < open:   # 约束 (2)：右括号别超过左括号
```

`open` 是已填的左括号数，`i` 是已填总数，所以 `i - open` 天然就是已填的右括号数——**不需要第二个计数器**，减法就够了。这是这份代码最漂亮的地方。

于是每个格子面对的问题变成：

- 左括号还有存货吗？有就可以填 `(`。
- 手上有"未配对的左括号"吗（即 `右 < 左`）？有才可以填 `)`。

两个条件互相独立，可能都成立（分裂成两条分支）、只成立一个（唯一选择）、或都不成立。而**都不成立是不可能的**：`open == n` 且 `i - open == open` 意味着 `i == 2n`，那已经在函数开头返回了。所以每条路径都能走到底，**这棵树没有死胡同、没有白跑的分支**——这也是为什么这题不需要 `t < 0` 那种失败回收。

## 四、为什么没有 `path.pop()`

前面几题用 `append` / `pop` 维持"进出平衡"的不变量。这里换成了**定长数组 + 按下标覆写**，不变量也随之改写：

> 进入 `dfs(i)` 时，`path[0..i-1]` 恰好记录着当前这条路径的决策；`path[i..]` 里是什么，无所谓。

既然 `i` 之后的内容从不被读取（只有 `i == m` 时才 `join`，那时 `0..m-1` 全部写满且都属于当前路径），就不必"擦掉"——下一条分支自然会把 `path[i]` 覆盖掉。

**pop 的本质从来不是"清理"，而是"让兄弟分支看到干净的状态"。** 覆写达成了同样的效果，只是手段不同。可以类比：`append`/`pop` 像用铅笔在便签末尾写字再擦掉；定长数组像在固定格子里写字，下一个人直接盖上去。

## 五、一句话收束

**这题的难点不在回溯，在于把"括号合法"这个全局性质，翻译成了"每一步都能立刻检查的两个计数关系"。** 一旦翻译完成，剩下的就是最普通的回溯骨架。

顺带说，还有第三种视角：既然 $2n$ 个位置中左括号占 $n$ 个，也可以理解成"**从 $2n$ 个位置里选 $n$ 个放左括号**"——这就完全退化成 [[组合]] 了，只是多了个前缀约束。这个视角能让你看清它和前面几题是同一个模板。
