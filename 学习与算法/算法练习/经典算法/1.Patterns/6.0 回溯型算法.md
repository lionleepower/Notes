# 回溯型算法

## 解决什么问题

题目要求**所有**方案（所有组合、子集、切分、排列），且答案是一步一步选出来的——每一步做一个决定，增量构造 (incremental construction) 出完整答案。子问题与原问题相似，所以用递归；回溯 Backtracking 本质就是 DFS 在「决策树」上的应用。

## 为什么用递归：层数不固定的嵌套 for

若 `digits = "23"`，两层 for 就能枚举全部组合；`"234"` 要三层。输入多长就要多少层，而代码写不出「n 层 for」——**递归就是用来生成 n 层 for 循环的工具，每递归一层 = 多一层 for。** 这就是全部的动机。

> [!tip]- 核心思路：回溯三问
> 
> 写模板前先回答三问，`dfs(i)` 的语义随之确定：
> 
> 1. **当前操作？** 枚举第 $i$ 位的所有候选，填入 `path`。
> 2. **子问题？** 构造下标 $\ge i$ 的那部分答案。
> 3. **下一个子问题？** 构造下标 $\ge i+1$ 的那部分答案。
> 
> 由此得到 `dfs(i)` 的完整语义：**`path[0..i-1]` 已经填好，我负责填第 $i$ 位以及后面所有位。** 它不看前面填了什么，也不关心被谁调用——这份规则写给「任意一个抽象节点」，和二叉树递归写给任意节点是同一种思维，区别只是分叉数不同。
> 
> 只需考虑边界条件与非边界条件，其余交给数学归纳法。

## 统一模板

> [!success]- 模板代码（以 17. 电话号码的字母组合 为例）
> 
> ```python
> MAPPING = ["", "", "abc", "def", "ghi", "jkl", "mno", "pqrs", "tuv", "wxyz"]
> 
> class Solution:
>     def letterCombinations(self, digits: str) -> List[str]:
>         n = len(digits)
>         if n == 0:                        # 不判空会返回 [""] 而不是 []
>             return []
>         ans = []
>         path = [''] * n                   # 答题卡：定长数组，第 i 层只写第 i 格
>         def dfs(i):
>             if i == n:                    # 没有槽位可填 → 收一份完整答案
>                 ans.append("".join(path)) # join 生成新字符串，与 path 脱钩
>                 return
>             for c in MAPPING[int(digits[i])]:
>                 path[i] = c               # 覆盖式写入，下轮直接重写，无需撤销
>                 dfs(i + 1)
>                 # 这里也可以用我们之前的模板写法
> 	            #  path.append(c)
> 	            #  dfs(i+1)
> 		        #  path.pop()
>         dfs(0)
>         return ans
> ```
> 
> - 主流程：for 横向枚举第 $i$ 位的候选，`dfs(i+1)` 纵向推进到下一位，`i == n` 时收答案。
> - 关键变量：`path` 是所有层共用的一张「答题卡」，第 $i$ 层只负责写第 $i$ 格。
> - 易错位置：`n == 0` 的空输入判断；收答案必须拷贝（`join` / `copy`），否则存的是引用，见 [[Python_赋值与拷贝]]。
> - `MAPPING[int(digits[i])]` 的语法逐层拆解见 [[Python_字符串常用操作]]。

> [!example]- 示例推演：digits = "23" 的递归树
> 
> ```text
>                  dfs(0)  path=['','']
>          ┌──────────┼──────────┐
>        a           b           c        ← path[0]，for 横向
>       dfs(1)      dfs(1)      dfs(1)    ← 递归纵向
>      ┌──┼──┐     ┌──┼──┐     ┌──┼──┐
>      d  e  f     d  e  f     d  e  f    ← path[1]
>      ↓
>    i==n 收 "ad"、"ae"、"af"、"bd" …… 共 9 个叶子
> ```
> 
> `dfs(1)` 的 for 跑完就自然 `return`，控制权回到 `dfs(0)` 的 for 里——**「回溯」不是一个要写的动作，而是函数返回本身带来的效果。**
> 
> 树是画出来的，执行是一条线：任何瞬间 `path` 里只有一份值，不存在条件竞争。详见 [[递归树]]。

## 状态恢复：覆盖式与追加式

`path` 是共享的，每层用完必须让它「进来什么样，出去什么样」。两种写法对应两种恢复方式：

| | 覆盖式 | 追加式 |
| --- | --- | --- |
| `path` | 定长 `[''] * n` | 变长，动态增删 |
| 写入 | `path[i] = c`（覆盖） | `path.append(x)`（追加） |
| 恢复 | 不需要，下次覆盖即可 | `pop()` 必须与 `append` 成对 |

铁律：**`append` 和 `pop` 必须成对出现，夹住中间的递归调用**，否则残留元素会污染兄弟分支。这条不变量 (invariant) 背后的「所有权 / 承诺」视角详见 [[状态恢复]]。

## 剪枝 Pruning

for 枚举候选时，如果当前候选**注定不能通向合法答案**，直接跳过、不递归——等于砍掉整棵子树。例如 131. 分割回文串 中 `if t == t[::-1]` 才递归：非回文的切分不进入下一层，指数级节点被提前排除。剪枝写在**进入递归之前**，这是它和「先生成再过滤」的本质区别。（组合型回溯的上界剪枝，后续专题展开。）

## 易错点

> [!warning]- 易错点
> 
> - **空输入不判**：17 题不写 `if n == 0`，`dfs(0)` 进门就命中 `i == n`，往 `ans` 塞进空串，返回 `[""]` 而非 `[]`——经典 WA 点。
> - **收答案存了引用**：`ans.append(path)` 存的是同一个 list 的引用，最终 `ans` 里全是 `path` 的最终状态；必须 `''.join(path)` 或 `path.copy()`，原因见 [[Python_赋值与拷贝]]。
> - **append / pop 不成对**：子层不还原，父层 `pop()` 掉的就是别人的元素，整套所有权规则崩塌，见 [[状态恢复]]。
> - **把递归树当并发**：没有「同时」，只有「先后」；`dfs(i+1)` 是阻塞的同步调用，整棵子树跑完才回来。

## 复杂度

> [!summary]- 复杂度
> 
> 通用方法：**叶子（或节点）个数 × 单个叶子的处理代价**。
> 
> - 17 题：叶子最多 $4^n$ 个，每个叶子 `''.join(path)` 花 $O(n)$ → 时间 $O(n \cdot 4^n)$。
> - 子集型：$O(n \cdot 2^n)$；排列型：$O(n \cdot n!)$。
> - 空间：$O(n)$ —— 递归栈深度 $n$ 加 `path` 长度 $n$（不计返回结果）。

## 一句话总结

递归负责**纵向**推进槽位，for 负责**横向**枚举候选，走到底收一份答案；「回溯」只是函数返回，「恢复现场」只是兑现「进来什么样、出去什么样」的承诺。

## 模板归纳

**触发信号**：要求返回**所有**方案 / 组合 / 切分；答案由一串决定构成；数据规模很小（$n \le 20$ 左右，暗示指数级枚举可接受）。

**落笔步骤**：

1. 回答回溯三问，确定 `dfs(i)` 的语义（负责 $\ge i$ 的部分）。
2. 选 `path` 形态：每位必填 → 定长覆盖式；可选可不选 / 变长 → 追加式（`append`/`pop` 成对）。
3. 写终止条件 `i == n`，收答案时**必须拷贝**。
4. for 枚举当前位候选，能剪枝的条件写在递归之前。
5. 检查空输入等边界。
