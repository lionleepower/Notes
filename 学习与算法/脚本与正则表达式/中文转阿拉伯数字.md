# 中文数字转阿拉伯数字：扫描 + 累加器

把「三百二十一」这类中文数字串转成整数 `321`。核心难点在于中文数字是**乘 + 加**结构（`三×百 + 二×十 + 一`），不是字符串拼接，所以不能用 `re.sub` 替换，而要用**一次线性扫描 + 累加器 (accumulator)** 逐字符算出来。凡是「把一段文本转成一个需要求和的数值」都属于这个题型。

---

## 思路

为什么不能用正则替换：直觉上会想「把 `百` 换成 `00`、`千` 换成 `000` 再拼起来」，但 `三百二十一` 这样拼会得到 `"300"+"20"+"1"="300201"`，而正确答案是 `3×100 + 2×10 + 1 = 321`。`re.sub` 只会「匹配 + 局部改写 + 拼接」，**没有跨越整段做加法的能力**，工具选错了。

它为什么适合累加器：中文数字的语义是「数字 × 位权，再累加」。所以维护一个「刚读到的数字」`cur`，遇到位权单位（十/百/千）就 `cur × 位权` 加进总和、并清空 `cur`。一遍扫过去，加法自然完成。

> [!tip]- 核心思路 「数字先记住，遇单位就乘上位权加进总和」。
> 
> ```python
> if ch in digits:            # 读到数字 → 暂存
>     cur = digits[ch]
> elif ch in units:           # 读到位权 → 乘加
>     total += cur * units[ch]
>     cur = 0
> # 结尾别忘了加上没有单位的个位 cur
> ```
> 
> 不变量：任意时刻 `total` 是已结算部分的和，`cur` 是尚未结算的、等待下一个单位的个位数字。

---

## 1. 状态设计

无需导入。关键是想清楚要维护哪几个变量，以及两张映射表 (hash map) 把汉字翻成数值。

> [!success]- 基础状态
> 
> ```python
> digits = {"零":0,"一":1,"二":2,"三":3,"四":4,
>           "五":5,"六":6,"七":7,"八":8,"九":9}   # 数字字符 → 值
> units  = {"十":10,"百":100,"千":1000}            # 位权单位 → 倍数
> 
> total = 0   # 已结算部分的累计和
> cur   = 0   # 刚读到、还没乘位权结算的个位数字
> ```

---

## 2. 核心操作

逐字符扫描，按字符类型分三种处理规则。

|读到的字符|处理|说明|
|---|---|---|
|数字（一~九）|`cur = digits[ch]`|暂存，等后面的单位来乘|
|位权（十/百/千）|`total += cur * units[ch]; cur = 0`|乘上位权累加，再清空 `cur`|
|扫描结束|`return total + cur`|补上结尾没有单位的个位|

> [!example]- 最小示例
> 
> ```python
> def cn_to_int(s):
>     digits = {"零":0,"一":1,"二":2,"三":3,"四":4,
>               "五":5,"六":6,"七":7,"八":8,"九":9}
>     units  = {"十":10,"百":100,"千":1000}
>     total = cur = 0
>     for ch in s:
>         if ch in digits:
>             cur = digits[ch]
>         elif ch in units:
>             if cur == 0:          # 处理"十五"这类十前无数字
>                 cur = 1
>             total += cur * units[ch]
>             cur = 0
>     return total + cur
> 
> 
> print(cn_to_int("三百二十一"))   # 321
> ```

---

## 3. 关键行为与边界

三个最容易漏的边界：结尾的个位、`十`打头、以及 `零` 的作用。

> [!tip]- 为什么这样做 位权单位负责「结算」，但**个位数字后面没有单位**（`三百二十一` 的 `一`），所以它永远留在 `cur` 里进不了 `total`，必须在 `return` 时手动补 `total + cur`。这是最高频的漏写点。

> [!warning]- 边界条件
> 
> - **`十` 打头无数字**：`十五` 的 `十` 前面没有数字，`cur` 还是 0，需先把 `cur` 置 1 当作「一十」，否则 `0×10=0` 丢掉了十位。
> - **结尾个位**：扫描结束务必 `+ cur`，否则末尾的个位数被吞。
> - **`零` 的处理**：`零` 映射为 0，`一千零五` 里读到 `零` 时 `cur=0`，不影响累加，只是占位；无需特殊分支。
> - **空串 / 非法字符**：本实现对不在两张表里的字符直接跳过，视题目约束决定是否要报错。

## 4. 实例一：万以内转换（十/百/千）

输入 `三百二十一`，目标 `321`。这是最能体现「乘 + 加」主流程的场景，逐帧看 `cur` / `total` 怎么变化：

> [!success]- 逐帧状态
> 
> |读到|类型|处理|`cur`|`total`|
> |---|---|---|---|---|
> |三|数字|暂存 3|3|0|
> |百|单位|`total += 3×100`|0|300|
> |二|数字|暂存 2|2|300|
> |十|单位|`total += 2×10`|0|320|
> |一|数字|暂存 1|1|320|
> |结束|—|`return total + cur`|—|**321**|

主流程：数字进 `cur`、单位触发乘加清空。最容易写错的位置是**结尾忘了 `+ cur`**——那样 `一` 会被吞，结果变成 `320`。

---

## 5. 实例二：带「万 / 亿」的分节

万以上要引入「节」的概念：`万` 和 `亿` 会把前面累计的整段**乘以 10000 / 10^8** 并结算掉，进入更高一级。用第三个变量 `section` 管当前「万节」内的累计。

> [!success]- 完整实现
> 
> ```python
> def cn_to_int(s):
>     digits = {"零":0,"一":1,"二":2,"三":3,"四":4,
>               "五":5,"六":6,"七":7,"八":8,"九":9}
>     units  = {"十":10,"百":100,"千":1000}
>     total = section = cur = 0      # total: 已结算大节; section: 当前万节内
>     for ch in s:
>         if ch in digits:
>             cur = digits[ch]
>         elif ch in units:
>             if cur == 0:
>                 cur = 1
>             section += cur * units[ch]
>             cur = 0
>         elif ch == "万":
>             section = (section + cur) * 10000
>             total += section
>             section = cur = 0
>         elif ch == "亿":
>             section = (section + cur) * 10**8
>             total += section
>             section = cur = 0
>     return total + section + cur
> 
> 
> print(cn_to_int("三万二千一百"))   # 32100
> print(cn_to_int("一千零五"))       # 1005
> ```

> [!summary]- 当前实例复杂度
> 
> - 时间复杂度：$O(n)$，$n$ 为字符串长度，单次线性扫描，每字符 $O(1)$ 处理。
> - 空间复杂度：$O(1)$，两张映射表大小固定，只用了三个整数变量，与输入规模无关。

## 6. 与相近写法怎么选

|需求|推荐写法|原因|
|---|---|---|
|中文数字 → 整数（需求和）|扫描 + 累加器|唯一能做「乘加」的方式|
|阿拉伯数字互转、纯格式改写|`re.sub`|只需模式匹配 + 局部替换，不涉及求和|
|一个字符 ↔ 一个字符固定映射|`str.translate` / 字典 `re.sub`|无位权、无进位时够用|
|想偷懒用 `eval` 拼算式|不推荐|有安全风险，且中文数字无法直接映射成合法表达式|

---

## 7. 常见易错点

> [!warning]- 易错点
> 
> - 结尾漏 `+ cur`：末尾个位数字没有单位触发结算，会被吞，务必在 `return` 补上。
> - `十` 打头未置 1：`十五` 的 `十` 前无数字，`cur` 为 0 会丢十位，需 `cur = 1`。
> - 用 `re.sub` 拼零：`百→"00"` 拼接对多位数错误（`三百二十一→300201`），中文数字是乘加不是拼接。
> - 忘记 `万/亿` 是「乘整段」：它们不是简单加零，而是把当前 `section + cur` **整体乘倍**再进位。
> - 结果没赋值回变量：`re.sub` / 字符串操作都返回新值，字符串不可变，改动必须接住。

---

## 复杂度

> [!summary]- 复杂度
> 
> - 核心操作：每个字符 $O(1)$（字典查表 + 一次乘加）。
> - 完整流程：时间复杂度 $O(n)$，一次线性扫描，$n$ 为字符数。
> - 额外空间：$O(1)$，映射表固定大小，仅 `total / section / cur` 三个标量，不随输入增长。

## 一句话总结

中文数字转整数的本质是「数字 × 位权后累加」，看到「把一段文本转成需要求和的数值」就用扫描 + 累加器，关键写法是数字暂存进 `cur`、遇单位 `total += cur * unit` 清空、结尾补 `+ cur`。

## 模板归纳

看到以下信号时，优先想到扫描 + 累加器（而非 `re.sub`）：

- 「把一段字符转成一个**需要计算/求和**的值」，输出不是文本而是数值。
- 元素之间存在**位权、进位、分组求和**关系（中文数字、罗马数字、单位换算）。
- 处理逻辑是「读到 A 暂存、读到 B 才结算」的**延迟计算**模式。

```python
# 可直接复用的最小模板:暂存 + 结算 累加器
def scan_accumulate(s, value_map, unit_map):
    total = cur = 0
    for ch in s:
        if ch in value_map:
            cur = value_map[ch]          # 暂存待结算的值
        elif ch in unit_map:
            if cur == 0:
                cur = 1
            total += cur * unit_map[ch]  # 遇结算点:乘权累加
            cur = 0
    return total + cur                   # 补上末尾未结算部分
```
