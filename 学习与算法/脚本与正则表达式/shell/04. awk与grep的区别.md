# AWK 与 grep 的区别：筛选整行还是处理字段

`grep` 擅长根据关键词或正则表达式筛选整行；`awk` 不仅能筛选行，还能拆分字段、计算和重新组织输出。两者都能查找文本，但选择依据是匹配后还需不需要处理数据结构。

---

## 核心区别

> [!tip]- 选择口诀
> - **只想找出哪些行**：先用 `grep`。
> - **还要读取列、比较数值、计算或改变输出格式**：用 `awk`。
> - **前面先大范围过滤，后面再按列加工**：可以组合 `grep | awk`，但简单条件通常直接用一个 `awk` 更清楚。

| 对比项 | `grep` | `awk` |
| --- | --- | --- |
| 核心定位 | 按模式筛选文本行 | 按记录和字段处理文本 |
| 默认处理单位 | 整行 | 整行记录及其中的字段 |
| 正则匹配 | 原生核心能力 | 可匹配整行或指定字段 |
| 字段拆分 | 不负责 | 默认按空白，也可用 `-F` 指定 |
| 数值比较 | 不适合 | 支持 `$3 > 10` 等条件 |
| 统计计算 | 通常只做匹配计数 | 可求和、平均值、分组统计 |
| 输出重构 | 主要输出原行、匹配部分或上下文 | 可选择字段并用 `print`、`printf` 重排 |
| 学习成本 | 较低 | 较高，但处理能力更完整 |
| 典型场景 | 找错误行、递归搜索、显示上下文 | 处理表格、日志字段、实验结果 |

---

## 1. 相同任务：筛选包含关键词的行

假设 `run.log` 内容如下：

```text
INFO  start simulation
ERROR failed to open mesh
INFO  retry completed
```

两者都可以筛选包含 `ERROR` 的行：

```bash
grep 'ERROR' run.log
```

```bash
awk '/ERROR/ { print $0 }' run.log
```

输出都是：

```text
ERROR failed to open mesh
```

> [!success]- 这种情况优先选择 grep
> 目标只是判断整行是否匹配，没有字段处理或计算，`grep 'ERROR' run.log` 更短，也更直接地表达意图。

---

## 2. AWK 更合适：匹配后还要取字段

假设日志是：

```text
INFO runtime 12.35
ERROR runtime 0
INFO runtime 10.20
```

只输出 `INFO` 行中的运行时间：

```bash
awk '$1 == "INFO" { print $3 }' run.log
```

输出：

```text
12.35
10.20
```

`grep` 可以找出 `INFO` 行，却不擅长表达“再取第 3 个字段”。虽然可以继续接 `cut`，但这时一个 `awk` 通常更清晰：

```bash
# 可以工作，但需要两个进程，并且字段规则分散在两个命令里
grep '^INFO ' run.log | awk '{ print $3 }'

# 同一个 AWK 程序完成筛选与取列
awk '$1 == "INFO" { print $3 }' run.log
```

## 3. 语法对照

| 需求 | `grep` | `awk` |
| --- | --- | --- |
| 包含 `Time` 的行 | `grep 'Time' log.txt` | `awk '/Time/' log.txt` |
| 不包含 `DEBUG` 的行 | `grep -v 'DEBUG' log.txt` | `awk '!/DEBUG/' log.txt` |
| 忽略大小写 | `grep -i 'error' log.txt` | `awk 'tolower($0) ~ /error/' log.txt` |
| 使用扩展正则 | `grep -E 'error\|warning' log.txt` | `awk '/error\|warning/' log.txt` |
| 输出匹配行号 | `grep -n 'Time' log.txt` | `awk '/Time/ { print NR ":" $0 }' log.txt` |
| 统计匹配行数 | `grep -c 'completed' log.txt` | `awk '/completed/ { n++ } END { print n + 0 }' log.txt` |
| 只检查第 1 个字段 | 不直接支持字段语义 | `awk '$1 == "completed"' file.txt` |
| 第 4 个字段大于 10 | 不适合数值字段比较 | `awk '$4 > 10' file.txt` |
| 输出第 1、4 个字段 | 不负责字段重排 | `awk '{ print $1, $4 }' file.txt` |
| 求第 4 个字段平均值 | 不适合 | `awk '{ s += $4; n++ } END { if (n) print s/n }' file.txt` |

> [!warning]- `grep` 的正则模式取决于选项
> 常见 `grep` 默认使用基本正则表达式；`grep -E` 使用扩展正则表达式。AWK 的 `/.../` 使用扩展正则风格。移植正则时应检查 `+`、`?`、`()` 和 `|` 等符号的含义与转义方式。

## 4. 常用选项与变量

### grep 常用选项

| 选项 | 作用 |
| --- | --- |
| `-i` | 忽略大小写 |
| `-v` | 反向选择，即输出不匹配的行 |
| `-n` | 显示行号 |
| `-c` | 输出匹配行数 |
| `-E` | 使用扩展正则表达式 |
| `-F` | 把模式当作固定字符串，不解释正则字符 |
| `-r` | 递归搜索目录 |
| `-A N`、`-B N`、`-C N` | 显示匹配行之后、之前或两侧的上下文 |

### AWK 常用写法

| 写法 | 作用 |
| --- | --- |
| `-F,` | 用逗号拆分输入字段 |
| `$0` | 当前整行 |
| `$1`、`$2` | 当前行的指定字段 |
| `NR` | 当前累计行号 |
| `NF`、`$NF` | 字段数、最后一个字段 |
| `~`、`!~` | 匹配、不匹配正则 |
| `BEGIN`、`END` | 输入前初始化、输入后汇总 |
| `print`、`printf` | 普通输出、格式化输出 |

## 5. CSV 与 HPC 结果中的选择

假设 `results.csv` 的结构是：

```csv
scale,nodes,runtime,status
small,1,120.5,completed
medium,4,35.2,completed
large,8,0,failed
```

### 只找包含 completed 的原始行

```bash
grep 'completed' results.csv
```

### 严格判断 status 字段并输出 scale 与 runtime

```bash
awk -F, 'NR > 1 && $4 == "completed" { print $1, $3 }' results.csv
```

### 计算完成任务的平均 runtime

```bash
awk -F, '
  NR > 1 && $4 == "completed" { sum += $3; count++ }
  END {
    if (count > 0) print sum / count
    else print "no completed records"
  }
' results.csv
```

这里不能简单用 `grep 'completed'` 代替字段判断：关键词可能出现在其他列中，而 `$4 == "completed"` 明确限定了 status 字段。

> [!warning]- 简单逗号拆分的边界
> `awk -F,` 不能正确解析字段内部含逗号、引号或换行的完整 CSV。此限制与 grep 无关；复杂 CSV 应交给真正的 CSV 解析器。

## 6. 什么时候适合组合使用

处理大量混合日志时，可以先用 `grep` 过滤容易识别的记录，再让 `awk` 处理字段：

```bash
grep '^RESULT ' huge.log | awk '$4 == "completed" { sum += $3; n++ }
                                  END { if (n) print sum / n }'
```

组合的价值在于职责清楚，或者 `grep` 的递归搜索、上下文等能力正好有用。但如果一个 `awk` 就能清楚完成任务，不必为了使用管道而拆成两个命令：

```bash
awk '$1 == "RESULT" && $4 == "completed" { sum += $3; n++ }
     END { if (n) print sum / n }' huge.log
```

> [!tip]- 判断标准
> 管道是否更好，不取决于命令数量，而取决于每一步是否让意图更清楚、是否需要该工具独有的能力。

## 常见易错点

> [!warning]- 易错点
> - `grep 'small'` 是整行搜索，不等价于 AWK 的 `$1 == "small"`。
> - `grep -F` 表示“固定字符串匹配”，而 `awk -F,` 表示“输入字段分隔符为逗号”，两者含义完全不同。
> - `grep -c` 统计匹配行数，不是匹配内容出现的总次数。
> - AWK 的裸正则 `/error/` 匹配整行；字段匹配应写成 `$2 ~ /error/`。
> - 只需搜索目录中的关键词时，`grep -r` 比自己用 AWK 遍历文件更合适。
> - 需要数值比较时不要用文本匹配代替，例如字符串包含 `10` 不等于数值大于 `10`。

---

## 一句话总结

`grep` 负责“找到哪些行”，`awk` 负责“这些行的哪些字段满足条件，以及如何计算和输出”。
