```python
# 场景 C：查表映射（罗马数字 → 阿拉伯数字）
ROMAN = {"I": "1", "II": "2", "III": "3"}
print(re.sub(r"\b(I{1,3})\b", lambda m: ROMAN[m.group(1)], "Chapter II and III"))
```

## 先拆成 4 个零件

```python
ROMAN = {"I": "1", "II": "2", "III": "3"}          # 零件①:查表字典
re.sub(
    r"\b(I{1,3})\b",                                # 零件②:匹配模式 pattern
    lambda m: ROMAN[m.group(1)],                    # 零件③:替换函数 repl
    "Chapter II and III"                            # 零件④:原文
)
```

关键认知:**`re.sub` 会自己去原文里找匹配,每找到一个,就把那个匹配「喂」给零件③这个函数,函数返回什么,就替换成什么。** 你不用手动调用 lambda,是 `re.sub` 在背后替你调。

---

## 零件②:`r"\b(I{1,3})\b"` 到底在匹配什么

从里到外拆:

|片段|含义|说明|
|---|---|---|
|`I{1,3}`|1 到 3 个连续的大写 `I`|`{1,3}` 是量词,匹配 `I`、`II`、`III`|
|`(...)`|捕获组 (capture group)|把匹配到的 `I` 们「装起来」,后面用 `m.group(1)` 取出|
|`\b`|单词边界 (word boundary)|**零宽**,不占字符,只是「卡位置」的断言|

`\b` 是这里最容易忽略、但**最关键**的东西。它匹配的是「单词字符 和 非单词字符之间的那条缝」。有了前后两个 `\b`,意思就是:**这串 `I` 必须是一个独立的词,左右不能粘着别的字母。**

---

## 零件③:`lambda m: ROMAN[m.group(1)]` 怎么工作

这是一个匿名函数,等价于:

```python
def f(m):                    # m 是 re 传进来的「匹配对象」match object
    matched_text = m.group(1)   # 取出第 1 个捕获组匹配到的文本,比如 "II"
    return ROMAN[matched_text]  # 拿它去字典查表 → "2"
```

- `m` 不是你传的,是 `re.sub` **每匹配到一次就自动创建并传进来**的对象。
- `m.group(1)` = 第 1 个括号 `(...)` 捕获到的文本(这里就是那串 `I`)。
- `ROMAN["II"]` 走字典查表,返回 `"2"`。
- 函数**必须返回字符串**,返回值就是替换结果。

---

## 完整走一遍:`"Chapter II and III"`

`re.sub` 从左到右扫描,frame-by-frame:

|步骤|扫描位置|发生了什么|lambda 收到的 `m.group(1)`|返回值|
|---|---|---|---|---|
|1|`Chapter`|`C/h/a/p/t/e/r` 里没有独立的大写 `I`,不匹配|—|—|
|2|`II`|前后都是空格 → 两个 `\b` 成立,`I{1,3}` 贪婪吃下 `II`|`"II"`|`ROMAN["II"]` → `"2"`|
|3|`and`|不匹配|—|—|
|4|`III`|前后边界成立,贪婪吃下 `III`|`"III"`|`ROMAN["III"]` → `"3"`|

拼接结果:`Chapter` + `2` + `and` + `3` = **`'Chapter 2 and 3'`**。

## 两个「为什么」——这才是你真正需要懂的

**Q1:为什么 `III` 没被拆成三个 `I` 分别替换成三个 `1`?**

因为 `{1,3}` 是**贪婪 (greedy)** 的,能多吃就多吃。到 `III` 时它一口气吃满 3 个,当成**一个**匹配 `"III"` → 查表得 `"3"`。它不会退回来一个一个匹配。

**Q2:那两个 `\b` 到底防了什么?去掉会怎样?**

这是重点。看对比——假设原文里有个单词 `BILL`(里面有个 `I`):

```python
# 没有 \b:
re.sub(r"(I{1,3})", lambda m: ROMAN[m.group(1)], "Chapter II and BILL")
# → 'Chapter 2 and B1LL'   ← BILL 里的 I 被当成罗马数字换成了 1!错!

# 有 \b:
re.sub(r"\b(I{1,3})\b", lambda m: ROMAN[m.group(1)], "Chapter II and BILL")
# → 'Chapter 2 and BILL'   ← BILL 的 I 左右粘着字母,没有单词边界,不匹配。对!
```

`BILL` 里的 `I` 夹在 `B` 和 `L` 中间,两边都是单词字符,**没有那条「缝」**,所以 `\b` 不成立,整个模式匹配失败,`I` 被安全地放过。`\b` 保证你只替换**独立成词**的罗马数字,不误伤别的单词里的字母。

> 补一个冷知识:这里 `m.group(1)` 换成 `m.group(0)` 结果一样。因为 `\b` 是零宽的、不占字符,所以「整个匹配」`group(0)` 和「括号里捕获的」`group(1)` 内容完全相同,都是那串 `I`。用 `group(1)` 只是习惯上更明确。

## regex101.com 能练这个吗?——能一半

这是个好问题,答案是**部分能**,你要知道边界在哪:

**✅ regex101 能帮你的部分(零件②):**

- 把 flavor 切到 **Python**(左边栏选),粘上 `\b(I{1,3})\b`,在测试区输入 `Chapter II and III BILL`。
- 它会**高亮**所有匹配,右侧 MATCH INFORMATION 面板会告诉你 `Group 1` 抓到了什么。你可以亲手删掉 `\b` 看 `BILL` 会不会被误匹配——把上面 Q2 的实验做一遍,非常直观。
- 它下面还有个 **SUBSTITUTION** 面板,能测简单替换,但那里只支持 `$1` / `\1` 这种「搬运」语法。

**❌ regex101 帮不了的部分(零件③):**

- `lambda m: ROMAN[m.group(1)]` 是 **Python 代码**,里面有字典查表和函数逻辑。regex101 的 substitution **不会执行 Python 函数**,它只懂正则替换语法,查不了你的 `ROMAN` 字典。

**建议的练习路径:**

1. 先在 **regex101(Python flavor)** 上把 pattern 和捕获组玩熟——`\b`、`{1,3}`、`(...)` 分别删掉试试,观察匹配怎么变。这一步专攻「匹配」。
2. 再到能跑 Python 的地方练「函数替换」这一档:[**Python Tutor**](https://pythontutor.com/)(能可视化 `m` 对象怎么被传进 lambda)、或任意在线 Python REPL / 你本地的 Jupyter。把 lambda 换成具名 `def f(m): ...` 加几个 `print(m.group(1))` 看每次匹配传进去的是什么。

一句话:**regex101 练「匹配和捕获」,Python 环境练「拿匹配去计算/查表」。** 两步合起来这行你就彻底通了。
