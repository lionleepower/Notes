# obsidian-algo-note

把算法题、代码、截图文字或原始笔记整理成适合长期复习、面试回顾的 Obsidian 笔记。
目标：一读能懂 / 二读能快速回忆 / 三读（面试前）能秒定位核心。

库的根目录：`E:\obsidian\algorithmDesign_ideas`
笔记主战场：`学习与算法\算法练习\经典算法\`

## 路由规则：内容写到哪里

判断标准只有一条：**内容围绕「某道题 / 某类题怎么解」→ Patterns；围绕「某个语言特性 / 数据结构本身怎么用」→ 基础概念。**

| 内容 | 目录 | 举例 |
| --- | --- | --- |
| 单题题解、专题模板、算法套路 | `经典算法\1.Patterns\` | `6.1 子集型回溯.md` |
| 用户手写的原始笔记 / 草稿 | `经典算法\1.Patterns\原始稿件\` | `6.0.1子集型回溯.md` |
| Python 语法、数据结构、语言特性 | `经典算法\0.基础概念\` | `Python_deque.md` |

- **原始稿件只读不改。** 整理版从原始稿生成，并通过 wiki 链接指回原始稿；永远不要编辑或移动 `原始稿件/` 里的文件。
- 整理 Patterns 笔记时遇到值得单独讲的语言知识点（比如 `path[:]` 为什么要拷贝），不要在题解里展开长篇——拆出去建一篇基础概念笔记，在题解里用 `[[Python_xxx]]` 引用。
- 新建基础概念笔记前，先看 `0.基础概念\` 里有没有已覆盖同一知识点的文件；有就更新它，不要建重复笔记。

## Callout 硬约束（最容易犯、优先级最高）

`> [!type]- 标题` 必须**独占一行**，正文**另起一行**以 `> ` 开头；标题行和正文之间留一个 `> ` 空行。

```markdown
> [!tip]- 核心思路
> 
> 正文从这一行开始，绝不能挤在标题行后面。
```

**为什么**：Obsidian 把 callout 标记行之后的引用行渲染为可折叠的正文；如果正文跟在 `> [!tip]-` 同一行，会被当成标题的一部分，折叠功能和渲染都会坏掉。这是本库最常出的格式错误，输出前务必逐个检查。

- `-` 表示默认折叠。除顶部的 `> [!info] 知识图谱` 导航（不折叠）之外，所有详细内容 callout 一律带 `-` 默认折叠。
- 标题行可以带说明文字，如 `> [!tip]- 核心思路：三者只差"根在哪一步处理"`。
- 类型固定为六种，不要发明新类型：

| 类型 | 用途 |
| --- | --- |
| `[!info]` 知识图谱 | 顶部导航：总览 · 前置 · 原始记录（不折叠） |
| `[!tip]-` 核心思路 | 为什么该算法适合本题；维护什么状态或不变量 |
| `[!example]-` 示例推演 | 最小但有代表性的例子，控制在 15 行以内 |
| `[!success]-` 代码实现 | 完整关键代码 + 主流程 / 关键变量 / 易错位置 |
| `[!warning]-` 易错点 | 说明错误**为什么**发生，不要只列关键词 |
| `[!summary]-` 复杂度 | 时间、空间及其来源 |

## 命名规范

- Patterns 文件名：`编号 + 空格 + 中文主题.md`，如 `6.0 回溯算法.md`、`6.1 子集型回溯.md`。
- 原始稿件编号在整理版编号后加 `.1`，如整理版 `6.0` 对应原始稿 `6.0.1`。
- 基础概念文件名：`Python_主题.md`，如 `Python_赋值与拷贝.md`。
- 正文 H1：单题用 `# 题号. 题名`（如 `# 78. 子集`）；专题用 `# 专题名称`；基础概念用 `# Python <主题>：<一句话说明>`。
- 编号体系：`X.0` 是专题总述，`X.1`、`X.2`… 是该专题下的具体题型。新建笔记前先看目录里已有的编号，保持连续，不要跳号或撞号。

## 固定结构

三种笔记各有固定模板，动笔前先读对应的参考文件：

- 单题模式和专题模式 → [references/pattern-note.md](references/pattern-note.md)
- 基础概念笔记 → [references/concept-note.md](references/concept-note.md)

所有笔记共享的骨架顺序：

1. **第一行标签**（与标题之间空一行）
2. `> [!info] 知识图谱` 顶部导航
3. `# 标题`
4. 正文：每节保留 1～3 句可见结论，细节全部放进折叠 callout
5. `## 一句话总结`——一句话点破本质
6. `## 知识图谱`——前置 / 同类 / 进阶 的 `[[wiki-links]]`
7. `## 模板归纳`——触发信号 → 条件反射，什么时候该想到这个算法

## 双语正文

- 中文为主，简洁、问题导向、面试导向，不堆概念。
- 关键算法术语首次出现时给出英文对照，如「前序 Preorder」「回溯 Backtracking」「剪枝 Pruning」。
- 代码、变量名和英文术语用反引号；代码注释用中文。
- 每个知识点优先回答「为什么这样做」，其次才是「这是什么」；先给结论，再解释原因。

## 复杂度用 LaTeX

- 行内公式 `$O(n)$`、`$O(2^n \cdot n)$`、`$O(\log n)$`；独立公式用 `$$...$$`。
- 禁止 `\( \)`、`\[ \]`、HTML。
- 时间和空间都要写**来源**：「$O(n)$ —— 每个节点恰好入栈一次」，不是只报一个数。
- 空间复杂度区分辅助空间和返回结果空间（有必要时）。

## 标签（kebab-case，固定集合）

放在文件第一行，算法标签选 1～3 个最关键的，不堆叠：

```text
#algorithm/two-pointers #algorithm/sliding-window #algorithm/binary-search
#algorithm/monotonic-stack #algorithm/bfs #algorithm/dfs #algorithm/recursion
#algorithm/backtracking #algorithm/dp #algorithm/greedy #algorithm/union-find
#algorithm/trie #algorithm/binary-tree #algorithm/linked-list #algorithm/hash
#algorithm/sorting #algorithm/prefix-sum #algorithm/bit #algorithm/graph #algorithm/math
```

```text
#difficulty/easy | #difficulty/medium | #difficulty/hard
#status/todo | #status/review | #status/done
```

- 单题必须带难度标签；不确定难度时省略并说明待确认，不要猜。
- 专题笔记包含不同难度题目时可省略难度标签。
- 不要发明集合之外的标签。

## Wiki 链接规则

- **只链接真实存在的 Markdown 文件。** 写链接前用 Glob 确认目标文件存在；不存在独立笔记的 LeetCode 题目写普通文本（如 `102. 二叉树的层序遍历`），不制造悬空节点。
- 原始稿链接带路径和别名：`[[原始稿件/6.0.1子集型回溯|6.0.1 子集型回溯]]`。
- 每篇 Patterns 笔记至少关联一个真实存在的前置、同类或进阶专题，并链接总览 `[[0.0 Patterns 算法知识图谱]]`；新专题建好后检查知识图谱是否需要补充对应条目。
- 跨专题链接可用显示别名：`[[5.4 层序遍历|BFS 层序问题]]`。

## 代码要求

- 用户提供代码时，优先保留并整理用户原有思路；代码有错先指出原因再给修正版，不要静默换成别的解法。
- 用户指定语言只输出该语言；提供了代码但没指定语言就沿用代码的语言；都没有默认 Python。
- 代码块必须带语言标识，包含必要导入和边界处理。
- 较长代码不逐行解释，只说明：主流程、关键变量、核心不变量、最易写错处。
